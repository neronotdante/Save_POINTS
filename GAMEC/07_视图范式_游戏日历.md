> **v3.21 变更（2026-09-11）**
> 1. **§4.2e 精简模式只屏蔽截图，不再连成就一起关掉**。原来它一个开关管两件事（成就图标簇 + 截图面板），而成就该不该显示本来就有 §4.2f 的「隐藏成就」单独管——打开精简等于顺手把成就也关了，轴下方只剩一排封面：用户要的是「少看点截图」，拿到的却是「连成就也一起没了」。两个开关现在各管一件事，正交。

> **v3.20 变更（2026-09-11）**
> 1. **§4.8 悬浮不再染底色**，改由 panel **落在指针那一格正上方**回答「我指的是哪一格」。那块 5% 灰矩形是「我指到了」的替身，而 panel 原来一律锚在整组中心——指第三格却在中间冒出来。两件事一起改：底色删掉，锚点从组中心改成**那一格的中心**（取格心而不是指针的精确像素：`mouseenter` 只在跨进边界那一刻触发一次，用鼠标坐标的话同一格从左进、从右进会差半格，panel 跟着左右跳）。
> 2. **§4.2e 相机图标只在精简模式下出**。非精简时每一张截图都已经在轴下方的面板里铺出来了（对得上轴的进当天的日面板，对不上的进按游戏收的面板，**和图标是同一批截图**），轴上再放一个图标是同一件事说两遍（05§0 规则 2），而且说得更差——图标只告诉你有几张，面板直接把图给你看。精简模式是**必须**的例外：那时面板全藏，图标是这批截图在轴上唯一的入口（§4.2g）。
> 3. **§4.2d 面板里屏幕上横着的一排最多 4 张**。⚠️ 这是全文少见的、真按「屏幕横向」定的约束，两个方向落在**不同的变量**上：横排的一排是 `cols`，竖排的一排是 `perColumn`。横排原来能顶到 6 列以上（见该节），竖排原来封在 5。

## 4. 横向时间轴（V0.1 唯一视图）

> 现状：V0.1 的主视图，**传统 HTML 实现**（原生 HTML/CSS/JS 单页），不套桌面客户端与面板骨架。上方是「何时发生了什么」的时点，下方是「当时看到什么」的截图——一条线把游戏人生摊开。

### 4.1 需求来源

原 P-1 用户故事（v0.5 移除、v1.0 恢复为主视图）：一条**可缩放的横向时间线**，从「最近一个月」拉到「我的十年」，把**首次启动 / 成就解锁的时刻**与**当时的游戏截图**摆在同一条线上。

| **大图地址的取法**（v3.2 补） | **不能按字段名信任 `ScreenshotOut.url`**：走官方 `GetUserFiles` 时它是图片（`file_url`），走社区页 HTML 兜底解析时曾被塞成 `…/sharedfiles/filedetails/?id=…` 这个**网页地址**。取图要按长相判断（`lib/media.js`），页面地址由 `shot_id` 现拼 | 实测库里 332 张有 150 张是网页地址、182 张为 NULL，没有一张 `url` 是图片。把网页当 `background-image` 加载浏览器**不报错**，只画一片空白——所以灯箱必须用 `new Image()` 预载并显式给出「正在加载原图… / 原图加载失败」两态，CSS 背景图的静默失败和「还在路上」长得一模一样。后端侧同时修掉了写入（[[03_Steam信息获取文档\|03]] §4.7） |
| **缩放层级** | **日 / 周 / 月** | 不做「全部」——全量跨度在一条轴上太拥挤（见 §4.6） |
| **头部时间读数** | 年份（26px 弱化）+ `.` + 当前月份（44px 强调），等宽数字 | 三档统一显示「年 . 月」，**档位由切换器表达，不由读数表达**。走 `clock/*`（05 §4），不再用 `display/month`——比例字体在逐帧变化的读数上会横向抽动 |
| **命中区层级** | 日 / 周档：只有组级；**月档：组级 + ICON 级**（嵌套） | 月档一个像素跨好几天，组级面板读不出单个事件的确切日期，见 §4.8a |

### 4.2a 全景导航条（v3.1 新增）

主体区顶部一条横贯全宽的活动概览（`left/right` = 安全边 40、`top` 18、高 **56**、圆角 12），**不随轨道平移**——它表达的是整条 domain，不是当前视窗。

解决的是一个真实的导航问题：domain 是十年，一屏只看得见几周到几个月。头部读数只说「现在在哪」，不说「一共有哪些地方可去」；想跳到某一年只能一路滚或反复换档试探。

| 元素 | 定 | 说明 |
|---|---|---|
| **密度柱** | domain 等分 **220** 桶，柱长 = `sqrt((事件数 + 截图数) / 峰值)` | 固定桶数 → 位置全用百分比，条的尺寸变化不必重建。开方是必要的：一个 40 张截图的日子会把其余十年压成一条线 |
| **柱分两段**（v3.2） | 底段 = 事件（`--ov-ev` 深）、顶段 = 截图（`--ov-shot` 浅），一层渐变实现、不多建节点 | 两根一样长的柱子，一根可能是那周解了 20 个成就、另一根是截了 20 张图。混成一个色块就把这个区别抹掉了——这条概览要回答的是「那阵子我在干什么」，不只是「哪里热闹」 |
| **柱顶蓝帽**（v3.2 由整柱变色改） | 该桶内有**首次游玩**时，柱的外端加一道 2px `--accent` | 十年里最值得跳过去的就是这些点。原来整柱染蓝会和「分两段」抢同一条视觉通道 |
| **年分隔 + 年号** | 每年 1 月 1 日一条 1px 线 + `mono` 9px 年号（`--text-muted`） | 十年跨度里唯一稳定的地标 |
| **季度细线**（v3.2） | 仅当 domain **短于三年**时才出，色 5% | 十年跨度下季度线会密得看不清，那时它只是噪声 |
| ~~**图例**（v3.2）~~ **已删（v3.19）** | ~~三个 6px 色块 + `mono` 9px：事件 / 截图 / 首玩~~ | 它和上一行的**年号钉在同一条边上**：横排下图例在右上沿、年号也在上沿，domain 右端那个年号必然被压住；竖排下图例在左下角，正好盖住最后一段柱子。而「哪段是什么」悬停读数已经逐项报了（「年.月 · 事件 N · 截图 M · 有首玩」）——删掉不丢信息，只是把「先看图例才懂」换成「指哪读哪」。**加图例是为了让分段说得清，但它压住的恰恰是这条概览上唯一的绝对地标** |
| **视窗框** | 当前屏在整条轴上的位置与占比 | `--accent` .10 填充 + 1.5px 描边 |
| **行为** | 点一下 → 该处居中；按住拖 → 连续平移；悬停 → 一条游标线 + 浮出「年.月 · 事件 N · 截图 M · 有首玩」 | 悬停读数是必需的：没有它这条概览只是一片好看的柱子，看得出疏密、读不出具体是哪年哪月 |
| **显隐开关**（v3.2） | 头部一颗图标钮，`aria-pressed` 表态，偏好存 localStorage | 它是导航增强不是内容；不想要的时候应该能收掉，而不是只能忍着 |
| **位置口径** | 一律 `p = scale(t) / 轨道总长`，**不另起一套时间→位置映射** | 坐标层仍是全页唯一位置真源（05 §1.2） |
| **方向** | 跟随主视图：横排时贴主体区上沿横放，竖排时贴左沿竖放（§4.10） | |
| **自动收起** | 主体区垂轴 < **340** 或沿轴 < **420** | 窄到这份上那 56px 该还给标记与截图 |
| **层级** | z-index 12，低于标记（20）、命中层（45）、panel（60） | 视口窄到最高一档引线顶进这一带时，赢的必须是标记 |

### 4.2c 轴上的成就图标（v3.3 新增）

解锁成就的时点，在标记侧的**媒体带**里摆出当天解锁的成就图标——与开局封面并排，因为它们回答的是同一个问题：**这一天留下了什么**。

| 项 | 定 | 说明 |
|---|---|---|
| **图标** | **32 × 32**、圆角 6，与 §4.8 成就行里的图标同规格 | 轴上和面板里是同一件东西，不另立一套尺寸 |
| **排布**（v3.6 由「一行」改为「一簇」，**v3.7 改用定形表**） | 1~9 各手工定一个形：`1 / 2 / 3 / 2-2 / 3-2 / 3-3 / 2-3-2 / 3-2-3 / 3-3-3`（数字是每列几个，列沿时间轴排开）。列在**垂轴方向居中**——菱形与沙漏靠的就是这个，贴边对齐会塌成缺角的方块。厚度不够叠 3 个时退回机械切列，**形状让位于放得下** |
| **为什么值得逐个摆形**（v3.7） | 格子总数封顶 9，一共只有九种情况 | 逐个定形让**数量本身变得可读**——2-3-2 的菱形和 3-2-3 的沙漏一眼能分开，而机械切列时 7 和 8 长得几乎一样。⚠️ v3.6 曾试过「规整网格 + ±2px 确定性偏移」求有机感，**效果反而像没排好**：没有规律的不齐读作失误。要有机感就得用有规律的不齐（砖砌错缝），或者干脆逐个定形 |
| **跨轴分配**（v3.7 新增） | 成就格子可以分到轴的**两侧**。判据只有一条：**选让 `max(上侧, 下侧)` 最小的那个分法**；平手时优先对半分，再平手把多的放下侧 | 一条规则同时解决三件事：轴下方已有截图面板时，往下挪只会更长 → 自然全留在上面；轴下方是空的时（真实库九成时点如此）→ 自然匀一半下去；而 `max(上,下)` 正是这个时点的沿轴占位，所以**最平衡的分法同时也是最省地方的分法**——不是拿密度换观感，两者是同一件事。格子数封顶 9，穷举 10 种分法即可 |
| ~~（v3.6 原排布）~~ | 先沿垂轴叠满 3 个，再沿时间轴增开一列；每格带 ±2px 的散落 | 轴上方的**厚度是富余的、沿轴长度是稀缺的**——把成就从长的那一维挪到厚的那一维就是在给轴增密。排一行时 3 个占沿轴 108；堆成簇后 9 个也是 108，而 **1~3 个只占 32**。实测真实库 1172 个有成就的日子中位数是 2、69% 在 3 个以内，所以绝大多数时点的占位直接掉到 32 |
| **数量** | 一个时点最多 **9** 个（含 `+N` 那一格），超出折成 `+N` | v3.6 由 3 提到 9。`+N` **占一格**、不额外加长——它和图标一样大，挤在簇尾正合适 |
| **实测收益** | 排布改造 82 → 48px/时点；再叠上跨轴分配 → **37px/时点（累计 −55%）**。露出的成就数 **+43%**（2443 → 3503）。**轴下方的占用率 8% → 100%** | 按真实库 1172 天的成就数分布算出来的。更密、信息更多、两侧都不空——三件事同一个方向 |
| **上下两簇共用一串序号** | 明细懒加载按同一串序号回填，收集器建在时点上、两簇共用 | 分成两簇之后不能各填各的，否则同一天的成就会被回填成两份 |
| **悬停** | 浮出「成就名 / 解锁时刻 · 全球解锁率」 | 时刻取 `AchievementDetail.unlocktime`，精确到分。**只有明细到位的图标才给悬停反馈**（`.ready`）——占位色块上没有信息，不该骗用户去指它 |
| **取数** | 走 §4.5 的成就明细懒加载路由，**与 §4.8 面板共用同一份缓存** | 同一个 `(appid, day)` 两处各拉一次，等于把懒加载的意义抵消一半 |
| **懒加载判据** | 只拉 `g.p` 落在 `[offset, offset + 视窗]` 内那几组 | 一开始用的是 `IntersectionObserver`，**换掉了**：它和 rAF 一样挂在渲染生命周期上，页签在后台时一次都不派发——「后台打开、切回前台」会先看到一屏没有图标的占位色块。而要判的本来就只是「在不在视窗区间里」，坐标层已经把这个数算好了，用不着让浏览器再算一遍交叉。纯整数比较、不碰 DOM，挂在所有位移的唯一出口上 |
| **媒体带对齐** | `align-items: flex-end`，一律贴住**靠轴那一边** | 竖版封面 114、横版封面 64、成就图标 32 三种尺寸混排，靠这一条得到共同基线 |

### 4.2d 游戏截图面板（v3.4 新增）

**截图分两类，判据是「同一款游戏同一天有没有事件」**（购买 / 首玩 / 成就 / 发售）：

> **v3.5：轴下方一律是面板。** 对得上轴的那批也包同一套外壳，标题同样写游戏名（一天涉及多款就用 `·` 连起来）——**日期由轴的位置表达，写进标题是同一个信息出现两次**（05§0 规则 2）。于是轴下方只剩「面板」一种东西，两类只是标题不同。

| 类 | 去处 |
|---|---|
| **对得上轴** | 按天成一个面板，挂在那个时点下 |
| **对不上、且该游戏 ≥ 5 张** | 收成一个**游戏截图面板**，锚在这些截图的**中位日期**上 |
| **对不上、该游戏 < 5 张** | 仍按各自日期挂回轴上 |

> **真实库实测**（332 张截图 / 35 款游戏）：对得上轴 **166 张（50%）**，对不上 **166 张**。阈值取 5 时 **14 款游戏成面板、收走 114 张**（对不上的 69%），其余 52 张仍按日期上轴。阈值再高（10 → 4 款 53 张、15 → 1 款 18 张）收得太少，面板这个机制就形同虚设。

**为什么要有这一层**：把那 166 张全按日期铺到轴上，等于凭空多出上百个「只有截图」的时点，轴被撑得又长又碎；而它们本来就说不出「那天发生了什么」——它们只说得出「我玩这款游戏时截了这些」。按游戏归堆才是它们真正的组织维度。

| 项 | 定 | 说明 |
|---|---|---|
| **阈值** | **5 张** | 少于这个数不值得单开面板——一个带标题栏的容器比它装的三张缩略图还占地方，那时按日期挂回轴上更划算 |
| **锚点** | 这些截图的**中位日期** | 它们没有对应事件，但仍有时间；锚在中间最能代表「那阵子」。**不画跨度条**——本范式不引入区间型数据（§0） |
| **标题** | 游戏名 + 张数，**永远在面板上方** | 横排时标题吃掉一截轴下厚度，面板内的每列张数因此比普通截图列少；竖排时它吃的是沿轴长度，不影响列容量 |
| **张数上限** | 面板内最多摆 **12** 张 | 点标题右侧的张数按钮进灯箱看全部。不另挂 `+N` 芯片——它和张数说的是同一件事，却要再多占一截沿轴长度。**张数按钮只在装不下时才出**（v3.5）：全都摆在眼前时它没有信息，只会把本就窄的标题再挤掉一截 |
| **标题字体**（v3.5） | 走 05§4 的 `body`（Noto Sans SC 13.5 / 1.5 / 500）；张数走 `mono/stamp`（JetBrains Mono 11 / 400） | 05§4 里 `body` 那一行写的就是「列表主行、**游戏名**」，这里显示的正是游戏名。原来的 12 / 500 与 10 / .04em 都不在字阶里——放在一屏全是 token 值的界面上，会显出一种说不上来的不搭 |
| **沿轴尺寸** | **由 `shotPanelMain()` 算好后写死在元素上**，标题超出即省略号 | ⚠️ 标题是游戏名、长度不可控。让它撑开容器就会和喂给坐标层的占位对不上（05 §1.2），相邻时点随之压到一起 |
| **仍然是时点** | 面板组照常有引线、命中区与悬浮 panel | 它锚在一个日期上，只是内容从「那天的截图」换成「这款游戏这些说不出对应事件的截图」 |

### 4.2e 精简模式（v3.9 新增）

头部一颗开关（`aria-pressed` 表态，偏好存 localStorage，**默认关**——第一次来的人应该先看到全部内容，再自己决定收不收）。

| 屏蔽 | 保留 |
|---|---|
| **截图**：面板（§4.2d）与缩略图，全部不画 | **成就图标簇**（§4.2c，v3.21 起不再屏蔽）、**事件图标 + `×N` + 色点**（含截图的相机图标，§4.2g）、**开局封面**（§4.2）、引线、刻度、导航条 |

⚠️ **v3.21 把成就从这个开关里拿出来了**。原来它一个开关管两件事，而「成就该不该显示」本来就有
§4.2f 单独管——打开精简等于顺手把成就也关了，轴下方只剩一排封面。一个开关只管一件事，
两个开关才组合得出四种状态；绑在一起时那四种里有两种是取不到的。

两条要点：

- **不是「藏起来」，是「不参与布局」**。屏蔽掉的内容同时不再占沿轴长度，所以切过去时整条轴会明显收紧——实测 MOCK 下轨道 25 435 → 10 983（**−57%**），时点数一个不少（140 → 140）。这正是这个模式的用处：想快速扫一条十年的线时，不必被缩略图撑开。
- **截图必须先有自己的图标**，否则精简之后「只有截图的那些日子」在轴上会一点痕迹都不剩。相机图标与其它事件图标同构（14px 描边图标 + 可选 `×N` + 6px 色点），色取游戏主题色，参与 05§3.4 的同日配色去重。⚠️ 截图面板锚点那一天的 bucket **任何模式下都要建**，只是精简模式下不往里塞面板——不然那天连图标都没有。

### 4.2f 隐藏成就（v3.10 新增）

头部第二颗开关。**与 §4.2e 的精简模式是两件事，别混**：

| 开关 | 屏蔽什么 | 保留什么 |
|---|---|---|
| **精简模式**（§4.2e） | 图像内容：成就图标簇 + 截图面板 | 全部事件图标（含成就的钥匙）、开局封面 |
| **隐藏成就**（本节） | 成就**这一整类事件**：钥匙图标、`×N`、图标簇一起不出现 | 购买 / 首玩 / 发售 / 截图这几条主线 |

口径与 §4.9 的「隐藏从未启动」一致：**不进轴，不是灰化**——留一个灰掉的图标既占地方又什么都没说。

⚠️ **两处连带影响，都是有意的**：

- **截图会重新归堆**。成就被隐藏后，那天不再是轴上的时点，挂在它下面的截图就「对不上轴」了，于是按 §4.2d 的规则按游戏收成面板。实测 MOCK：面板 84 → 35，时点 140 → 69。
- **回归封面只剩「那天还在轴上」的那些**。判定本身**不受开关影响**（见下），但回归日如果是一个纯成就日，那个时点已经不存在，封面自然无处可挂。实测 7 → 4。

⚠️ **「封盘后重启」的判定必须从未经显示开关过滤的事件里算**（v3.10 修）：它是数据属性——这款游戏的可见活动断了 45 天又出现——不该因为「我把成就图标关掉了」而改变。早先它是从已过滤的 `unitsAll` 推的，一开这个开关回归封面会**全部消失**（7 → 0）。

实测四种组合（MOCK，140 个时点；**v3.21 重测**，旧表是 v3.12 的数字，中间隔着封面、面板外壳、
标题撑宽等多轮改动，早已对不上）：

| 组合 | 时点 | 事件图标 | 相机 | 成就簇 | 面板 | 封面 | 轨道 |
|---|---|---|---|---|---|---|---|
| 都关 | 140 | 138 | 0 | 345 | 84 | 31 | 25 435 |
| 只精简 | 140 | 220 | 82 | **345** | 0 | 31 | 10 983 |
| 只隐藏成就 | 69 | 48 | 0 | 0 | 35 | 28 | 14 316 |
| **两个都开** | 69 | 83 | 35 | 0 | 0 | 28 | **5 372（−79%）** |

两列值得对读：
- **相机** 那列只在精简时非零——v3.20 起它只在精简模式下出（§4.2g）；「只精简」的事件图标
  220 = 都关时的 138 + 回来的 82 个相机，正好对上。
- **成就簇** 那列现在只跟「隐藏成就」走，不再跟着精简一起归零（v3.21）。

### 4.2g 截图图标可点开（v3.12 新增）

轴上的相机图标（§4.2e）**任何缩放下都可点**，点开就是那款游戏那一天的截图灯箱，光标为 `zoom-in`。

⚠️ **v3.20 起这个图标只在精简模式下存在**，所以这一节说的也只是精简模式下的事。非精简时截图由面板直接铺出来，图标连同它的命中格一起不画——那时截图的灯箱入口是面板里的缩略图本身。

理由是一条闭环：§4.2e 给截图加图标，是为了「只有截图的那些日子」在精简后仍留下痕迹；可留了痕迹却点不开，那批截图在精简模式下就被彻底锁死了——面板已经不在，图标是它唯一的入口。

实现上是把原本只在**粗粒度缩放**下才铺的逐 ICON 点击层（那时组级面板读不出单个事件是哪天，点开出日期读数）扩到「或者组里有截图 unit」：

- 粗粒度 + 非截图 → 老行为，点开日期读数；
- 截图 unit → 任何缩放下都铺，点开灯箱。

⚠️ **截图 unit 必须携带截图本身，不能只带计数**。早先它只记 `日期|appid → 张数`，图标画得出来但点开是空的。计数与内容用同一份数据，才不会出现「显示 5 张、点开 0 张」这种只在某个模式下才暴露的偏差。

### 4.2h 封面跨轴交错（v3.12 新增）

**只在精简模式（§4.2e）下开**：那时轴的对侧本来就空着（截图面板与成就簇都被屏蔽了），而标记侧
挤着一排封面。开启后相邻的开局封面**一个在轴上、一个在轴下**，**图标与引线一并跟着换边**——
换的是「一整组」，不是把封面单独挑出去放到另一边。

⚠️ **不是同侧分两层**。同侧两层只是把标记侧撑得更厚，对侧照样空着；跨轴交错是把闲置的那半边
真正用起来，同时让一上一下的两组沿轴**根本不会相撞**。

**收益在坐标层，不只是观感**：换边之后轴的上下是两条互不相干的通道，间距约束要**分侧**算
（`mainOnSide` / `pairGap`）——一上一下的相邻两组只受各自那一侧的长度约束。实测 MOCK 横排
1280×800，精简 + 隐藏成就：轨道 **5 431 → 5 217（−214px / −3.9%）**，28 张封面 14 上 14 下。

四条约束，缺一不可：

- **只有封面组参与轮转**，纯图标的日子一律留在标记侧。让整条图标脊线跟着抖是噪声——交错要跟着的是「封面」这件事，不是每一个时点。
- **按时间顺序轮转，不按位置**。这样缩放 / 换向之后同一张封面仍落在同一侧，不会一动就跳。
- **隔一个的同侧组要单独校验**。A(上) B(下) C(上) 的两段都被放松过，A 与 C 仍会在上侧撞。间距只能表达在相邻段上，所以把这条约束**均摊到中间那两段**（`minWidthsBetween` 的第二趟）。少了这一趟，是否重叠只取决于数据碰巧。
- **对侧放不下就整个关掉**。要求封面还是原尺寸（`fpCoverScale === 1`），且对侧厚度 ≥ 引线 + 图标 + 8 + 封面（`flipNeedCross()`）。宁可不交错，也不能把封面顶出主体区。

换边在实现上只有两件事，**DOM 顺序一个字都不改**：反向 flex（`[媒体][图标][引线]` 自然倒成
`[引线][图标][媒体]`，引线仍贴着轴）+ 反向 transform（不再往回退一整个身位）。其余全是把
「朝轴的那一面」从下改成上——内边距、外边距、对齐、引线渐隐的方向。

跟着换边的还有三样，漏一样就会露馅：**命中区**（关于轴线镜像）、**读数条**（粗粒度缩放下才出现）、
**悬浮 panel**（§4.8 的落点改用 `panelCrossPosBelow`，否则会压在标记侧的内容上）。

⚠️ `settleResize` 的「占位没变就不重排」判据必须把交错开关算进去。漏了它，拉窗口把对侧空间撑够 /
挤没时不会重建，表现是「交错时有时无」。

### 4.2i 封面对齐到一条线（v3.13 新增）

**一排封面必须落在同一条距轴线上**，两侧、两个方向都一样。封面是同一类东西，没有理由因为
「它那天的图标被抬高了」就换个高度。

挡在前面的是两件与封面无关的事：

- **引线是分档的**。`assignStems` 为了错开命中区会把一部分组抬到 104 / 144 / 184，封面若跟着
  各自的引线走就会高低不齐（实测横排 104 / 144 两档）。
- **`×N` 的实际字宽**。竖排下 `×N` 往垂轴方向加厚，模型里的 `XN_EXTRA` 只是个估值，真实字宽
  与它差几个像素，一排封面就歪几个像素（实测 118 / 120 / 123）。

所以封面带**脱离标记块的流**，直接钉在距轴 `coverPin + 8` 处（CSS `.media-band.pinned`，
靠 `.event-group` 那条贴轴的边做 `bottom` / `right` 的基准）。`coverPin` 取**有封面的那些组里
最外的标记外沿**——不能比这个小，否则封面会压到自己那组的图标上；再夹一次可用厚度（交错时
取窄的那一侧），夹不下就那一组保持原位，宁可一个不齐也不能把封面顶出主体区。

实测 1280×800：横排精简 144（净空 8）、横排完整 104（净空 8）、竖排 129（净空 14），28 张全部一个值。

⚠️ 顺带修掉了 `XN_EXTRA` 16 → 25。它按两位数估的，模型比实际薄 3px，表现是竖排下封面与图标
之间的净空从 8 掉到 5。取值按 9px 等宽字实测：「×10」16.2px、「×5」10.8px，加 3px 间隙，
留到「×999」这一档。

### 4.2k 封面跟内容走（v3.18 新增）

**这个时点摆出来的成就 / 截图是哪款游戏，封面就该是哪款。** 原来封面只由「首玩 / 回归」决定，
和它旁边摆的是什么无关：实测真实库 305 个有封面的时点里，**49 个的封面和当天的成就不是同一款、
6 个和截图不是同一款**。一张《A》的封面挨着一簇《B》的成就图标，读起来就是「这天我在玩 A」——
那是假的，而且没有任何地方能纠正它。

| 项 | 定 | 说明 |
|---|---|---|
| **代表游戏** | **首个成就的游戏 > 截图的游戏** | 成就簇和封面并排在同一条媒体带里（§4.2c），挨得最近的那个必须先对上；截图在轴的另一侧。这条优先级**不必再判显示开关**：隐藏成就时成就事件根本不进 `unitsAll`，自然落到截图；精简模式只是不画簇、成就仍在，于是仍按成就算——也就是「两样都不显示时同上」 |
| **「首个」按时刻取** | 用 `TimelineEvent.minutes`（当日第几分钟），成就簇取该日**最早**一次解锁 | 后端 `raw.sort` 的键是 `(date, type)`，同一天里成就与成就之间只剩数据库扫描顺序。拿它当「首次成就」是**拿一个任意值当依据**——所以出参补了 `minutes`（[[05_后端接口文档\|05]] §3），前端才谈得上「第一件事」 |
| **只改「那张图该是谁」，不给没封面的时点补图** | 时点有封面才生效 | 1203 个时点里 1173 个有成就，补下去等于几乎每个时点都长出一张封面，轴要长 3~4 倍，**精简模式也不再精简**。封面仍然是「值得留一张图」的日子才有 |
| **张数不变** | 对不上就**顶掉**一张，不是加一张 | 封面的沿轴长度参与时点间距（05§1.2），多一张就改一次轴的疏密。实测轨道长度前后一致 |
| **位置** | 代表封面排在**最靠成就簇那一端**（媒体带里是最后一张） | 「对不对得上」看的是挨着的那一张 |
| **第三种 kind：`play`** | 「这一天在玩」。视觉上和 `first` 一样（同一圈主题色环），只有 `title` 不同 | 那圈环表达的是**这款游戏的颜色**，不是 kind（§4.2 v3.5）；`return` 才有额外的墨线。但说法必须分开——不能让一张封面替「首次游玩」作证，而那天根本没首玩 |
| **只顶 `first`，绝不顶 `return`** | 一张 `first` 都没有（全是回归封面）时保持原样 | **不对称的理由**：首玩那天轴上还有一枚 play 图标顶着，封面没了这件事仍在；而「封盘后重启」在这条轴上**只由封面那圈墨线表达**，没有对应的事件图标——顶掉它等于把这个信息从页面上整个抹掉。实测库里 120 张回归封面，不加这条保护会掉 11 张 |

实测（LIVE 1203 个时点）：有封面的时点 305 → 305、封面总数 331 → 331、轨道长度不变；
挨着成就那张对上代表游戏的 294 个，10 个是「只有回归封面」而按上面最后一条留着，其余 0。
331 张的构成：首次游玩 172 · 封盘后重启 120 · 这一天在玩 39。

### 4.2j 截图面板的外壳：主题色角标（v3.15 定，v3.16 收敛为唯一）

原来的白玻璃卡片在这里不成立：轴下方本来就是一片浅灰，再叠一层半透明白，**边框看得见、面却看不见**，
「有个框」比「里面是什么」还显眼。

外壳定为**只留对角两个角**：左上 / 右下各一个 22×22、1.5px 的角，取该游戏的**主题色**
（与封面边框同一套语言），底透明、无描边、无投影。「成组」这件事不需要一整圈线，两个角就够；
轴下方本来就浅，少一层面，缩略图自己才站得出来。

> v3.15 曾同时保留「接触印相」作为第二种皮肤、按面板身份哈希随机分配。v3.16 按要求收敛为角标一种——
> 同屏两种外壳读起来像是两类东西，而它们其实是同一类。随机分配那套连同 `PANEL_SKIN` 一并删除。

#### 4.2j-1 三个「框和内容对不上」的坑

都是**模型比实际薄 / 厚**，而溢出与虚胖都是静默的，只是看着挤或看着空：

- **漏算标题与网格之间那 6px**（CSS 里 `.shot-panel` 的 `gap`）。`panelChromeCross` 只算了标题 + 内边距，
  列容量因此可能多算一行，最后一行顶出面板。
- **竖排下 `panelChromeCross` 直接返回 0**。标题在竖排确实吃的是沿轴，但**面板自己的内边距两侧照样要减**。
- **标题把面板顶宽了**。竖排下面板宽度是内容撑出来的，而标题栏中间那条 `minmax(0, auto)` 轨道在
  「按内容定宽」的上下文里会朝 max-content 长——实测把面板顶宽 26px。解法是 `width: 0; min-width: 100%`：
  对固有宽度贡献 0，再撑满最终宽度。

#### 4.2j-2 标题要写得全（v3.16 新增）

**横排下标题和缩略图排在同一个方向上**：一张图的面板只有 96 宽，而一个游戏名动辄 160~330——
标题只能省略号，看到的是「红色沙漠：增…」。规则改为：

1. **先按标题定下面板的最小沿轴长度**（`panelTitleMain`）；
2. **再把图横着摊开去占满这个宽度**（`panelGrid` 现算 `cols`，行数随之变少）——先横后竖，而不是缩在一列里；
3. 摊不满剩下的留白**居中**（`.sp-body { justify-content: center }`）。靠边站会让那片空白读作「少了一张图」。

竖排下标题横在**垂轴**上，与沿轴长度无关，走另一条路：`panelCrossMin` 给面板一个 `min-width`，
夹进主体区剩下的厚度里。垂轴不进坐标层的间距约束，所以这条不影响轴上的疏密。

| 取值 | 定 |
|---|---|
| `PANEL_TITLE_MAX` | **330**。实测单游戏标题最宽 326（`The Witcher 2: …Enhanced Edition`）、中位 157，330 覆盖全部 |
| `SHOTS_PER_ROW_MAX`（v3.20 新增） | **4**，屏幕上横着一排最多几张。两个方向落在不同变量上：**横排**夹 `cols`（列横着排、列内竖着叠），**竖排**夹 `perColumn`（一个 `.shot-column` 内部横着排；竖排的 `cols` 是竖直方向的行数，限制它没有意义）。<br>横排原来没有上限，列数有两条路能顶上去：一条是标题撑宽后横着能多摆几列（`fit`，实测封顶在 4），另一条是 `minCols = ceil(shown / perColumn)`——每列叠几张由**轴下方的厚度**决定，窗口矮到一列只叠得下 2 张时，12 张要排成 **6 列**。第二条才是真正会跑宽的那条。竖排那侧原来封在 `COL_MAX`（5）。<br>⚠️ **张数必须跟着列上限一起夹**（`shown = min(count, 12, 4 × perColumn)`）：只夹 `cols` 的话，摊平算法会把 12 张硬塞进 4 列（每列 3 张），而每列能叠几张是垂轴空间定死的——`perColumn = 2` 时第 3 张直接顶出面板，**不报错、不裁切，只是看着挤**。`panelGrid` 因此把 `shown` 一并交给渲染侧，两边按同一个数 slice 和算 `+N` |
| 量宽的办法 | canvas `measureText`，字体串与 CSS 逐字段对齐。**必须在渲染前量**——这个宽度是坐标层算间距的输入（§1.2），等 DOM 出来再量，间距已经定死了 |

⚠️ **三栏网格的两条 8px `gap` 是恒定的**，两侧那两栏是空的照样占位。漏掉它们，面板会正好短 16px——
表现是「明明加宽了，标题还是省略号」。

实测（LIVE 107 块）：

| | 改前 | 改后 |
|---|---|---|
| 标题被省略 | 75 | **6**（全部是日面板） |
| 其中单游戏面板 | — | **0 / 94** |
| 轨道 | 87 838 | 94 130（**+7.2%**） |
| 溢出 · 框大于内容 | 0 · 0 | 0 · 0 |

被省略的 6 块都是**日面板**：它的标题是把当天所有游戏名串起来的一串（中位 298、最长 1528），
那不是一个名字而是一份清单，撑到 1528 宽毫无意义——撞上限，照常省略号。

### 4.2b 轴的两端：`START` 标与 `TODAY` 标（v3.3 新增，v3.17 同形）

轴的两头各立一道横跨轴线的短帽，旁边挂一枚牌子：开头是「`START` · YYYY-MM-DD」，末端是「`TODAY` · YYYY-MM-DD」。

- **口径**：这个日期是**轴上最早的一条记录**（通常是第一笔购买入库或第一次游玩），**不是 Steam 账号创建日**——后者要 `GetPlayerSummaries.timecreated`，后端目前不取；库里的 `users.created_at` 是「本应用首次同步该用户」的时间，不能拿来充数。它也会随「隐藏从未启动的游戏」开关变化，因为那开关本来就会改变轴上有哪些点（§4.9）。
- **轴线从这里开始画**（v3.8）：不再从 domain 最左端起。起点之前那段是留白（首个时点前 14 天），本来就没有刻度、没有斜纹带；再画一截轴线过去，「起点」就只能退化成挂在轴旁边的一枚标签。**线从这里起，起点才是结构上的起点。**
- **端帽**（v3.8）：横跨轴线的一道 2 × 20 短线，像尺子上的「0」。**不用圆点**——圆点在这条轴上是事件色点的语汇（`.dot`），拿来当起点会读成「这天有个事件」。
- **标签落在轴线的延长线上**（v3.8）：垂轴方向**居中于轴线**、沿轴方向排在端帽之前。两个方向同一条规则，竖排下不会再歪到一侧去（v3.7 之前它是往标记侧偏的，竖排下尤其别扭）。起点之前是留白，所以不需要玻璃胶囊把它从背景里拎出来——去掉底衬后它更像线的一部分。
- **落点按实测宽度夹取**（v3.8）：沿轴位置 = `max(4, 起点 - 12 - 标签实测宽)`。靠 `translate(-100%)` 的话位置全看 `START_LEAD` 猜得准不准——日期格式一变长、换个字体、换种语言，标签就会被轨道起点裁掉半截，**而且是静默的**。那段留白仍由 `segment.minPx` 预留（横排 152 / 竖排 36），走 05§1.2「内容尺寸回灌坐标层」那条既有通道。
- **配套**：domain 首尾两段是**留白**（首个时点前 14 天 / 今天后 10 天），v3.3 起不再给它们画稀疏斜纹带——那说的是一件不存在的事；起点之前也不再出日期刻度。
- **两端同形，只有颜色不同**（v3.17）：`START` 与 `TODAY` 用同一支笔——大写小字距的记号体（同页脚的 `LAST SYNC`），同样的字号、字距与间隙，日期都走 mono/stamp。原来一头写中文「首次使用」、另一头写记号体的 `TODAY`，同一件东西的两头写成了两种体例。区分它们的只剩 `--accent`：那是「今日」的专属色（05§6 第 7 条），起点走中性灰，两端各自是什么仍然一眼可辨。日期的口径（不是账号创建日）留在 `title` 里——那是解释，不是标题。
- **让位按「相邻那一组的内容边缘」算，不是它的中心**（v3.17）：这两枚标**垂轴方向居中于轴线**，也就是横跨轴线——而封面在轴的一侧、截图面板在另一侧，它们**没有「挪到对面去」这条退路**，只能沿轴让开。所以预留 = 标签自己的长度 + **相邻那一组的 `groupFootprint / 2`**，两头都是：
  - 头段（`START_LEAD` + 间隙 + 第一组的一半）；
  - 今天**之前**那一段（最后一组的一半 + 间隙），让最后一组的面板退到 TODAY 标之外；
  - 尾段（`END_LEAD` + 间隙 + 尾端那一组的一半——今天之后也可能有组，比如未来的发售日）。

  竖排下这个坑最明显：标签横躺着有 120 宽，轴两侧各伸出 60，正好落在封面和面板的通道里；原来只让 12px，实测第一组的封面压住起点标、最后一组的截图面板压住 TODAY 标。**渲染层的落点也按同一条边缘算**，但那只是安全网——距离本身由 `segment.minPx` 在坐标层保证（05§1.2），不是渲染时硬挪。
- **今天之后的组不参与推 TODAY 标**（v3.17）：未来的发售日也是轴上的组，拿它去推 TODAY 标会把标推离它自己指的那一天。

### 4.3 变化坐标（多尺度自适应）

轴不是「时间 → 像素」的等距线性映射，而是**按数据密度分段变化尺度**：

| 段 | 尺度 | 刻度 |
|---|---|---|
| **稀疏段** | 压缩，**跨周** | 一格 = 一周（空档再长也只占一条窄的「跨度」带，退到周级甚至月级） |
| **密集段** | 展开，**精确到日** | 一格 = 一天，每个事件 / 簇都有独立落点 |

- **同一屏内可并存多个尺度段**：左半屏一格 = 一周，右半屏一格 = 一天，尺度随数据密度自适应。
- **稀疏段的画法（v2.0 补取值，取自画板）**：轴上一条**斜纹带**——高 13、圆角 7、`repeating-linear-gradient(45deg, rgba(15,23,42,.07) 0 2px, transparent 2px 6px)`，向密集侧用 mask 渐隐（`linear-gradient(90deg,#000 0 76%,transparent)`）；跨度标签在带上方 28、走 `mono/label`。
- 稀疏 / 密集的分界、尺度切换用**渐变还是跳变**：画板已按**渐变**出稿（斜纹向密集侧渐隐），**V0.1 暂按渐变实现**，仍以 spike 6b 在真数据上复核（PRD §8 未决 #3）。
- 与「缩放层级（日 / 周 / 月）」的关系：缩放层级是**全局**的「一屏装多少时间」；变化坐标是**局部**的「这段多长映射成多少像素」——两者正交。缩放层级再粗 / 再细，轴上的稀疏段仍压缩、密集段仍展开。

### 4.4 滚动（边缘触发，微延时）

- **鼠标移到页面左 / 右边缘 → 微延时后时间轴向该方向滑动**，离开边缘即停（避免鼠标路过边缘就误触发）。
- 缩放层级越细（日），滚动步长越小；越粗（月），步长越大。
- V0.1 只做桌面浏览器；移动端滚动后续验证。

### 4.5 数据契约

本范式**不引入区间型数据**——只消费**时点事件**（发售 / 购买 / 首玩 / 成就）+ **截图**（P-12）。原「区间数据需派生」的未决点**已取消**：时间轴要的是"跨度感"，时点 + 截图已足够。

**「时点」的定义（v2.0 定案）**：**凡该用户在某一天有任意一条可渲染数据，该天即是一个时点**——四类事件之一，**或仅有截图**。仅有截图的日期同样成为轴上落点，只是它的轴上方没有 unit（只有引线与截图组），悬浮它出的是该日的游戏形态 panel。这条定义关掉了「截图挂哪儿」的悬空问题。

**截图的挂载判据（v3.4 修正）**：一张截图挂到某个时点下，条件是**该时点当天有这款游戏自己的事件**，不是「当天有任何事件」。原来按日期一刀切，会把 A 游戏事件那天 B 游戏的截图挂到 A 的时点下。挂不上的走 §4.2d。

**成就明细走后端专用路由（v2.0 定案）**：§4.8 成就形态要「成就名 + 图标 + 全球解锁率」，而 `/timeline` 的成就事件只带数量。明细**不塞进全量出参**（体积会翻几倍），改由**后端新增一个按时点取成就明细的路由**，悬浮时懒加载。原 §1「不得引入第三个数据接口」的约束**只约束前端取数函数的数量口径**，不约束后端路由数——该条约束随 §1 一并归档。

**购买事件的数据依赖**：购买时间来自商店购买历史页（web cookie，Layer 2 opt-in）。**Layer 1（OpenID）登录下拿不到购买历史**，此时轴上不出现购买点——这是数据缺失，不是隐藏（P-14 的隐藏是另一回事）。

> **v1.3 补**：每个 `Game` 还要带 `lifecycle` / `shelved_at` / `launched_ever` / `play_days_count` / `ach_unlocked` / `ach_total` 六个字段（后端派生，见 [[02_PRD_游戏日历|PRD]] §3），供 §4.9 的封盘帽与隐藏开关用。仍然不是区间数据——`shelved_at` 是一个时点。

### 4.6 交互

**看**
- **悬浮**轴上方时点标记 → 就地渲染**时点 panel**（取值见 §4.8）；**不使用底部升起的 L3 日详情浮层**（已随范式 A / C 归档）。
- **月档额外可点单个 ICON** → 浮出只读一行日期的读数条（§4.8a）。悬浮与点击并存，不互斥。
- **点封面** → 进全屏灯箱看大图（§4.8）；**在封面上滚轮** → 切下一张 / 下一款。

**移动**
- **滚轮 / 触控板直接平移时间轴**，不必按住任何修饰键——取 `deltaX` / `deltaY` 中量更大的一轴，让纵向滚轮的鼠标与横向滑动的触控板都能直接推轴。
- 前 / 后按钮 = 平移一个层级单位（日 1 天 / 周 7 天 / 月 30 天）。
- 边缘触发滚动见 §4.4。
- **平移时收起所有浮层**：悬浮 panel 与钉住的读数条都锚在某个时点上，轴一动它们就不再指向原来的东西，留着比收掉更容易读错。

**换档**
- **缩放层级 = 日 / 周 / 月**，头部三段切换，`Ctrl` + 滚轮为快捷换档；**默认「月」**。换档以视窗中线为锚，锚点时间不漂移。
- **V0.1 单一范式阶段，横向手势回归「时间轴自身滚动」**（范式切换已归档）。
- **不做「全部」层级**：全量时间跨度在一条轴上会挤成一团。

> **滚轮的三种含义不会打架**：封面上滚 = 切封面（事件在封面上 `stopPropagation`，不会顺带推轴）；按住 `Ctrl` 滚 = 换档；其余位置滚 = 平移。

#### 4.6a 无档缩放（v3.2：取消日 / 周 / 月三档）

原来的三档是 `px/天 = {日 96, 周 28, 月 6}`。**这三个数从来不是三种模式，只是同一条连续区间上的三个采样点**——做成三个互斥按钮的代价是：想看「介于周和月之间」的密度时无处可停，而那恰恰是浏览一年跨度最舒服的密度。v3.2 把它还原成连续量。

| 项 | 定 | 说明 |
|---|---|---|
| **区间** | `px/天 ∈ [1.5, 160]`，默认 **6** | 1.5 → 十年约 5500px、一屏可览；160 → 一天占大半屏，再放大没有信息增量。默认值就是原「月档」，进来先看全局 |
| **缩放方式** | **按比例**（每格 ×1.18），不是按加法 | 加法在 6 px/天 时步子太大、在 96 px/天 时又太小。比例缩放在整个区间上手感一致，也是「无档」的应有之义：相邻两次操作之间没有跳变 |
| **锚点** | `Ctrl` + 滚轮锚在**指针**上，按钮 / 滑块锚在**视窗中心** | 不锚的话每缩放一次视窗都往轴的起点漂，用户得反复把内容拖回来 |
| **控件** | **无**（v3.3 移除 `−` / 滑块 / `+` 与读数）。缩放只走 `Ctrl` + 滚轮 | v3.2 曾在头部放过一条缩放条，v3.3 按要求撤掉。⚠️ **代价要认**：`Ctrl` + 滚轮没有任何视觉入口，第一次来的人不会知道能缩放。头部只剩「上一屏 / 下一屏」两颗按钮 + 导航条 + 方向切换 |
| **刻度粒度** | 从 `[1天, 2天, 1周, 2周, 1月, 3月, 6月, 1年, 2年, 5年]` 里选**第一个**满足「一格宽度 ≥ 最小标签间距」的档 | 缩放时刻度自己从逐日退到逐周、逐月、逐年，不需要用户换档。最小间距横排 **86**、竖排 **26**。⚠️ v3.19 起次刻度不写字了，这个值仍按「放得下 `2026-07-11`」留着——**稀疏段的聚合标签（`起 — 止`）还在用同一个粒度写字**，调小它会把那行挤爆 |
| **稀疏阈值** | 由 px/天 查阶梯：`≥48 → 3 天`、`≥16 → 7`、`≥4 → 14`、否则 `45` | **故意做成阶梯而不是连续函数**：这个值决定轴被切成哪些段，连续变化会让分段结构在缩放过程中不停重组，视觉上是整条轴在抖。三个台阶的取值就是原来那三档的值，观感不变 |
| **ICON 级读数的启用** | `px/天 < 12`（原条件是「月档」） | §4.8a 那层读数是为「一个像素跨好几天」存在的，判据应该是密度而不是档位名 |

#### 4.6c 刻度分主次（v3.19 新增）

原来轴上每一格刻度都配一行字，样式是 `.label` 那套：10.5px、`--text-3`（50% 墨）、字距 .10em、全大写等宽，直接压在壁纸和封面上，没有衬底。三件事叠在一起，结果是「有字但读不出时间」：

1. **字本身太轻**——一排同样淡的小字，没有任何一枚是锚点；
2. **多数刻度不带年份**——周粒度写 `AUG 24`、月粒度写 `AUG`，**只有 1 月那枚才写 `2019`**。滚到十年中间根本不知道是哪一年，而头部读数报的是**视窗中点**，不是你正指着的这一处；
3. **默认那一屏一枚刻度都没有**——稀疏段内部不出刻度，首尾两段连聚合标签也不画。实测最后一枚次刻度在轨道 93680px，而默认视窗是 95430–96870。

| 项 | 定 | 说明 |
|---|---|---|
| **次刻度** | `scale.ticks(spec)` 那一套，位置不变；**只留一道 1 × 4 的淡线（10% 墨），不写字** | 它表达的是「尺子的格」。字多不等于读得出来——十年里几百行同样淡的小字，每一行都在稀释另一行 |
| **主刻度** | 月首 / 年首：`1 × 12` 的线，**横跨轴线**（轴上 4 / 轴下 8），26% 墨 | 跨轴是有意的：它说的是「这里换月了」，是一道分界，不是一枚更长的刻度。和 §4.2a 导航条的年分隔线同一套语言 |
| **主刻度退到哪一级** | 次粒度是日 / 周 → 主刻度按**月**（文案 `2019.08`）；次粒度是月 / 年 → 主刻度按**年**（文案 `2019`） | 主刻度永远比次刻度粗一级，缩放时两层一起退 |
| **主刻度单独生成，不从次刻度里挑** | 直接按 `Date.UTC(y, m, 1)` 落点 | 周粒度下刻度落在周一，「进入 8 月的第一枚刻度」是 8 月 1 日之后的某个周一，跟着周对齐左右漂最多 6 天。这条线既然说「8 月从这里开始」，就该落在 8 月开始的地方 |
| **主标签样式** | 12px、字重 500、`--text-1`、字距 .04em | 它现在是轴上**唯一**的时间锚点，得按主要信息给，不能再套 `.label` 那套次要标注的取值 |
| **一条防撞链管所有标签**（v3.19b 改） | 主刻度的年月与稀疏段的「起 — 止」**落在同一条线上**，放进同一条链里按位置抢位：抢到就写字，抢不到只留线 / 只留斜纹带。两枚标签之间至少留 `LABEL_GAP = 6`。**主刻度先抢**——它是轴上唯一的年份锚点，而稀疏段让掉之后带子还在，跨度改由 `title` 说 | ⚠️ 这是**渲染层的视觉去重，不是坐标层的约束**：刻度与稀疏段标签都是叠在轨道上的绝对定位元素，不推挤任何东西，所以挤不下时少写几个字就行，**绝不能反过来去改间距**——间距归坐标层管（05§1.2）。<br>v3.19 只给主标签之间做了防撞（`MAJOR_MIN_SPACING`），**两类标签之间没有人管**：实测横排 6 处重叠，5 处是两个相邻稀疏段互压（段被压成固定 96px，而标签实测 110px，每边溢出 7px），1 处是主标签压在稀疏段标签上（`2017.12` 压 `DEC 02 — JAN 12` 27px）。分开各做各的防撞是修不完的——它们抢的本来就是同一段空间 |
| **标签宽度怎么来的** | 等宽字体，**字符数 × 单字宽**：10.5px + .10em → 7.35/字，12px + .04em → 7.7/字；竖排标签横放，沿轴占的是行高（16） | 实测 `SEP 12 — OCT 03` 15 字 = 110px、`2015.11` 7 字 = 54px，与 `offsetWidth` 分毫不差。这个估算**只决定写不写字**，估偏一两像素最多是某枚本可以写的标签没写出来，不会让任何东西移位——所以不必进 DOM 实测 |
| **让掉文案的补偿** | 稀疏段带 `title = 「起 — 止 · 这段没有记录，轴上按固定宽度压缩」`；主刻度线 `title` = 那个年月 | 挤掉的是**显示**，不是信息。指上去仍读得到 |
| **刻度粒度算在稀疏段标签之前**（v3.19b 修） | `currentSpec` 的赋值移到那两个循环之前 | 稀疏段那行「起 — 止」的文案也跟着这个粒度走。原来它算在后面，等于**用上一帧的粒度写这一帧的字**。⚠️ 这条错得**没有声音**：`currentSpec` 有初值 `{month, 1}`，所以第一帧不报错，只是一律按月粒度写（该写 `SEP 12 — OCT 03` 的地方写成 `SEP — OCT`），之后每帧慢一拍。有初值反而让它更难被发现 |
| **仍然跳过的三种** | 稀疏段内 / 起点之前 / 恰好是今天 | 前两条同 v3.8；今天那枚由 TODAY 标表达，再画一遍就是同一件事说两遍（05§0 规则 2） |

**已知没解决的**：末段仍然可能一枚次刻度都没有（它整段落在稀疏段里）。默认这一屏因为 9 月 1 日恰好是主刻度而有了 `2026.09`，但那是数据碰巧——彻底修要让首尾稀疏段也出一枚日期，属另一件事。

#### 4.6b 中键自动滚动（v3.11 新增）

按下滚轮中键 → 落一个锚点，鼠标离锚点越远滚得越快；再按中键、按任意其它键、按 `ESC` 或窗口失焦都退出。就是 Windows 上那套熟悉的 autoscroll。

**为什么要自己写**：浏览器自带的中键自动滚动只对**真正会滚的页面**生效。这条轴是用 `transform` 平移的虚拟滚动，`#timeline-body` 是 `overflow:hidden`，原生那套无从下手——按下去只会出现一个滚不动的锚点图标，比没有更糟。所以 `preventDefault()` 挡掉原生的，自己实现一份同样行为的。

| 项 | 定 | 说明 |
|---|---|---|
| **死区** | 锚点周围 **14px** | 手抖不该让整条轴动起来 |
| **速度** | 超出死区后 `(距离 − 14) × 0.26` px/帧，上限 **42** | 上限是必要的：再快就看不清自己滚到哪了。60fps 下满速约 2500 px/s |
| **只取沿轴那一维** | 横排取 `dx`、竖排取 `dy` | 这条轴只有一个方向；把另一维也算进来，斜向移动时方向会忽左忽右 |
| **锚点** | 34px 圆 + 指向可滚方向的两枚箭头 + 中心点；竖排整枚转 90° | 一份 DOM 两个方向 |
| **退出** | 再按中键 / 按其它任意键 / `ESC` / 窗口失焦 | ⚠️「按其它键退出」必须挂在 **window** 上而不是主体区——自动滚动期间去点头部的开关也该退出，挂在主体区上点到外面就停不下来。中键那条留在主体区，否则会自起自停 |
| **与边缘滚动互斥** | 自动滚动进行中，边缘带不再触发 | 两套滚动同时推同一个 offset 会打架 |
| **导航条只认左键** | `pointerdown` 里 `button !== 0` 直接返回 | 否则中键按在导航条上会顺带跳转一次 |

### 4.7 实现形态

- **传统 HTML 先行**：单页 `index.html` + CSS + JS，浏览器直接打开；不依赖 Electron / Tauri / 后端常驻。
- **数据获取**：V0.1 前端先**纯 mock 跑交互**（`mock-data.js`）；接真数据时**后端一次性返回全量**（`TimelineEvent[]` + `screenshots[]`），前端本地按范围 / 层级过滤，不按范围多次请求。
- **三套数据环境并行**，视图层对自己跑在哪套完全无感知（分流在取数门面内部，见 `timeline/docs/前端开发规范.md` §4a）：

  | 环境 | 来源 | 可写 | 生命周期 |
  |---|---|---|---|
  | `MOCK` | 本地假数据 | 假同步 | 持久（localStorage） |
  | `LIVE` | 真实后端 | 可同步 | 持久（localStorage） |
  | `IMPORT` | 用户导入的一份 JSON 备份 | **只读** | **仅本次会话**，刷新即失效 |

  `IMPORT` 是为了让「导出的备份」有地方可看，同时给不想登录的人一条无网路径。它只在内存里——一份几十 MB 的库塞进浏览器 storage 不稳，宁可让它随刷新消失，也不留一个取不到数的死状态。导出的备份**不含成就明细**（逐款拉会打上百个请求），所以导入后成就面板显示「当日无成就明细」。
- 封装成桌面客户端的时机与方案见 PRD §6 V0.2 与 [[04_未来规划_游戏日历|未来规划]]。

#### 4.8-1 为什么改成逐 ICON（v3.14）

原先整条命中区一起变色、panel 也讲整天。**一天三个 ICON 时三个一起亮，可用户想指的只有一个**——
界面上没有任何地方回答「我指的是哪一个」，看到的和能操作的对不上。

分格用的是**相邻 ICON 的中点**，不是各自取一个固定宽度：

- 固定宽度**偏大**就互相压住——ICON 中心间距只有 26~42px，40px 的格子会重叠约 6px，瞄准左边那个的右缘却命中右边那个，表现是「hover 不响应」；
- 固定宽度**偏小**就留下缝隙——缝隙里既不高亮也不出 panel，是一块解释不清的死区。

按中点切分之后，命中区里每一个像素都恰好属于一个 ICON。实测 LIVE 1209 个时点组、1484 个格子，
**重叠 0、缝隙 0**，横竖两个方向都是。

⚠️ **`mouseleave` 仍然挂在整条命中区上**，不挂在格子上。挂格子的话，格与格之间移动会先触发一次
离开，panel 每换一个 ICON 都要闪一下。

⚠️ 轴上**没有 unit** 的组（截图面板锚点）分不出格子，仍整块响应——那类组标 `.whole`，是唯一的例外。

### 4.8a 月档：ICON 级的日期读数（v3.0 新增）

**为什么要有这一层**：月档一格 = 一个月量级，轴上一个落点常常压着好几天的事件。组级悬浮 panel 给的是「这一簇」的日期，回答不了「那个购买点到底是 7 月 2 号还是 7 月 6 号」。所以月档在组级命中区**之内**，再给每个 unit 一个 40 × 40 的圆形命中区。

| 项 | 定 |
|---|---|
| **触发** | **点击**（不是悬浮）。悬浮已经被组级 panel 占用了，再叠一层悬浮会互相打断 |
| **命中区** | 40 × 40 圆形，水平居中于该 unit 的 ICON；**必须是组级命中区的子元素**——做成兄弟节点的话，指针停在 ICON 上会被判成离开组，组级悬浮会被自己打断 |
| **只在月档有** | 日 / 周档一格就是一天 / 一周，组日期本身已经够准，不需要这一层 |
| **非成就事件** | 浮出**日期读数条**：无底色、仅描边，内容 = 46 × 69 小封面 + 该事件的确切日期，底边垂一条 15px 引线指回被点的 ICON。**只给日期，不给别的**——要更多信息，悬浮那一层已经在给了 |
| **成就事件** | 读数条升级成完整的成就形态面板（宽 320，内容同 §4.8），顶部收敛到头部下沿 8px |
| **一次只开一个** | 点另一个 ICON 换过去；再点同一个、点空白处、按 `ESC` 都收起。轴一平移也收起（§4.6） |
| **与悬浮 panel 的关系** | 打开读数条时立即收掉悬浮 panel——一个是钉住的、一个是跟手的，叠在一起会打架 |
| **不放什么** | 不放事件行、不放封盘依据、不放截图。这一层的存在理由只有一个：**读准日期** |

### 4.9 封盘与生命状态（PRD P-13 / P-14）

判定规则、四种状态与三个阈值的**唯一来源是 [[02_PRD_游戏日历|PRD]] §3**，本节只定「轴上怎么画」。

| 项 | 定 |
|---|---|
| **封盘帽** | 该游戏 `shelved_at`（= 最后活动时点）那一组里，**压在对应 unit 正上方 4px**：宽 12、高 1.5、圆角 1 的横线，色 `--text-3`。像给这一竖收个顶——线到此为止 |
| **为什么按 unit 不按时点** | 一个时点常有多款游戏，封盘是**单款游戏**的状态；压在那款游戏的图标 / 色点这一竖上才指得准 |
| **不引入新色** | 用 `--text-3` 中性色，不占事件色、不用主题色（05 §3.3 / 规则 8）。封盘不是第五类事件，是状态 |
| **帽子会消失** | `lifecycle` 是每次同步现算的（PRD §3）：该游戏**再次启动 → 下次同步回 `active`，封盘帽自动消失**。所以封盘帽是「这条线到今天为止停在这里」的当下状态，不是刻上去的结论；渲染层不缓存这个状态，跟着 `/timeline` 返回的 `lifecycle` 走 |
| **不做的事** | 不画「封盘」横幅；不把封盘游戏的历史事件整组降透明度（会和 05 §6.6「非本月降 45%」的语义撞车）；不给 `dormant` 画任何标记 |
| **悬浮 panel 的补充** | 游戏形态 panel 头部：游戏名右侧一枚 `caption` 11、`--text-3` 的「封盘」文字标；日期行右侧补判定依据 `运行 63 天 · 成就 38/50`（`mono/stamp`）。**依据不与日期同排**（v2.1 修正：`运行 63 天 · 成就 38/50` 实测 141px，加日期 66px 超出右栏 184px），改为日期**下方**独立一行；**依据里给运行天数不给小时数**——小时数只在后端判定用，界面上「玩得久不久」只有 P-9 运行天数一个指标 |
| **never_launched 被隐藏时** | 该游戏的**全部事件（购买 / 发售）一并不进轴**，不是只灰掉——否则轴上仍是它的点，隐藏没有意义。开关见 [[开发文档/02_前端功能文档\|02 前端功能]] §4 |
| **过滤在前端做** | 全量数据本就一次性到前端（§4.7），开关切换是本地重算 + 120ms 淡入，不重新请求；轴的坐标随之重算（隐藏后稀疏段会更长，变化坐标自然吸收） |

### 4.10 纵向时间轴（v3.2 新增）

头部一颗图标钮在横排 / 竖排之间切换，偏好存 localStorage。**功能完全一致**——同一份渲染代码、同一套布局规则，不是两个视图。

做得成的原因是把这一层的几何量从「宽 / 高」改写成了「**沿轴 main / 垂轴 cross**」：

| 术语 | 横排 | 竖排 | 谁归它管 |
|---|---|---|---|
| **main**（沿轴） | x | y | 时点间距、组占位、截图增列、轨道长度、平移 |
| **cross**（垂轴） | y | x | 轴线位置、引线长度、每列截图张数、封面厚度 |

换方向就是这两个词换个绑定，**规则本身一个字都不改**。具体到实现：`#timeline-body[data-orient]` 是唯一开关，JS 只负责写 `--axis-c`（轴线的垂轴位置）与元素的沿轴坐标，「谁该朝哪边长」全部由 CSS 表达。

| 元素 | 横排 | 竖排 |
|---|---|---|
| 轴线 | 水平线，y = `--axis-c` | 竖直线，x = `--axis-c` |
| 时点组 | 锚在轴上向**上**长：封面 → 图标 → 引线 | 锚在轴上向**左**长，顺序同左 |
| unit 内部 | 图标在上、色点朝下（朝轴） | 图标在左、色点朝右（朝轴） |
| `×N` | 把 unit 沿轴**拉长**（14 → 30） | 挂在图标侧面，**加厚**不加长（+16） |
| 日期标签 | 轴上方 10 | 轴左侧 10 |
| 截图 | 列内竖叠、列间横排 | 列内横排、列间竖叠 |
| 悬浮 panel | 标记上方，沿 x 居中 | 标记左侧，沿 y 居中 |
| 导航条 | 上沿横放 | 左沿竖放 |
| 滚轮 / 边缘滚动 | 左右 | 上下（竖排时纵向滚轮天然就是沿轴方向） |

轴线仍然「垂轴方向居中」（05 §1.1）：横排是垂直居中，竖排是水平居中，同一条规则。

⚠️ 竖排下 panel 的沿轴居中**必须按实测尺寸算**，不能用 §4.8 的标称高度：成就明细是异步到达的，定位那一刻面板还是「加载中」那一行的高度。v3.2 的做法是按标称值给 `min-height` **预留**——既让定位时量到的就是最终尺寸，也顺手消掉了「面板在光标底下自己长高一截」的抖动。

## 8. 未决与风险（v2.0 收窄为时间轴相关）

1. **变化坐标的分段阈值**与尺度切换的「渐变 vs 跳变」（PRD §8 未决 #3）：画板已按渐变出稿，V0.1 暂按渐变实现，用 mock 与真数据复核（spike 6b）。
2. ~~引线（stem）高度的分配规则未定~~ **v2.1 已关闭**：算法定为「默认 64，命中区重叠时逐级抬高、步进 40、上限 4 档」，写进 05 §6 第 3 条与 `build_timeline.py::assign_stems`。
3. **成就 `unlocktime` 密度**：密到什么程度需要 canvas 承接、稀到什么程度撑不起「过去」，需真库验证（spike）。
4. **45 天阈值下封盘帽的密度**：阈值短会让帽子明显变多，可读性要在真库上看（PRD §3 已承认这个代价）。
5. **购买点的可得性**：Layer 1 登录拿不到购买历史，轴上会缺一整类事件；是否引导用户升级 Layer 2 属产品决策。
