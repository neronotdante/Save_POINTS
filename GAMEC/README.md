# GAMEC — 产品报告与设计文档仓库

本目录（`GAMEC/`）用于管理**产品相关的报告与设计文档**，不涉及任何代码开发。

## 用途与范围

- 调研报告、PRD、设计方案、原型说明等产品 / 设计类文档。
- 后续可存放其他设计文件（图稿、流程、规范等）。
- **仅本地 Git 存储**，不推送到 GitHub 或任何远程仓库。

## 后续处理规则（AI 协作约定）

> **2026-09-01 · V0.1 锁定**：唯一视图 = **横向时间轴（浏览器单页）**。月历 / 周列看板 / 左历右详三套范式、桌面壳与玻璃取值、旧的后端开发计划**全部归档**，不再出现在当前文档中。

### 文档

1. **文档优先**：任何设计 / 需求结论先落到本目录的 `.md`，再谈实现。口头结论不算数。
2. **单一来源**：产品范围以 `02_PRD_游戏日历.md` 为准；UI 通用取值（色彩 / 字体 / 组件 / 事件标记 / 动效 / 画布基准）以 `05_UI设计规范_游戏日历.md` 为准；时间轴自身取值以 `07_视图范式_游戏日历.md` §4 为准。冲突时先改文档再改代码。
3. **不重复**：新结论写进已有文档的对应章节，不新开文件；同一主题散在多文件时合并，被合并的文件移入 `_to_delete/` 并回改链接。
4. **暂不实现的内容**移入 `04_未来规划_游戏日历.md`；**已实现过但本轮不做的**移入 `_archive/` 对应子目录（见目录说明）。
5. **去除冗余项**：界面上每个元素必须能对应一条 PRD 用户故事，答不上来就删；同一信息一屏内不出现两次。
6. **基准尺寸**：**1440 × 900 桌面浏览器视口**为设计基准，最小可用视口 1120 × 720（05 §1.1）。原 668 × 768 面板基准属桌面壳阶段，已归档。
7. **视觉方向**：**浅色传统 HTML 页**，不画玻璃底、不悬浮桌面、不挂托盘。玻璃 / 悬浮 / 托盘随 V0.2 封装再评估（取值在 `_archive/UI/`）。深色皮肤仍在 `04_未来规划` 未解禁。
8. **颜色只有一处个性化**：成就 / 首次游玩用游戏封面主题色（本地取色 + 回退，缓存）；**购买 `--ev-purchase` `#0E9E68`**、发售 `--ev-release` `#2F6BFF` 为系统固定色；不得引入第二个可变色源（唯一例外：封面占位可用主题色双色渐变）。
9. **回复尽量简短**：改动完成后用总结陈述结果，不复述文档内容、不贴全文。
10. **设计稿走可视化画布**（当前只维护 `canvas/范式B_V1/`），不直接产出可运行 HTML；开发实现在代码仓库。
11. **每次改动都要提交**：DESIGN 用「类型: 标题 + 原因/改了什么/影响范围」（类型：报告/设计/文档/修订/杂项）；`backend` / `timeline` 用 Conventional Commits，两套别混用。
12. **实施与测试只按时间轴**：不提前给已归档的范式写渲染层、写测试、画画板。
13. **唯一的开发规划在 Project 的 `claude/INBOX.md`**——DESIGN 目录内不再维护第二份计划文档。

## 提交规范（Commit 约定）

提交记录的目标是**记录每一次报告或设计更改的细节**，便于回溯每一次改动的原因与内容。请遵循以下格式：

```
<类型>: <简短标题>

- 本次更改的背景 / 原因
- 具体改了什么
- 影响范围
```

类型取值：

| 类型   | 含义                     |
| ------ | ------------------------ |
| 报告   | 新增 / 更新调研报告      |
| 设计   | 设计方案的改动           |
| 文档   | 其他文档类改动           |
| 修订   | 对既有内容的修订 / 订正  |
| 杂项   | 目录结构、说明文件等     |

示例：

```
设计: 调整游戏日历的筛选交互

- 将"按类型筛选"从下拉框改为标签页，减少点击层级
- 增加"今日"快捷定位按钮
- 影响：主界面信息架构与交互稿（02_PRD_游戏日历.md）
```
