# 前端功能文档

> 用途：前端（UI 层）的功能与交互规格。**取值（颜色 / 事件色 / 字体 / 组件）以 [[05_UI设计规范_游戏日历|UI 规范]] 通用章节为准**，本文档只描述"有什么、怎么交互、数据从哪来"，不重复具体数值。
> 上游：[[02_PRD_游戏日历|PRD v1.0]] §4。
> 方向（v1.0）：主视图 = 横向时间轴（范式 B），**传统 HTML 实现**；液态玻璃悬浮 / 托盘等桌面壳延后（见 [[04_未来规划_游戏日历|未来规划]]）。
>
> **v1.1 变更（2026-09-02，两套环境并行）**

> 2. **§8 新增取数门面**：视图层只认 `timeline/api.js` 一个入口，MOCK / LIVE 在门面内分流；明确 `mock-data.js` 出参形状必须逐字段对齐后端，并记下 `TimelineEvent.date` 只到日、时刻走 `/calendar/day` 懒加载补齐。
> 3. **§4 账号组补环境徽章与切换**；§1 界面清单相应更新。

> **v1.2 变更（2026-09-03，Steam 登录链路修复）**
> 1. **§5.3 改写为全自动回跳**：后端验签后 302 回前端、token 走 URL fragment，不再需要手工粘贴；前端改整页跳转（`window.open` 会被拦 / 在 CEF 里降级成当页导航）。对应后端新增 `GC_FRONTEND_BASE_URL`（见 [[05_后端接口文档|05]] §3）。
> 2. **记下端口硬约束**：前端不得用 8080——被 Steam 客户端 CEF 调试占用，默认端口改为 5173。这是本项目用户必然撞上的冲突。
> 3. **§5.4 补失败回跳与探活**：登录失败 302 回前端带 `#error=`；点登录前先探 `/health`。

## 2. 时间轴主视图（范式 B）

**结构**：顶部（时间范围指示 + 缩放层级）→ 横向中心轴 → 轴上方时点事件 / 轴下方截图。

- **轴**：一条水平线，**在主体区（头部 96 与底栏 34 之间）垂直居中**——不是「屏幕垂直中心」，两种算法差 47px（05 §1.1）。
- **轴上方**：时点事件标记（**发售 · 购买 · 首次启动 · 成就簇**），unit = 图标 + 可选 `×N` + 色点，组底引线连到轴；成就 / 首玩取游戏主题色，购买 `--ev-purchase`、发售 `--ev-release`；一组最多 3 个 unit，超出 `+N` 折叠。
- **轴下方**：**首玩封面 + 该时点的游戏截图缩略图**并排，整块以时点为中心居中。截图**竖向排列，每列最多 5 张，超过增开一列**；**首次游玩的游戏另有一张 76 × 114 封面**落在截图左侧（v1.6），左上角一枚主题色 play 角标——轴上只有一个 14px 图标，那天开的是哪款游戏原本只能悬浮才知道。取值见 [[07_视图范式_游戏日历|07]] §4.2。
- **截图与封面可点看原图**（v1.6，落地 P-12）：点缩略图 / 封面进全屏灯箱（截图舞台 16:9，封面 2:3），左右翻页、`ESC` 关闭。
- **一键设为页面背景**（v1.6）：灯箱底部一颗按钮，把当前这张钉成**整页底色**，再点取消。偏好存 localStorage，首启 / 时间轴 / 设置三个视图共享。底图重度模糊 + `.88` 洗白——目标是「这张图的底色铺满整页」而不是把照片贴在内容后面；洗白值是按 05§3.4 的对比度护栏倒算的，见 05§3.1。
- **全景导航条**（v1.6）：主体区顶部一条横贯全宽的活动概览（密度柱 + 年号 + 视窗框）。domain 是十年而一屏只看得见几周，原来跳到某一年只能一路滚；现在点一下跳过去、拖着走，悬停出「年.月 · 事件 N · 截图 M」。蓝柱 = 那段时间开了新游戏。取值见 07§4.2a。
- **日期标签在轴的上方**（v1.6，由「轴下 11」改）：轴下方已是截图 + 封面的密集区。引线随之在底部渐隐，不穿过日期。
- **滚动（边缘触发，微延时）**：鼠标移到页面左 / 右边缘，**微延时后**时间轴向该方向滑动，离开边缘即停。
- **变化坐标（多尺度）**：稀疏段压缩、刻度退到「跨周」；密集段展开、刻度精确到「日」；同一屏可并存多个尺度段，尺度随数据密度自适应。
- **缩放（v1.7 改为无档）**：取消日 / 周 / 月三段切换器，改为连续的 px/天（1.5 ~ 160，默认 6）。头部是 `−` / 滑块 / `+` 三件套，读数写「一屏 ≈ 4 个月」；`Ctrl` + 滚轮同样缩放且**锚在指针上**。刻度粒度（逐日 → 逐周 → 逐月 → 逐年）、稀疏压缩阈值、ICON 级读数的启用条件全部由当前密度现算，不再查档位表。理由见 07§4.6a。
- **中键自动滚动**（v2.6）：按下滚轮中键落一个锚点，鼠标离得越远滚得越快；再按中键 / 按其它键 / `ESC` / 窗口失焦退出。**浏览器自带那套只对真正会滚的页面生效**，这条轴是 transform 虚拟滚动、`overflow:hidden`，原生按下去只会出现一个滚不动的锚点，所以自己实现了一份。死区 14px、上限 42px/帧、只取沿轴那一维。取值见 07§4.6b。
- **滚轮直接平移**（v1.3）：不按修饰键时滚轮 / 触控板直接推轴，取 `deltaX` / `deltaY` 中量更大的一轴。三种滚轮含义互不冲突——封面上滚 = 切封面，`Ctrl` + 滚 = 换档，其余 = 平移。
- **头部时间读数**（v1.3）：年份 26px 弱化 + 当前月份 44px 强调，等宽数字。三档统一显示「年 . 月」，**档位由切换器表达，不由读数表达**。为什么不用比例字体见 05 §4。
- ~~**粗粒度下可点单个 ICON**（v1.3，v1.7 改判据）~~ **v3.9 移除**：时点组本来就是按天分的，一组里所有 ICON 同属一天，读数条写的日期与悬浮 panel 是同一个、封面也是同一张——它给的是 panel 的真子集，却自带一条引线与该组的引线并排画，同一个时点被两条线指着。逐 ICON 的点击层现在**只为截图 unit 保留**（07 §4.2g）。
- **纵向时间轴**（v1.7）：头部一颗图标钮在横排 / 竖排间切换，偏好存 localStorage。**功能完全一致**，同一份渲染代码——这一层的几何量已改写成「沿轴 / 垂轴」，换方向只是这两个词换个绑定。取值见 07§4.10。
- **开局封面在轴的标记侧**（v1.7 由截图侧移来）：封面、事件图标、引线连成一竖，「这一天我开了这款游戏」一眼成立，也不再和截图抢沿轴位置。
- **封盘后重启也挂封面**（v1.8）：某款游戏在轴上的可见活动（首玩 / 成就）断了 **≥ 45 天**（PRD §3 的 `T_quiet`）又出现，那一天也给它一张封面，用 **3px 深色内描边**与首玩区分。两者是同一件事的两次发生。⚠️ 判据与后端 `lifecycle` 不同口径——后端按「最后一次启动」算，前端只看得见事件，是启动的下界近似（实测 LIVE 库 69 张首玩 + 116 张重启）。
- **封面有两种形态**（v1.8）：竖版海报 76 × 114（`cover_portrait`）/ 横版头图 136 × 114（`cover`·`header_image`），按素材来自哪个字段决定。原来一律按 2:3 裁，横版头图只剩正中间一条。**两种形态等高**（v3.9，原为 136 × 64 的等面积）：一整条轴看过去，矮 50px 的横版内沿对齐后外沿参差，读成「没长齐」而不是「另一种比例」；混排不同比例的图，通行做法是统一一条边。多出来的 50px 用**同一张头图放大模糊铺底 + 原图清晰居中叠加**填满——按 `cover` 裁会切掉 logo（实测「WATCH DOGS」只剩「WATCH DOG」），而 logo 是横版头图上唯一能认出游戏的东西；留主题色空带则有 44% 面积是空的，像图没加载完。沿轴长度维持 136 不变：轴上稀缺的是时间方向。**灯箱舞台也跟着当前这张的比例变**（保面积不保边长）——一款游戏的变体常是「第一张竖版、第二张横版」，固定舞台两种都难看。
- **封面上不再有游戏名缩写与 play 角标**（v1.8）：真封面本身就认得出是哪款游戏。
- **轴上显示成就图标**（v1.8）：解锁成就的时点在标记侧摆出当天的成就图标（32 × 32，最多 3 个 + `N`），**悬停出「成就名 / 解锁时刻 · 全球解锁率」**。明细走懒加载路由、与悬浮面板共用缓存；只拉当前视窗区间内那几组。
- **轴上成就图标摆成「定形簇」**（v2.2）：由「一行最多 3 个」改为堆成一簇，上限提到 9，**1~9 各手工定一个形**（`1 / 2 / 3 / 2-2 / 3-2 / 3-3 / 2-3-2 / 3-2-3 / 3-3-3`）。7 的菱形、8 的沙漏让「这天解了几个」可以凭形状认出来。
  - ⚠️ 中途试过「规整网格 + ±2px 确定性偏移」求有机感，**撤销了**：没有规律的不齐读作失误，不是有机感。
- **成就可以分到轴的两侧**（v2.2）：判据是**选让两侧最长边最短的那个分法**，平手优先对半分。一条规则同时解决平衡与密度——轴下方有截图面板时成就自然全留上面，轴下方空着时自然匀一半下去；而两侧最长边正是这个时点的沿轴占位，所以最平衡也就是最省地方。
  - 实测（真实库 1172 天）：沿轴占位 82 → 48 → **37px/时点（累计 −55%）**，露出的成就 +43%，**轴下方的占用率 8% → 100%**——之前提过的「九成时点只有上半边」一并解决。
- **封面边框用主题色**（v2.0）：边框颜色 = 该游戏的主题色（后端从封面取的）。**取不到色的不画颜色**，回落到中性细边——兜底紫不是这款游戏的颜色，描一圈边等于在冒充信息。实测 185 张封面里 173 张上色、106 种不同色，12 张中性边。
  - 配套把后端的近灰度门槛从 12% 放宽到 5%（`normalize_color` 本就把饱和度钳到 35~85%，那道门槛只该判「有没有色相」），并回填了历史数据：取色成功 305 → 324 款。
  - ⚠️ 曾在前端加过一套画布取色补位，**已删除**：同一套算法、同一张图，算不出更好的结果，却因 Steam CDN 部分资源 404（无 ACAO 头，浏览器报成 CORS）刷一屏报错。根因在后端就该修在后端。
- **轴下方一律是面板**（v2.0）：对得上轴的截图也包同一套外壳，标题写游戏名，与游戏截图面板完全一致。张数按钮只在装不下时才出。
- **面板标题字体归位到字阶**（v2.0）：标题 `body`（13.5/500）、张数 `mono/stamp`（11）。原来的 12/500 与 10/.04em 都是字阶外的自造值。
- **截图按「能否对上轴」分流**（v1.9）：判据是**同一款游戏同一天有没有事件**（购买 / 首玩 / 成就 / 发售）。对得上的挂那个时点；对不上的按游戏归堆，**该游戏 ≥ 5 张就收成一个「游戏截图面板」**（标题 = 游戏名 + 张数，锚在中位日期，面板内最多摆 12 张、点张数看全部），不够 5 张的仍按日期挂回轴上。真实库实测：332 张里对得上 166、对不上 166，阈值 5 时 14 款游戏成面板收走 114 张。理由与取值见 07§4.2d。
  - ⚠️ 原来是**按日期**一刀切，A 游戏有成就那天 B 游戏的截图也会挂到 A 的时点下——说的是一件没发生过的事。
- **截图有了自己的事件图标**（v2.4）：相机图标，与其它事件图标同构（14px + 可选 `×N` + 色点，取游戏主题色）。原本截图只在轴外侧铺缩略图、轴上没有痕迹。
- **隐藏成就开关**（v2.5）：成就事件整类不进轴（钥匙图标、`×N`、图标簇一起没有），只留购买 / 首玩 / 发售 / 截图。与精简模式是两件事：那个屏蔽图像、事件图标照留；这个屏蔽整类事件。默认关。
  - ⚠️ 连带：截图会按 07§4.2d 重新按游戏归堆（那天不再是时点了）；回归封面只剩「那天还在轴上」的那些。
  - ⚠️ 修了一个连带 bug：「封盘后重启」原本从**已过滤**的 unit 推，一开这个开关回归封面会全部消失（7 → 0）。回归是数据属性，判定已改为从未过滤的事件里算（现在是 7 → 4，剩下 3 个的回归日是纯成就日、时点本身不在了）。
- **精简模式开关**（v2.4）：头部一颗按钮，屏蔽成就图标簇与截图面板，只留事件图标与开局封面。**屏蔽的内容同时退出布局**，轨道实测 21680 → 10743（−50%），时点数不变。默认关。取值见 07§4.2e。
- **截图面板换外壳 + 标题居中写全**（v3.1）：白玻璃卡片撤掉——轴下本来就是浅灰，再叠半透明白等于给纯色描边，「有个框」比「里面是什么」还显眼。外壳定为**只留对角两个主题色角标**，底透明。取值见 07§4.2j。
  - 标题居中用 `1fr auto 1fr`，左侧放一个与「张数」同字的隐形替身，两侧留白才真正等宽（只靠 `1fr` 会偏半个按钮，实测 10.6px）；张数按钮必须 `nowrap`，否则中文逐字可断、min-content 只有一个字宽，标题一长张数就折成两行、标题栏从 20 撑到 33。
  - **标题写得全**：横排下先按标题定面板最小宽度（canvas `measureText`，上限 330 = 实测最长单游戏名 326），再把图**横着摊开**去占满这个宽度，摊不满的留白居中。竖排下标题在垂轴，改走 `min-width`。实测 LIVE：标题被省略 75 → **6**（全部是日面板，单游戏面板 0/94），轨道 87838 → 94130（+7.2%）。
  - ⚠️ **三栏网格的两条 8px `gap` 恒定占位**，两侧空栏也算——漏掉就正好短 16px，表现是「明明加宽了标题还是省略号」。
  - ⚠️ 一并修了三处「框和内容对不上」：漏算标题与网格之间的 6px；竖排 `panelChromeCross` 直接返回 0（少减了内边距）；标题把面板顶宽 26px（改用 `width:0 + min-width:100%`）。横竖两向实测溢出 0、框大于内容 0。
- **悬浮收敛到单个 ICON**（v2.9）：命中区按相邻 ICON 的中点切成一格一个 unit，`--hover` 底色只加在指针底下那一格上，panel 也只讲那一格所属的游戏（同一款当天的其它事件仍一起列出）。原先整条命中区一起变色、内容是整天——一天三个 ICON 就三个一起亮，用户想指的只有一个，看到的和能操作的对不上。实测 LIVE 1209 组 / 1484 格，重叠 0、缝隙 0，横竖都是。取值见 07§4.8。
  - ⚠️ 按中点切分而不是各自取固定宽度：偏大互相压住（瞄左边那个的右缘却命中右边的，表现是「hover 不响应」），偏小留下缝隙（既不高亮也不出 panel 的死区）。
  - ⚠️ `mouseleave` 仍挂在整条命中区上，不挂格子——挂格子的话格与格之间移动会先触发离开，panel 每换一个 ICON 闪一下。
- **封面对齐到一条线**（v2.8）：一排开局封面钉在距轴统一距离上，两侧、两个方向都一样。封面带**脱离标记块的流**，不再被两件与封面无关的事顶歪——引线分档（64/104/144/184）和 `×N` 的实际字宽。实测 1280×800：横排精简 144、横排完整 104、竖排 129，28 张全部一个值，与图标的净空 ≥8。取值见 07§4.2i。
  - ⚠️ 顺带修了 `XN_EXTRA` 16 → 25：它按两位数估的，模型比实际薄 3px，竖排下净空从 8 掉到 5。
- **封面加载失败查清了**（v2.8）：`cover_portrait` 是按 appid 拼的模板地址（`{cdn}/{appid}/library_600x900.jpg`），**从没验证过**，但并不是每个 app 都上传过 library capsule。实测真实库 334 个地址里 **32 个（9.6%）是 404**，而这 32 款的横版 `header_image` **全部可用**（334/334 全 200）。失败的两头很整齐：未发售的新作与 demo（仁王３、女神异闻录６、影之刃零、F1 25…）和 2019 库改版之前的老游戏（COD MW2 2009、刺客信条 DC 版）。
  - 三处一起修：后端 `sync_service._resolve_cover_portrait` **存之前先 HEAD**（已验过的不重复探，存 None 的每次重探一次，Steam 后来补图能自愈）；`backend/scripts/verify_cover_portrait.py` 回填既有数据（`--apply` 才写库）；前端 `fallbackWhenBroken` 兜底——贴图挂了就退到下一个变体，**不换尺寸**（形态是坐标层算间距时的输入，这时候改会把整条轴弄错）。
  - ⚠️ 之所以一直没人发现，是因为 `background-image` 加载失败**完全静默**：页面只露出底下那层主题色渐变，看着就像「这些游戏没有封面」。
- **封面跨轴交错**（v2.7）：精简模式下相邻的开局封面**一个在轴上、一个在轴下**，图标与引线一并跟着换边（换的是一整组）。精简模式下对侧本来就空着，换过去正好把闲置的那半边用起来。收益在坐标层而不只是观感——一上一下的两组沿轴根本不会撞，间距约束改为**分侧**计算，实测 MOCK 横排 1280×800 轨道 5431 → 5217（−214px / −3.9%），28 张封面 14 上 14 下。只有封面组参与轮转（纯图标的日子留在标记侧，否则整条图标脊线跟着抖是噪声）；按时间顺序轮转（缩放 / 换向后不跳）；对侧厚度不够或封面已被迫缩小时整个关掉。取值见 07§4.2h。
  - ⚠️ **隔一个的同侧组要单独校验**：A(上) B(下) C(上) 的两段都被放松过，A 与 C 仍会在上侧撞。间距只能表达在相邻段上，所以把这条约束均摊到中间两段。少了这一趟，是否重叠只取决于数据碰巧。
  - ⚠️ 跟着换边的还有命中区、悬浮 panel 两样，漏一样就露馅；`settleResize` 的「占位没变就不重排」判据也要把交错开关算进去，否则拉窗口时交错会时有时无。
- **截图图标可点开**（v2.7）：轴上的相机图标任何缩放下都可点，点开就是那天那款游戏的截图灯箱（光标 `zoom-in`）。精简模式下面板已经不在，图标是那批截图**唯一的入口**，给了痕迹却点不开等于把内容锁死。取值见 07§4.2g。
  - ⚠️ 截图 unit 必须携带**截图本身**而不只是张数，否则会出现「显示 5 张、点开 0 张」这种只在某个模式下暴露的偏差。
- **起点是轴的起点，不是一枚标签**（v2.3）：轴线本身从第一个时点开始画，端帽横跨轴线（像尺子上的「0」，不用圆点——圆点在这条轴上是事件色点的语汇），标签落在**轴线的延长线上**、垂轴方向居中。两个方向同一条规则，竖排下不再歪向一侧。标签的沿轴落点按**实测宽度**夹进轨道，不靠 `translate(-100%)` 猜。
- **封面跟这个时点摆出来的内容走**（v3.18）：代表游戏 = **首个成就的游戏 > 截图的游戏**，代表封面排在最靠成就簇那一端。「首个」按 `TimelineEvent.minutes` 的时刻取，不按数组顺序（后端按 `(date, type)` 排序，同一天里成就之间只剩数据库扫描顺序）。**只改「那张图该是谁」，不给没有封面的时点补图**——1203 个时点里 1173 个有成就，补下去轴要长 3~4 倍；张数也不变，对不上就顶掉一张。第三种 kind `play`（这一天在玩）与 `first` 同一圈主题色环，只有说法不同。**只顶 `first`，绝不顶 `return`**：首玩那天轴上还有 play 图标，而「封盘后重启」只由封面那圈墨线表达，顶掉就没了。详见 07§4.2k。
- **悬浮形态由指针底下那一格决定**（v3.18）：指成就出成就明细，指首玩出游戏信息。原来判的是「这一组全是成就」，同一天同一款游戏既首玩又解成就时（实测 171 个时点）条件不成立，指着成就弹出来的是首玩信息。
- **刻度分主次**（v3.19）：次刻度只留一道 4px 淡线、**不写字**；主刻度（月首 / 年首）横跨轴线，标签 12px / `--text-1` / **写全年份**（`2019.08` / `2019`）。原来每格一行 10.5px、50% 墨的小字，密、淡，而且周粒度写 `AUG 24`、月粒度写 `AUG`——**只有 1 月那枚带年**，滚到中间读不出是哪一年（头部读数报的是视窗中点，不是你指着的那一处）。主刻度**单独按月初生成**，不从次刻度里挑：周粒度下刻度落在周一，「8 月的第一枚刻度」会跟着周对齐漂最多 6 天。详见 07§4.6c。
  - **一条防撞链管住轴上所有写字的标签**（v3.19b）：主刻度的年月和稀疏段的「起 — 止」落在同一条线上、抢同一段空间，放进同一条链按位置抢位，主刻度先抢。抢不到就只留线 / 只留斜纹带，跨度与年月改由 `title` 说——挤掉的是显示，不是信息。<br>⚠️ 分开各做各的防撞修不完：v3.19 只做了主标签之间，实测横排仍有 **6 处重叠**（5 处两个相邻稀疏段互压——段被压成固定 96px 而标签 110px，每边溢出 7px；1 处主标签压稀疏段标签 27px）。修后横竖两向 × 四档缩放（1.5 / 6 / 40 / 160 px/天）**重叠恒为 0**，最小间距 8~82px。
  - ⚠️ 挤不下时**只画线不写字**——刻度是叠在轨道上的，不推挤任何东西，所以渲染层能选的只有「说不说」，**不能反过来去改间距**（间距归坐标层管）。标签宽度用「字符数 × 单字宽」估（等宽字体，实测与 `offsetWidth` 分毫不差），它只决定写不写字，所以可以估、不必进 DOM 量。
  - **精简模式只屏蔽截图，成就簇照留**（v3.21）：原来一个开关管两件事（成就簇 + 截图面板），而「成就该不该显示」本来就有「隐藏成就」单独管——打开精简等于顺手把成就也关了，轴下方只剩一排封面。两个开关现在正交，四种状态都取得到。按钮文案同步改成「屏蔽截图」。
  - ⚠️ **交错换边的前提跟着收紧**：它把整组连封面一起挪到对侧，靠的是那边空着，而成就簇有一部分就落在对侧（`splitAchAcrossAxis`）。换边条件因此由「精简模式」改成**两个开关都开**——只开精简时对侧还站着成就。这类「A 的前提写的是 B 的实现细节」的耦合，改 B 时最容易漏。
  - **悬浮不再染底色，panel 落在指针那一格正上方**（v3.20）：原来那块 5% 灰矩形是「我指到了」的替身，而 panel 一律锚在整组中心——一天三个 ICON 时指第三格却在中间冒出来。现在底色删掉，panel 的沿轴锚点改成**那一格的中心**，位置本身就是「我指的是这一格」的回答。垂轴仍按整组最外侧内容让位，panel 不会压到它正在解释的封面和图标上。
  - ⚠️ 锚点取**格心**而不是指针的精确像素：`mouseenter` 只在跨进边界那一刻触发一次，用鼠标坐标的话，同一格从左边进和从右边进会差半格宽，panel 跟着左右跳。
  - **相机图标只在精简模式下出**（v3.20）：非精简时每一张截图都已经在轴下方的面板里铺出来了（对得上轴的进当天的日面板，对不上的进按游戏收的面板，**和图标是同一批截图**），轴上再放一个图标是同一件事说两遍，而且说得更差——图标只报张数，面板直接给图。<br>⚠️ 精简模式是**必须**的例外：那时面板全藏，图标是这批截图在轴上唯一的入口。过滤只作用在要画的那份 `units` 上，`unitsAll` 保持完整——封面「跟内容走」要按截图的启动时刻挑代表游戏，成就簇也从它数。
  - **面板里屏幕上横着一排最多 4 张**（v3.20，`SHOTS_PER_ROW_MAX`）：横排夹的是列数，竖排夹的是列内张数——同一条约束在两个方向落在不同变量上。<br>⚠️ **张数要跟着列上限一起夹**：只夹列数的话，摊平算法会把 12 张塞进 4 列（每列 3 张），而每列叠几张是垂轴空间定死的，`perColumn = 2` 时第 3 张直接顶出面板，且**溢出是静默的**。
  - ⚠️ **刻度粒度必须算在稀疏段标签之前**：那行「起 — 止」的文案也跟着这个粒度走，原来算在后面，等于用上一帧的粒度写这一帧的字。这条错得**没有声音**——`currentSpec` 有初值 `{month, 1}`，第一帧不报错，只是一律按月粒度写（该写 `SEP 12 — OCT 03` 的写成 `SEP — OCT`），之后每帧慢一拍。**有初值反而让它更难被发现**。
  - ⚠️ `TICK_MIN_SPACING`（横 86 / 竖 26）不能因为次刻度不写字了就调小：**稀疏段的聚合标签还在用同一个粒度写字**。
  - 遗留：末段整段落在稀疏段里时仍可能一枚次刻度都没有。默认这一屏因为 9 月 1 日恰好是主刻度而有 `2026.09`，那是数据碰巧。
- **横版头图当悬浮 panel 的底**（v3.19）：游戏形态的封面轮播里只留竖版海报，横版头图（460×215）改铺成整块面板的底（`cover` 居中 + `blur(6px)` + `rgba(255,255,255,.86)` 洗白）。两张图说的是同一件事，并排摆两张是把「同一件事说两遍」做成了一个可以滚的控件；横图塞进 96×144 的竖框里两边全被裁掉。只剩一张时圆点自动不出。洗白的 `.86` 与整页背景的 `.88` 同一套算法，**调低即作废 05§3.4 的验算**。详见 07§4.8。
  - ⚠️ 铺图只能写 `style.backgroundImage`，**不能写 `background` 简写**：简写会把样式表里的 `background-size: cover` / `position: center` 一并重置成 `auto` / `0% 0%`，而且写在行内盖不回来（同成就图标那次「只显示左上四分之一」）。
- **整页背景按素材比例选铺法**（v3.19）：`max(素材比/视口比, 视口比/素材比) > 1.5` 时用 `contain`，否则 `cover`。一张 600×900 的竖封面 `cover` 进 1440×900 要放大 **2.64 倍**，看得见的只剩正中 **42%**——`background-position` 实测就是 `50% 50%`，**几何上居中，看上去完全不是**。`contain` 时四周铺同一张图的 `blur(30px)` 版本，主题色只做兜底（主题色那版会把整页染成粉红）。视口比例会变，`resize` 要重算。详见 05§3.1。
- **截图设成页面背景时曾铺出一块纯色**（v3.19 修 bug）：素材的 `background` 只是**底色**，真图在 `image` 字段里（截图的底色就是一层主题色渐变，真图交给灯箱预载才分得清「挂了」和「还在路上」）。而「设为页面背景」只把 `background` 带走了，于是钉上去的是一块渐变色，一个像素的截图都没有，且不报错。改为把 `image` / `aspect` / `tint` 一并带进偏好。**老偏好没有这几个字段，按原样铺、不退化**，用户下次再点一次「设为页面背景」自动升级。
- **全景导航条删掉文字图例**（v3.19）：图例和年号地标钉在**同一条边**上——横排下图例在右上沿、年号也在上沿，domain 右端那个年号必然被压住；竖排下图例在左下角，正好盖住最后一段柱子。而「哪段是什么」悬停读数本来就逐项报了（「年.月 · 事件 N · 截图 M · 有首玩」），删掉不丢信息。详见 07§4.2a。
- **轴末端标「TODAY」**（v3.9）：与起点标同构（跨轴线的端帽 + 落在轴线延长线上的标签），只是换 accent 色、排向末端。此前轴上根本没有「今天」——只有当某枚刻度**恰好落在今天那一天**时那枚刻度才染成 accent，而刻度按月 / 按周落，绝大多数时候今天不在刻度上；而默认视窗就停在这一端。同时给尾段一个像素下限 `END_LEAD`（原来只有起点有 `START_LEAD`）：尾段本是「今天之后 10 天」，缩到最疏的一档只剩十几 px，轴线到今天戛然而止，读起来像被截断。落在今天的那枚刻度不再单独画，否则同一件事说两遍。
- **轴起点标 `START`**（v1.8，v3.17 同形）：口径是**轴上最早的一条记录**，不是 Steam 账号创建日（后端没取 `timecreated`），口径写在 `title` 里。文案与排版跟 `TODAY` 标逐项对齐（记号体、同字号字距、同间隙），只有颜色不同——accent 是「今天」的专属色。牌子挂在起点之前的留白里，留白由 `segment.minPx` 预留。
- **两端的标按「相邻那一组的内容边缘」让位**（v3.17）：两枚标都**横跨轴线**，而封面在轴一侧、截图面板在另一侧，没有「挪到对面」这条退路，只能沿轴退到整组之外。预留 = 标签长度 + 相邻那组的 `groupFootprint / 2`，三处都要（头段 / 今天之前那段 / 尾段）。原来只让 12px，竖排下第一组的封面盖住起点标、最后一组的截图面板盖住 TODAY 标。距离由坐标层的 `minPx` 保证，渲染层按同一条边缘落点只是安全网。
- **截图 / 封面点开看原图**（v1.7 修 bug）：灯箱用 `new Image()` 预载并显式给出「正在加载原图… / 原图加载失败」。**大图地址不能按字段名信任 `url`**——后端曾把 `…/filedetails/?id=…` 这个网页地址塞进图片字段，当 `background-image` 加载时浏览器不报错、只画一片空白，表现就是「点开看不到图」。实测 332 张里 150 张中招。取图改按长相判断（`lib/media.js`），后端写入侧同时修掉。
- **全景导航条加厚 + 可关**（v1.7）：柱分「事件 / 截图」两段、柱顶蓝帽标首玩、domain 短于三年时补季度细线、~~右上角图例~~（v3.19 删，见上）、悬停出游标线与读数。头部一颗图标钮控制显隐，偏好存 localStorage。
- **已发售愿望单游戏不进时间轴主体**（PRD F-2）。
- **同一时点内的主题色要拉开**（v1.5）：取色失败的游戏全部回退到同一个 `#6D4AE0`，同天两款游戏首玩时轴上就是两个一模一样的紫色 play 图标，看着像「同一个游戏画了两次」。按 05§3.4 的去重规则逐级降 L 拉开；只对用主题色的类型做（成就 / 首玩），购买与发售是系统固定色，不参与。
- **轴线随主体区垂直居中、截图每列张数随轴下可用高度**（v1.5）：05§1.1 的 384 与 07§4.2 的「每列 5 张」都是 **1440×900 基准下的结果**，不是常量。写死会让矮视口下的截图列捅出底栏（实测 305px 高时溢出 535px）。
- **随视口纵向实时重排**（v1.6）：窗口变高变矮时轴线跟着重新居中，截图**行数减少、列数增加**，首玩封面同步缩到整数行高。实测主体区 770 → 640 → 530 → 430：每列 5 → 4 → 3 → 3 行、最多 2 → 3 列，轴线始终居中且无溢出；回到 770 完全复位。低于 05§1.1 最小可用视口后轴线按需下压（保「看得见」不保「正中」），主体区 < 340 时导航条整条收起。实现要点（CSS 变量重排、便宜路 / 贵路分离）见 `timeline/docs/前端开发规范.md` §4b-2。

## 3. 时点悬浮 panel（范式 B，V0.1）

### 3.0a 封面是轮播（v1.3）

## 5. 首启（v1.3：三套环境并行）

首启页是**唯一的环境入口**——用户在这里选择进入哪一套数据环境，选定后整个应用（时间轴 / panel / 设置）都跑在该环境下。产品名 **Save Point** 作为标题位，走 `display/month`（05 §8）。

### 5.1 三套环境

| 环境 | 入口 | 数据来源 | 可写 | 生命周期 | 用途 |
|---|---|---|---|---|---|
| **LIVE**（生产验证） | 主按钮「登录 Steam」 | 真实后端全部接口（见 [[05_后端接口文档\|05]] §3） | 可同步 | 持久 | 真实数据、生产链路验证 |
| **MOCK**（测试模式） | 卡片按钮「进入测试模式」 | 本地 `mock-data.js`，**完全不访问网络** | 假同步 | 持久 | 交互与视觉验收、无后端时的开发 |
| **IMPORT**（v1.3） | 次入口「导入本地备份」 | 用户选的一份导出 JSON，**完全不访问网络** | **只读** | **仅本次会话** | 看别处导出的备份；不想登录时的无网路径 |

- **并行不互斥**：三者是同一套视图层 + 三个数据适配器，不是分叉代码。切换环境只改数据来源，界面行为完全一致——**MOCK 下调通的交互，到 LIVE 必须原样成立**。
- **MOCK 入口自带数据规模摘要**（`N 款游戏 · N 个时点 · N 张截图 · 起止日期`），让人一眼知道这份假数据的量级，不必进去猜。
- **`IMPORT` 不持久化**：一份几十 MB 的库塞进 `localStorage` 不稳，它只在内存里。刷新即失效——宁可让它消失，也不要出现「模式还在、数据没了」的死状态。文件形状不对就地报「导入失败：{原因}」，停在首启页。
- **当前环境常驻可见**：底栏同步状态右侧一枚 `mono/label` 徽章（`LIVE` accent 蓝 / `MOCK` 与 `IMPORT` 中性灰）。**这条是硬要求**——把测试数据或一份导入的备份误当真实数据看，是这类多环境设计最容易犯也最难发现的错。
- **环境持久化**：`LIVE` / `MOCK` 存 `localStorage`，刷新后保持；在设置页「账号」组切换（见 §4）。
- **首启页也有设置入口**：右下角同一枚浮动齿轮。**未登录时也要能进设置**——后端地址填错时，这是用户唯一的自救路径。
- **换态有转场**：登录态先淡出 220ms 再把同步态淡入，直接换 DOM 会「啪」地跳一下。

### 5.2 MOCK 模式的载入

阶段序列与 LIVE 的 `/sync` 完全一致（`owned_games → recently_played → achievements → screenshots → done`），只是**每阶段 90ms 快进**——测试模式的时间不该花在等进度条上。保留阶段序列而不是直接跳过，是为了让进度态本身也在 MOCK 下可被验收。

阶段 chip 用英文大写短名逐级点亮，与后端 SSE 的 step 一一对应，完整序列见 §5.2b。

### 5.2a LIVE 首次同步的进度呈现（v1.2 补）

真实首次同步**要跑几十分钟**（297 款实测约 22 分钟，逐款打 Store API），所以进度态必须做三件事，否则和「卡死」没有观感区别：

1. **实时计数**：消费 `/sync` SSE 的 `processed / total`，显示 `20 / 297` 并推进进度条。后端每 10 款产出一次事件（见 [[05_后端接口文档|05]] §3.2）。
2. **明说要多久**：收到 `first_run` 标记时给出「几百款的库可能需要几十分钟」的提示——不说的话，进度条动得极慢就会被当成卡住。
3. **给出口**：同一时刻给「先查看已有数据」。数据是分批入库的，先看不影响后台继续同步。
4. **活跃指示**（v1.4）：进度条斜纹持续流动 + 条尾推进头呼吸 + 右端 `ELAPSED mm:ss` 每秒走一格。这三样与「还剩多少」无关，回答的是另一个问题——**后端静默的那几分钟里，这东西还活着吗**。同步报错时三样一起停住并转灰（`.stalled`），状态改「同步中断」。取值与设计理由见 [[05_UI设计规范_游戏日历|05]] §7.1。

### 5.2b 阶段序列必须与后端逐个对齐（v1.4）

后端 `/sync` 实际推送的 step（`backend/app/services/sync_service.py`）：

```
sync → owned_games → wishlist → purchase_history → recently_played
     → achievements → screenshots → lifecycle → done
```

- **chip 只给 6 个采集阶段**：`OWNED` / `WISHLIST` / `PURCHASES` / `PLAY_DAYS` / `ACHIEVEMENTS` / `SCREENSHOTS`。`sync` 是开工信号、`lifecycle` 是秒级的本地重算、`done` 是终态，三者有中文状态文案但不占 chip——给 `lifecycle` 一个格子只会在最后闪一下。
- **少列一个阶段的后果不是「少个格子」**：收到未列入的 step 时 chip 不推进、状态文案退化成裸英文的 step 名，用户看到的是「进度条不动 + 一行看不懂的英文」——正是最像卡死的那种画面。v1.3 就踩了这个：`SYNC_STEPS` 少了三个阶段。
- **MOCK 的阶段序列必须逐个对齐 LIVE**（§5.2 的快进只改节奏不改序列），否则 MOCK 下验收过的进度态到 LIVE 会露馅。
- 只有 `owned_games` 带 `processed / total`；其余阶段只有一次 `done`。**这是当前后端的形状**，要更细的进度得先让后端在 `achievements` / `screenshots` 里也按批推 `processed / total`。在那之前，静默窗口靠上面第 4 条的活跃指示兜。

### 5.3 LIVE 模式的登录（v1.2 打通全自动回跳）

1. 点「登录 Steam」→ 前端先探一次 `/health`（后端没起就地报错，不把人跳走）→ **整页跳转**到 `GET /auth/steam/openid/login`；
2. 后端 302 到 Steam OpenID → 用户授权 → Steam 回调 `/auth/steam/openid/callback`；
3. 后端验签成功 → **302 回前端**，token 放在 URL fragment（`#token=…&user_id=…`）；
4. 前端启动时消费该 fragment：存 token、`history.replaceState` 清掉 hash、直接进同步进度态。

设计要点：

- **整页跳转，不用 `window.open`**：弹窗会被拦截器拦；在嵌入式 / CEF 浏览器里 `window.open` 还会降级成当前页导航——两种情况都会把用户丢在 Steam 页上回不来。
- **token 走 fragment 而不是 query**：fragment 不会发给服务端，不进访问日志与 Referer；前端取到后立即清掉，不留在地址栏与历史记录。
- **失败也要能回来**：取消登录 / 验签失败 / `return_to` 不匹配等，后端一律 302 回前端带 `#error=`，首启入口把原因摆出来。否则用户会被卡在后端的 JSON 错误页上，没有任何返回路径。
- 后端 `GC_FRONTEND_BASE_URL` 留空时沿用旧行为（回调直接返回 JSON），供 curl / 非浏览器客户端调试。
- 前端「已有 token」入口保留为**调试用途**（换后端地址、手工贴 token），正常登录不再需要它。

> ⚠️ **端口硬约束**：前端**不能用 8080**。Steam 客户端的 CEF 远程调试固定占用 8080（`steamwebhelper.exe --remote-debugging-port=8080`），而本项目的用户必然开着 Steam——撞端口是必然而非偶然。撞上时浏览器打开 8080 拿到的是 Steam 的调试页，症状表现为「页面打不开 / 登录按钮没反应」。前端默认端口取 **5173**，后端 CORS 默认放行该源。

### 5.4 失败降级（PRD §1.2 优雅降级）

| 失败 | 表现 |
|---|---|
| 后端不可达 | 「无法连接后端 `{地址}`（后端未启动或 CORS 未放行）」，停在首启页，按钮恢复可用。点「登录 Steam」时**先探活再跳转**，避免把人跳到一个打不开的页面 |
| Steam 登录失败 / 取消 | 后端 302 回前端带 `#error=`，首启入口显示「Steam 登录失败：{原因}」 |
| token 失效（401） | 「登录态失效，请重新登录」（同步接口同样按 401 单独给这条文案，不再笼统报 HTTP 401） |
| 同步失败 | 不把人堵在首启页：给「跳过，直接查看已有数据」——已同步过的数据仍然可看 |
| 未绑 API Key | 明示「同步会失败，可先看已有数据」，不阻断进入 |

### 5.4 记住登录状态（v1.8）

**首启页是「你是谁」的一次性问题，不该每次刷新都重问。**

| 项 | 定 |
|---|---|
| **续上条件** | localStorage 里存过环境，且 LIVE 时 token 还在（`API.hasSession()`） |
| **⚠️ 不能拿 `getMode()` 判** | 它在什么都没存过时返回 `'mock'`——那是取数适配器的默认落点，不代表用户选过。直接用它，全新用户会被静默丢进测试模式，看到一堆假数据还以为是自己的库。所以判的是 **localStorage 里到底有没有那一条记录** |
| **失败回退** | 取数失败（后端没起 / token 过期）时 `showTimeline()` 自己会带着原因退回首启，所以启动时不必先探活 |
| **IMPORT 不参与** | 它是会话内只读环境、不落盘，刷新后本来就该回到底层环境 |
| **MOCK 入口** | 由首启页**移到设置 → ACCOUNT 组**。首启页要回答的是「你是谁」，摆一张同等分量的测试模式卡片会让第一次来的人以为那是两个平级的正常选项 |
| **设置里的进出** | 不在 MOCK 时：「进入测试模式」+ 数据量副标题；在 MOCK 时：标题改成「退出测试模式」（上面账号行已经写着 MOCK，同一信息不在一屏出现两次），按钮按有没有 token 分「退出并回到 LIVE」/「去登录 Steam」 |

## 8. 状态管理与数据流

- **时间焦点**：`{range, scale}`（如「2025-06 · 月」），`scale ∈ {day, week, month}`——时间轴当前可视范围与缩放层级。
- **取数门面（v1.1，v1.3 扩到三套）**：视图层**只认一个取数入口**（`timeline/api.js`），MOCK / LIVE / IMPORT 在门面内部分流，方法名与出参形状对齐 [[05_后端接口文档|05]] §3 的端点。视图层不知道自己跑在哪套环境——这是多套环境能并行而不分叉的前提。
  - **导入 / 导出这一对必须同源**（`exportDataset()` / `setImportedDataset()`），否则导出的东西自己都读不回来。导出**不含成就明细**：逐款去拉会打上百个请求，代价远大于收益；代价是导入方的成就面板显示「当日无成就明细」。
  - **形状对齐是硬约束**：`mock-data.js` 必须逐字段照抄后端出参（`TimelineEvent` / `ScreenshotOut` / `GameOut`）。形状一旦漂移，MOCK 下调通的东西到 LIVE 就会碎。
  - ⚠️ `TimelineEvent.date` **只到「日」不含时刻**（后端如此）。panel 事件行的时间戳走 `/calendar/day/{date}` 的 `rows[].time`（当日分钟数）懒加载补齐，两套环境同一路径。
- **事件数据**：**后端一次性返回全量**（`games[]` + `events[]` + `screenshots[]`，`GET /calendar/timeline`，带 ETag），前端本地按范围 / 层级过滤。**成就明细例外**——悬浮成就簇时按时点向 `/achievements/{appid}/{date}` 懒加载（[[07_视图范式_游戏日历|07]] §4.5）。
- **同步状态**：`idle | syncing | error` + 上次同步时间戳，来自 `get_sync_status` 与 `sync_now` 的进度事件流。
- **主题色**：不做前端取色，直接消费事件返回的 `theme_color` 字段。

## 10. 取值与依赖

- 动效只服务缩放 / 浮层层级感 / 显隐存在感，`prefers-reduced-motion` 全部降为 120ms 淡入。
