> **本文件已归档，不作为当前开发依据。** 2026-09-01 起 V0.1 的唯一视图是**横向时间轴**，取值见 `07_视图范式_游戏日历.md` v2.0。
> 归档内容 = 原 07 v1.3 的 §0（为什么要有范式这一层）、§1（主体区插槽约定，基于已归档的 668×768 面板）、§2（四范式一览）、§3（范式 A 月历）、§5（范式 C 周列看板）、§6（范式 D 左历右详）、§7（切换机制与方向轴定则）。
> 配套的 UI 取值（面板 / 玻璃 / 月历栅格 / L3 日详情浮层）在 `_archive/UI/桌面壳与月历UI取值_归档.md`；范式 A 的设计画板在 `_archive/范式/canvas-范式A/`。

## 原 §0 为什么要有「范式」这一层


同一批数据（发售 / 首玩 / 成就）可以有完全不同的看法：月历看的是**某一天有什么**，看板看的是**这一周长什么样**，时间轴看的是**这十年怎么过来的**。三者不是主次关系，是同一批数据的三种投影。

但 [[05_UI设计规范_游戏日历|UI 规范]] 总则 7 是「一屏一件事」，v0.6 也因此砍掉过双视图。本文档不推翻它，而是把它**收窄一格**：

> **一屏仍然只有一件事——那件事叫「日历」。范式换的是这件事的画法，不是往一屏里塞第二件事。**

判定标准很硬：**换范式，面板尺寸不变、玻璃不变、色彩不变、字体不变、底栏不变、日详情浮层不变，只有主体区那 640 × 548 换一张画法。** 任何做不到这一点的方案都不是范式，是第二个界面，该走「全屏替换」（设置 / 首启）那条路。

## 原 §1 主体区插槽


| 项 | 定 | 说明 |
|---|---|---|
| **插槽尺寸** | **640 × 548** | 与 [[05_UI设计规范_游戏日历#1.2 栅格（重算，1px 闭合）\|05 §1.2]] 的日历网格同宽同高。范式换画法，不换盒子 |
| 插槽上方 | 月份头 62 + gap 8 + 月份条 32 + gap 12 + 星期行 20 | **范式无关**，三套范式共用同一个头。切换时头部不重绘、不跳动 |

| 范式不可改 | 面板 668 × 768、玻璃三层、§3 色彩全表、§4 字体、§5 组件、§7 动效、底栏、设置 / 首启 / 托盘 | 改这些等于换皮肤，不在本文档范围内（深色皮肤仍在 [[04_未来规划_游戏日历\|未来规划]]，未解禁） |
| **L3 日详情浮层** | 取值范式无关（05 §8.2 唯一来源），**但用不用由范式决定** | A / B / C 用它；**范式 D 不挂载它**——右栏已是详情，再弹浮层就是同一份内容出现两次（§6.6）。这是本表唯一的例外，别再开第二个 |
| 手势与按键 | **横向换范式、纵向换时间**（§7.1），四套范式一律照此实现 | 一个方向轴只承载一种语义，否则换个范式就要重学一遍操作 |
| 数据契约 | 四套范式共用 `getDayGroups` / `getDayDetail` 两个函数，**不得引入第三个数据接口** | 范式 B 也只消费时点事件 + 截图（§4.5），无例外 |
| 事件语义 | 事件类型、事件色、图标词汇（首玩 = play / 成就 = 钥匙 / 发售 = 日历）三套范式完全一致 | 换范式不需要重新学一遍图例 |
| 颜色个性化 | 仍然**只有一处**（成就 / 首玩用游戏主题色），范式不得引入第二个可变色源 | 05 总则 6 |

**时间焦点共享**：三套范式共用一个「时间焦点」（一个日期）。切换范式时焦点不丢——月历切看板 = 定位到焦点日所在周并置顶；看板切月历 = 打开焦点日所在月；切时间轴 = 焦点日居中。**切换范式永远不会把用户丢到"今天"。**

## 原 §5 范式 C · 周列看板


> 参考来源：Steam 商店「即将推出」板块的周列网格（星期为列、日期为格、封面堆叠、今日高亮、纵向跨周滚动）。
> **只借它的排布逻辑，不借它的视觉**——配色仍是本产品的浅色液态玻璃（本次决策），不引入深色 token。§5.8 逐条列了没照搬的地方和原因。

### 5.1 它凭什么存在（对应哪条用户故事）

月历的色点回答"有没有"，但回答不了"是哪款"——认出哪款游戏要多点一次浮层。看板把**封面**直接摊在格子里，一眼扫过去就知道这周碰了哪几款。它服务的是 P-7 / P-9（回看成就与首玩）与 F-1（发售提前扫到），**不新增任何用户故事**。

### 5.2 栅格（1px 闭合）

| 项 | 值 | 算式 / 说明 |
|---|---|---|
| 插槽 | **640 × 548** | 与月历网格同盒子（§1） |
| 列数 | **7**（周一 ~ 周日） | 参考图是 5 列工作日；我们必须 7 列——游玩数据周末最密 |
| 列宽 | **88**，列间 gap **4** | `88 × 7 + 4 × 6 = 640` ✓ **与月历格同宽，切换范式时列不跳** |
| 日期条 | 高 **20** | 每个日格顶部 |
| 日期条 → 卡片堆 | gap **4** | |
| 事件卡 | **80 × 120**，圆角 10 | 竖版封面 2 : 3（`80 × 1.5 = 120` ✓）；水平居中于 88 列，左右各余 4 |
| 卡间 gap | **4** | |
| 周行间 gap | **8** | |
| **周行高** | `20 + 4 + n × 120 + (n − 1) × 4` | `n` = 该周**单日最大卡数**，取值 1 ~ 3 |
| | n = 1 → **144** · n = 2 → **268** · n = 3 → **392** | |
| **整周无事件** | 行高压到 **24** | 只留 7 个日期条 + 下 4。不画空卡、不画占位（05 总则 2 禁空状态） |
| 一屏可见 | **3 整周 + 第 4 周露出 92** | `548 = 144 × 3 + 8 × 2 + 100`，剩余 100 里露出下一行的日期条与半张卡——**这就是"下面还有"的提示，不另画滚动提示** |
| 滚动条 | 4px 细条，`rgba(15,23,42,.16)` | 与 05 §8.2 行区滚动条同规格 |

### 5.3 日格

| 项 | 定 |
|---|---|
| 日期数字 | `mono/stamp` 11px，色 `--text-3`，左对齐内缩 4 |
| **每月 1 日** | 日期条写全量「9月1日」，其余日只写日数字。**月界不另画分隔线、不另加月份标签**——月份主数字已在头部，同一信息一屏不出现两次（05 总则 2） |
| **今日格** | 底 `rgba(255,255,255,.42)` + 描边 `rgba(15,23,42,.12)` + `0 6px 16px rgba(15,23,42,.14)`，圆角 12 —— **与 05 §6.5 今日格完全同值**；日期数字换 `--accent` 胶囊（高 20，圆角 999，左右 padding 7，字 `--accent-ink`） |
| 「非本月」弱化 | **本范式取消**。看板是连续周流，没有本月 / 非本月之分（05 §6.6 只适用于范式 A） |
| 悬停 | 底 `--hover`，**无位移**（05 §7） |
| 空日格 | 不画任何东西，不响应点击 |

### 5.4 事件卡

| 项 | 定 |
|---|---|
| 底图 | 游戏**竖版封面**，`object-fit: cover`，圆角 10 |
| 压边 | `inset 0 0 0 .5px rgba(15,23,42,.14)` **强制**——浅封面压在浅玻璃上会糊成一片，同 05 §3.3 色点压边的理由 |
| 无封面 | 走 05 §5「封面占位」：该游戏主题色双色渐变 + ≤ 3 字母缩写（缩写规则见 05 §8.2），字号 Space Grotesk 20 / 600。**这是主题色唯一允许的填充用法，本范式不新增第二种** |
| 事件角标 | 左上角距边各 4；**18 × 18**，圆角 6，底 `rgba(255,255,255,.82)` + `inset 0 0 0 .5px rgba(15,23,42,.14)`；内 14px 描边 SVG，色 = 事件色 |
| 图标词汇 | 首玩 = play · 成就 = 钥匙 · 发售 = 日历 —— **原样沿用 05 §8.2，不新增图标** |
| 成就簇 `×N` | 角标右侧并排，高 18 的同款白片，`mono` 9px，数字用该游戏主题色 |
| **发售卡** | 卡片底边加 **2px 满宽 `--ev-release` 条** —— 沿用 05 §6.4，发售仍是唯一需要被提前扫到的类型 |
| **卡上不写游戏名** | 封面自带标题，再写一遍就是同一信息一屏出现两次（05 总则 2）。名字在日详情浮层里 |
| 单日超过 3 个事件 | 最多 3 张卡，溢出折叠 `+N`（`mono` 9px，`--text-3`）**压在第 3 张卡右下角**，不额外占行高。沿用 05 §6.1 |
| 同日排序 | **发售置顶**（它是"当天的日程"），其余按时间戳升序（沿用 05 §8.2 行排序） |

### 5.5 交互

| 项 | 定 | 理由 |
|---|---|---|
| 打开浮层 | 点日格任意位置（含卡片）→ L3 日详情浮层 | 与月历同一个浮层，不新增第二种详情 |
| 点某张卡 | 同上，并把浮层事件行**滚动到该事件** | 点了具体一款，别让人在浮层里再找一遍 |
| 无事件日格 | **不响应点击** | 沿用 05 §8.2 |
| 纵向滚动 | 滚轮 / 触摸，跨周连续 | 看板的时间轴是纵向的 |
| 横向手势 | **不做** | 月历的横滑是"切月"，看板里横滑没有对应语义，两套手势混用只会误触 |
| 前 / 后月按钮 | 跳到上 / 下月 **1 日所在周**并置顶 | 头部控件位置不变，语义随范式改（§1） |
| 月份条 | 点某月 → 该月 1 日所在周置顶 | 同上 |
| 月份主数字 | = 可视区**中线所在周**的归属月（跨月周按该周周四所属月算，同 ISO 周归属） | 滚动时实时更新；避免跨月周在两个月之间来回跳 |
| 浮层打开时 | 主体区**不滚动**（模态） | 沿用 05 §8.2 |

### 5.6 数据：本范式唯一的新增需求

看板要**竖版封面**（Steam `library_600x900`），而现有同步只存了日详情浮层用的 46 × 62 小封面。回退链：

`library_600x900` → 该 appid 的其他 2 : 3 素材 → 横版胶囊 `capsule_616x353` **居中裁成 2 : 3** → 主题色占位（05 §5）

> ⚠️ 老游戏普遍没有 600 × 900 素材，横版裁 2 : 3 会把标题切掉，观感明显劣化。**排期前必须先抽样验证覆盖率**（见 §8 未决 ②）。若覆盖率过低，本范式的价值主张（"一眼认出是哪款"）就不成立，应当直接砍掉而不是硬上。

数据接口本身不变：仍是 `getDayGroups`，只是每个事件多带一个 `portrait_url` 字段。

### 5.7 动效

沿用 05 §7 全表。范式切换的动效见 §7.2（**220ms 横向位移 24px + 淡入**，v1.1 由「200ms 淡入无位移」改——有了左右手势之后，动效方向必须跟手势一致）。

### 5.8 没照搬参考图的五处，及原因

| 参考图 | 我们 | 原因 |
|---|---|---|
| 5 列（周一 ~ 周五） | **7 列** | 它排的是发售日（工作日），我们排的是游玩记录（周末最密） |
| 横版胶囊 460 × 215 | **竖版 80 × 120** | 面板内容宽只有 640，横版胶囊在 88 列里只有 37 高，谁都认不出来；竖版 2 : 3 在 80 宽下仍可辨 |
| 深色底压封面 | **浅色液态玻璃** | 本次决策：这是第三种**布局**，不是第三套皮肤。深色主题仍在未来规划里，未解禁 |
| 「已在愿望单中」星标横条 | **不做** | 购买意愿等级（F-3）已砍，界面上没有任何意愿表达 |
| 价格 / 折扣角标 | **不做** | 价格与市场数据不维护（F-4 / F-5，未来规划） |

## 原 §6 范式 D · 左历右详


> 参考来源：左侧一块紧凑月历、右侧当日详情的双栏版面（日期 chip + 当日卡片列表）。
> 与另外三套的区别：**它没有浮层**——详情是常驻的右栏，选日即换栏。

### 6.1 它凭什么存在

月历、看板、时间轴都靠 L3 浮层看明细：点开、看、关掉，逐日回看时这个循环要重复几十次。范式 D 把浮层摊平成常驻右栏，**左侧选日、右侧直接换内容，没有开关动作**。它服务的仍是 P-7 / P-9 / P-12（回看成就 / 首玩 / 截图），**不新增用户故事**。

### 6.2 它是分栏，但不违反「一屏一件事」

05 总则 7 明写「不做分栏」。范式 D 是分栏，所以必须给出判据：

> **右栏的内容 100% 由左栏的选中日决定，右栏没有自己的时间焦点、没有自己的导航。** 两栏是同一件事的两半（选日 + 看这天），不是两件事。
> 反例（仍然禁止）：左边日历、右边游戏库；左边日历、右边设置——**两栏各自独立导航的方案一律不是范式**。

### 6.3 栅格（1px 闭合）

| 项 | 值 | 算式 / 说明 |
|---|---|---|
| 插槽 | **640 × 548** | 与另外三套同盒子（§1） |
| **左栏** | 宽 **248** | `32 × 7 + 4 × 6 = 248` ✓ |
| 中缝 | **12** | **不画分隔线**（05 总则 2 禁非必要分隔线）；两栏靠留白与右栏行底自然分开 |
| **右栏** | 宽 **380** | `248 + 12 + 380 = 640` ✓ |
| 左栏 · 星期行 | 高 16 | 7 列同宽，`caption` 11px，色 `--text-3` |
| 左栏 · 星期行 → 网格 | gap 8 | |
| 左栏 · 日历格 | **32 × 40**，行 gap 4，固定 6 行 | 32 宽是 7 列闭合的结果；40 高留给日期数字 + 底部色条。**命中区 32 × 40 ≥ 30 × 30** ✓ |
| 左栏内容总高 | **284** | `16 + 8 + 6 × 40 + 5 × 4` |
| 左栏垂直位置 | **垂直居中**，上下各余 132 | 下方留白是刻意的，**不填东西**——填不出能对应用户故事的元素就别填（05 总则 2） |
| 右栏 · 顶部区 | **96** | **整段沿用 05 §8.2 浮层顶部区**：日期主数字 40px + 三项计数块（宽 56）。口径、隐藏规则一并沿用 |
| 右栏 · gap | 8 | |
| 右栏 · 事件行区 | **364**，可滚动 | 行 62 + gap 8 → 可见 5 行（342），余 22 露出第 6 行一角当滚动提示 |
| 右栏 · gap | 8 | |
| 右栏 · 截图条 | **72** | PRD v0.7 的当日截图缩略图条，横向滚动 |
| 右栏合计 | **548** | `96 + 8 + 364 + 8 + 72` ✓ |
| 当日无截图 | 截图条**不渲染**，行区扩到 **444** | 禁空状态（05 总则 2）；`96 + 8 + 444 = 548` ✓ |

### 6.4 左栏日历格：只表达「有没有」，不表达「是什么」

类型在右栏一目了然，左栏再画一遍色点就是同一信息一屏两次（05 总则 2）。而且 32 宽的格塞不下 3 个 6px 色点。所以：

| 状态 | 定 |
|---|---|
| 有事件 | 日期数字 `--text-1`；格**底边 2px 满宽色条**，色 `--text-3` |
| 当日含发售 | 底边色条改 `--ev-release` —— 沿用 05 §6.4，发售仍是唯一需要被提前扫到的类型 |
| 无事件 | 数字 `--text-muted`，无色条，**不响应点击**（沿用 05 §8.2） |
| **选中日** | 28 × 28 `--accent` 实心圆胶囊 + `--accent-ink` 数字（沿用 05 §4 末行的今日胶囊规格） |
| 今日（未被选中时） | 同尺寸胶囊改 **1px `--accent` 描边、底透明**，数字 `--text-1` |
| 非本月 | 数字 `--text-muted`，色条降到 45% 透明度（沿用 05 §6.6） |
| 悬停 | 底 `--hover`，无位移 |

> **选中日 = 时间焦点**（§1）。进入范式 D 时选中日 = 当前时间焦点；若该日无事件，右栏显示该日的空态？——**不**：右栏此时只渲染顶部区的日期，事件行区与截图条整块不渲染。日期本身不算空状态。

### 6.5 右栏

- **顶部区**、**事件行**（62 高，图标 · 封面 46 × 62 · 游戏名 · 等宽时间戳）、**行排序**、**计数口径**、**封面缩写**——**全部原样沿用 05 §8.2**，本文不复述、不改值。范式 D 的右栏就是把那个浮层摊平，取值必须一致，否则同一份内容在两处长得不一样。
- **截图条**：72 高，缩略图 96 × 54（16 : 9）横向滚动，gap 8，圆角 8，压边 `inset 0 0 0 .5px rgba(15,23,42,.14)`；点击放大看原图（PRD P-12）。
- **禁止出现**：价格、折扣、游戏标签、「今日上线」一类状态文案。参考版面上那三样我们**都没有对应数据**（价格属 F-4 / F-5，已在未来规划；标签未采集），照搬只会得到一排空字段。

### 6.6 范式 D 不使用 L3 日详情浮层

右栏已经是详情，再弹一个浮层就是同一份内容同时出现两次。**在范式 D 下 L3 浮层整个不挂载**，左栏点击只改选中日。这是 §1「浮层范式无关」的唯一例外，已在 §1 表中登记。

### 6.7 交互

| 项 | 定 |
|---|---|
| 选日 | 点左栏格 → 右栏 220ms 淡入换内容，**无位移**（左栏不动） |

## 原 §7 切换机制（含方向轴定则）


### 7.1 方向轴定则（v1.1 新增，跨范式，最高优先级）

> **横向换范式，纵向换时间。** 一个方向轴只承载一种语义，四套范式一律照此实现。

| 轴 | 手势 / 按键 | 语义 |
|---|---|---|
| **横向** | **← / →**（Windows）· **左右划**（移动端） | **切换范式**（循环） |
| **纵向** | **↑ / ↓** · 上下滚轮 · 上下划 | **换时间**（各范式自行解释，见下表） |

> **单一范式阶段的例外（v1.2）**：V0.1 只实施范式 B，没有第二套范式可切，**横向手势回归「时间轴自身滚动」**（边缘触发，§4.4），纵向 = 平移时间 / 换层级。等第二套范式落地时，横向才恢复「切换范式」语义。

各范式对「纵向」的解释：

| 范式 | ↑ / ↓ 做什么 |
|---|---|
| A 月历 | 切上 / 下一月 |
| C 周列看板 | **连续滚动**周流（不是分页） |
| D 左历右详 | 切上 / 下一月；右栏事件行区在自己范围内先消化滚动 |
| B 横向时间轴 | 平移时间（纵向）；缩放层级用 `Ctrl` + 滚轮 / 双指捏合。**V0.1 单一范式阶段，横向手势回归「时间轴滚动」**（§7.1 例外） |

**这条定则推翻了两处旧约定，已同步改掉**：

1. 05 §7「切换月份 = 横向位移 24px」→ 改**纵向位移 24px**（方向感要跟手势一致）。
2. 05 §8.2「浮层开着时方向键 / 横向滚轮 / 触摸滑动不切月」→ 改为**浮层开着时横向与纵向一律不响应**（既不切月也不切范式）。

### 7.2 切换器

| 项 | 定 | 理由 |
|---|---|---|
| **手势 / 按键** | ← / →（Win）· 左右划（移动端），见 §7.1 | 主入口。范式切换是「翻到同一批数据的另一种画法」，横向翻页是最贴的隐喻 |
| **显式入口** | 设置页 → 外观组 → 「视图范式」四选一 | 手势发现不了时的兜底；也是默认范式的设置处。**底栏两件套与托盘四项均不新增入口**（05 §8.1） |
| 循环顺序 | **A 月历 → C 周列看板 → D 左历右详 → B 横向时间轴 → 回 A** | 未实现 / 未启用的范式**不在环里**；V0.1 只有 A，← / → 无效果，**不做无效反馈动画**（05 总则 2） |
| 动效 | **220ms · `cubic-bezier(.32,.72,0,1)` · 横向位移 24px + 淡入**，与原切月动效同规格 | 只有主体区参与，头部与底栏不重绘 |
| 浮层开着时 | **不切换**，先收起浮层（同 05 §8.2 的模态规则）；范式 D 无浮层，不涉及 | |
| 生效 | 立即，无过场页 | |
| 持久化 | 本地设置表 `view_paradigm`，默认 `calendar` | |
| 时间焦点 | 切换时**不丢**，见 §1 | |
| 移动端 | 左右划切范式；上下划换时间。移动端整体仍属「后期验证」（PRD §6） | |

## 原 §8 未决与风险（范式 C / D 相关）


1. **密度是否够**：看板一屏只见 3 周多一点，比参考图（5 周）稀。若真数据上来觉得太稀，备选是「卡片压到 80 × 96」或「单日第 2 / 3 张压成 44 高的窄条」。**等有真数据再定，现在不预先复杂化。**
2. **竖版封面覆盖率未验**（阻塞级，见 §5.6）：覆盖率低于某个线（建议 70%）则本范式不成立，应当砍掉重想，而不是让一屏都是裁坏的横版图。
3. **范式 D 的两处代价**：① 左栏无法用方向键选日（左右已给范式切换、上下已给切月），只能点；② 右栏事件行区的滚动与切月共用纵向轴，边界处理不好会误触，已定「行区先消化、到底不穿透」。
4. **排期**：范式 A / C / D 与切换器都依赖设置页，最早跟设置页一起（PRD §6 V0.2）；范式 B 为当前实施（传统 HTML）。
