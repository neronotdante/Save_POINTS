# 游戏日历（Game_C）· 前卫设计风格调研

> 阶段：视觉设计预研（Visual Discovery）
> 版本：v0.1 ｜ 日期：2026-08-25
> 目的：为 Game_C 的界面设计收集"前卫 / 实验性"日历视觉参考，供你拍板视觉方向。
> 上游约束：见 `01_调研报告_游戏日历.md`（§2.5 月历五层信息架构、密度自适应）与 `02_PRD_游戏日历.md`（§4 页面结构、§8 开放问题）。
> 使用方式：本文档只收集「风格流派 + 可引用案例 + 与项目的契合点」，不代替正式设计方案；最终视觉方向选定后，再单开一份设计规范文档。

---

## 0. 一句话结论

**这个产品不该做"又一个漂亮的日历 App"，而应该做一台"游戏档案馆 / 时间机器"。**

主流日历（Google / Notion Calendar / Fantastical）已经挤满了"圆角 + 渐变 + 毛玻璃"的通用审美；Game_C 的差异化机会在于它的**内容**本身就带有强烈语境——**游戏、数据、编年史、时间流逝**。前卫方向的正确用法不是选一个好看的皮肤，而是选一个**和"时间"这个第一公民对话的视觉语言**。

本报告筛选出 **7 个有据可查的风格流派**（另附 1 个对照组），并为每个流派给出「与 Game_C 的契合点 / 风险 / 落地建议」，最后合成 **3 个候选视觉方向**供拍板。

---

## 1. 筛选"前卫"的标准（为什么收这些，不收那些）

为避免"前卫"沦为形容词，先立三条筛选线：

| 标准 | 说明 |
|---|---|
| **有真实可引用的案例** | 宁可案例少，也要是能点开看的真实设计作品/项目，不收纯 AI 生成的概念图（StockCake 那类霓虹日历图一概不收） |
| **对"时间"有态度** | 前卫日历不是把事件放进普通网格，而是对"时间如何被看见"有主张（螺旋、撕页、点阵、巨大数字……） |
| **能映射到本项目** | 必须能落到 Game_C 的具体约束上：双视图（月历网格 + 横向时间轴）、主从布局、色点密度编码、深色游戏语境、稀疏+尖峰数据分布 |

**明确排除**（作为反例记录，不展开）：Google Material 3 "Expressive"（[APK 拆解](https://www.androidauthority.com/google-calendar-expressive-update-3558226/)）——它本身是 2025 年的主流趋势，但仍是"圆角容器 + 彩色 pill"的通用审美，恰恰是本项目想避开的同质化方向，仅作对照组参考。

## 2. 七个风格流派

### 2.1 瑞士 / 国际主义排版风（Swiss / Editorial Typographic）★最贴合"时间是第一公民"

**视觉语言**：严格网格、Helvetica/Neue Haas 类无衬线、巨大数字当主角、非对称留白、红黑灰主色、把"数据"当排版装饰。

**可引用案例**：
- [Typodarium 2025](https://ruddigkeit.de/releases/typodariu-2025)（Raban Ruddigkeit 主编的每日字体日历，持续十几年，是"编辑式排版日历"的标杆）
- [The Gutenberg 2025](https://dribbble.com/shots/24025426-The-Gutenberg-2025)（印刷排版风的实验日历）
- [Swiss 风格海报模板](https://weandthecolor.com/swiss-graphic-design-poster-template-bold-typography) · [VISUAL ARCHIVE 网格海报](https://www.behance.net/asset/820591/VISUAL-ARCHIVE---Eclectic-Typography-and-Grid-Posters)

**与 Game_C 的契合点（强）**：
- 日历本质是**网格**，瑞士风是把网格变成主角，而不是容器背景。
- 产品原则第一条就是"**时间是第一公民**"——瑞士风里的**巨大日期数字**（"2026 / 08 / 25"铺满半屏）是对这条原则最直白的视觉翻译。
- 游戏名、时长、价格、状态这些数据字段，在编辑式排版里可以当**排版元素**（大字标题 + 小字元数据），正好绕开"封面图放不进格子"的硬约束——**排版不依赖封面图**。
- 对"稀疏"友好：大片留白在瑞士风里是优点，不是"空"。

**风险**：
- 容易显得冷、疏离，与"回顾我的游戏人生"的私人温度有张力。
- 对游戏封面资源的利用率低（但调研 §2.5 已证明格子本来放不下封面，主视图本就不该靠封面）。

**落地建议**：作为**结构骨架**——网格、排版层级、留白、字号阶梯。游戏封面作为**点缀**（详情页、右侧面板），不进入主视图的骨架。

---

### 2.2 终端 / 数据档案风（Terminal / HUD / Data Aesthetic）★最贴合"编年史 + 会话数据"

**视觉语言**：深黑底、等宽字体、括号/分隔线边框、绿/琥珀单色、扫描线、数据密度高、"档案 / 日志"感。

**可引用案例**：
- [Nostromo LV-426 日历 App](https://github.com/EdgarPachinsky/nostromo-lv-426-fun-calendar-app)（复刻《异形》电影里的计算机界面，"retro-futuristic 但先进"，是**真实可跑的项目**，交互与字体都值得扒）
- [HUD / 赛博朋克 UI Kit（ArtStation，游戏 HUD 元素）](https://www.artstation.com/marketplace/p/PB8ND/34-futuristic-game-ui-kit-sci-fi-hud-interface-elements-volo-13)
- [ScamSentry 的 Cyberpunk/HUD 报告界面（真实实现）](https://github.com/Chaitanyahoon/ScamSentry/commit/abd5ca43a72e2d78b8837af575a65afe4a122584)

**与 Game_C 的契合点（强）**：
- 本项目的数据是**会话级**的——"11月3日 20:14–23:47 玩了 3 小时 33 分"，这种**起止时间 + 时长**正是等宽字体排版最擅长表达的内容（时间戳像日志、像存档）。
- 产品定位是"**编年史**"，终端/档案美学天然呼应"翻自己的存档记录"。
- **四级精度标注**（`exact / inferred / daily / manual`）需要一个诚实的视觉语言——终端风可以用不同的标记/括号/角标把"这是推算的"标得很清楚，比通用日历的图标更贴切。
- 深色 + 单色底色，能**最大化游戏封面的色彩作为唯一彩色焦点**（黑白档案里只有封面是有颜色的）。

**风险**：
- 可读性风险：等宽字体 + 高密度在长文本下会累；需要克制。
- "主题公园感"：做过头就像在玩一个"黑客模拟器"皮肤，反而廉价。
- 与"未来购买规划"（轻松、决策辅助）的情绪有张力——档案感更适合"过去"那一半。

**落地建议**：作为**数据层/细节层的视觉语言**——会话条目、时间戳、精度标注、价格/时长等**数字**字段用等宽字体 + 档案式排版。骨架与导航仍用普通无衬线，避免全局等宽造成阅读负担。

---

### 2.3 新粗野主义（Neo-brutalism）★最贴合"游戏/街机"语境与色点编码

**视觉语言**：粗黑边框、**无模糊的硬投影**（offset shadow）、高饱和原色、小圆角甚至直角、故意"未打磨"、高对比。

**可引用案例**：
- [ekmas/neobrutalism-components](https://deepwiki.com/ekmas/neobrutalism-components/2.4-data-display-components)（可复用的新粗野主义组件库，直接有 data-display 组件）
- [Bruddle — Neo-brutalism UI Kit for SaaS](https://www.whiteui.store/bruddle?ref=producthunt)
- [Neo Brutalism 探索（Dribbble）](https://dribbble.com/shots/25699089-Neo-Brutalism-Youtube-Exploration)

**与 Game_C 的契合点（强）**：
- **游戏语境**天然欢迎这种审美——它带着街机、像素、独立游戏的"糙"劲，是三个方向里**最"游戏"**的一个。
- 调研 §2.5 已经定了**色点编码事件类型**（发售/购买/首玩/通关分色）。新粗野主义里，这些色点可以直接升级为**高饱和硬色块**，辨识度极高，且和粗边框、硬投影形成统一语言。
- 硬投影 + 粗边框在**深色背景**上表现力极强，和游戏封面（Steam 封面多为高饱和插画）不打架。
- 状态机（想买/已有/在玩/玩完/弃坑）的五个状态，可以用五个高饱和色做成标签，符合粗野主义的直给气质。

**风险**：
- 长文本可读性：硬投影 + 高对比在右侧面板大段文字（短评、描述）下会疲劳。
- 情绪张力：粗野主义的"糙"与"回顾往昔"的柔软情绪有冲突——它更适合"现在我要买什么"的决策界面，而不是"2019 年我沉迷《只狼》"的怀旧页面。
- 是 2023–2025 的阶段性潮流，有"过时"风险。

**落地建议**：作为**事件系统 + 状态标签 + 交互反馈**的视觉语言（按钮、chip、事件色块、选中态）。大面积文本区（面板、详情）回归中性底色。

---

### 2.4 玻璃拟态（Glassmorphism）——主要价值在"借色"

**视觉语言**：毛玻璃背景模糊、半透明卡片、柔和光晕、大圆角、渐变。

**可引用案例**：
- [Moments in Motion（Glassmorphism 日历，真实项目）](https://github.com/SwamiTheDev/Moments_in_Motion)
- [NeoTokyo Glitch Glassmorphism UI Kit](https://www.artstation.com/marketplace/p/6eWAq/neotokyo-glitch-glassmorphism-ui-starter-pack)

**与 Game_C 的契合点（中，且已被主流化）**：
- 它**不是**一个独立的"前卫方向"（已被 Apple 系广泛采用而主流化），但它贡献了一个本项目特别该学的技巧——**借色**：卡片半透明 + 背后放游戏封面的模糊图，让**每个游戏卡片拥有自己的主色**，识别度靠色彩而非图标。
- 这与调研 §2.5.7 里"封面主色做格子背景（评估过但不采用）"的结论需要重新平衡——当时否掉的是**把主色铺满格子**（会和事件类型色打架），但**玻璃借色**可以只用在 L2 右侧面板 / L3 详情页，不与 L0 格子的事件色冲突。

**风险**：
- `backdrop-filter` 在 Tauri WebView 上的**性能开销**（尤其 Windows 端）需要实测；大量模糊层会拖慢月历滚动。
- Windows 上的原生观感打折（不如 macOS 通透）。

**落地建议**：作为**面板/详情页的局部材质**，不作为全局骨架。核心采纳它"借色"的思路，而非"毛玻璃"本身。

---

### 2.5 点阵 / 单色档案风（Nothing 式 Monochrome Dot-matrix）★最大胆，且与既有设计决策共振

**视觉语言**：纯黑白灰、点阵字体（dot-matrix）、工业感、极简、像素化、信息全靠字号与灰度层级。

**可引用案例**：
- [Nothing Calendar UI Concept（Figma）](https://www.figma.com/community/file/1342082368322781399/nothing-calendar-ui-concept) · [Nothing Calendar Concept（Dribbble）](https://dribbble.com/shots/23712614-Nothing-Calendar-Concept)
- [nothing-design-system（开源设计语言）](https://github.com/dominikmartn/nothing-design-skill) · [Day/Night Dot Progress Widget](https://nothing.community/d/53070-daynight-dot-progress-widget)

**与 Game_C 的契合点（强，且是"巧合的命中"）**：
- 调研 §2.5 已经决定了**色点编码密度**（格子内容区退化为色点 + 底边 2px 色条）。**点阵美学就是这个决策的自然延伸**——黑白灰骨架 + 彩色只留给"有事件"的点。
- "稀疏 + 尖峰"的数据分布在极简单色下是**优势**：大部分空白格子在单色下安静，尖峰日的几个彩色点反而成为视觉焦点。
- 全单色底 + 游戏封面彩色，形成最强的"**封面即唯一色彩**"的聚焦，契合"档案/编年史"气质。

**风险（最大）**：
- 信息层级全靠灰度与字号，**排版功力要求极高**，做不好就是"灰色一片、找不到重点"。
- 点阵字体的中文覆盖是硬问题——中文字形在 dot-matrix 下要么缺失、要么糊，需要找替代方案（等宽中文 / 保留普通无衬线 + 点阵只用于数字）。
- 纯黑白对色觉障碍/低对比环境不友好。

**落地建议**：作为**"最大胆"的候选方向**（见 §3 方向三）。若采纳，点阵只用于**数字与时间戳**，正文用中性无衬线。

### 2.6 复古未来 / Vaporwave / Y2K（游戏怀旧）——作为"年代主题"的加分项

**视觉语言**：霓虹渐变、铬金属字、像素、暗紫粉、扫描线、早期 GUI（Win95/PS1 菜单）。

**可引用案例**：
- [Y2K-ifier（90s 复古滤镜扩展）](https://chromewebstore.google.com/detail/y2k-ifier-90s-retro-filte/iamegjdjcfodbjajndfagnchgodppnnp#1) · [Vaporwave 风格设计](https://digitalheroesco.com/styles/vaporwave/)

**与 Game_C 的契合点（中，但用法特别）**：
- 不是全局风格，而是**"按年代换主题"**的灵感：时间轴拉到"2015 年"，那一带的视觉可以带一点当时的审美痕迹（像素、CRT 扫描线），让"我的十年游戏史"在**视觉上也有年代感**。这是真正"前卫"的产品叙事点，但也明显超出 MVP。
- 作为"年度总结"导出页的氛围可选。

**风险**：极易油腻；全局使用会牺牲可读性；工作量（年代主题系统）不小。

**落地建议**：**不进 MVP**，记为 V1.5+ 的"年代主题"彩蛋方向，先只提炼其"时间有年代感"的概念。

### 2.7 实体诗性日历（概念层启发，非 UI）——为"回顾/年度总结"注入仪式感

**视觉语言**：把"时间流逝"物化——螺旋、撕页、焚毁、手摇、每日一片。

**可引用案例**：
- [The Chrono-Shredder（每日粉碎一页的诗意时间机器日历）](https://dornob.com/time-killing-chrono-shredder-is-a-day-dicing-wall-calender/)
- [螺旋形数字日历（时间流逝的螺旋形态，Yanko Design）](https://www.yankodesign.com/2025/05/20/digital-calendar-uses-spiral-form-to-show-passage-of-time/)
- [Momentum Studio 手摇铝合金日历](https://freeyork.org/design/momentum-studio-crafts-a-timeless-ritual-with-hand-operated-calendar/)
- [NOT TODAY – Der Kalender gegen die Zeit（设计学院项目）](https://des.incom.org/project/6982)

**与 Game_C 的契合点（概念层）**：
- 这些**不是 UI**，但回答了一个本项目要面对的问题：**"时间"怎么被"看见"**。月历是网格（实用），但"回顾"页、年度总结页可以借用这些形态——比如"我的一年"用螺旋/线性年表而非表格。
- 对**横向时间轴**（vis-timeline）的视觉设计有启发：时间轴不必是冷冰冰的甘特图，可以是"一条会生长的线"。

**风险**：直接照搬会脱离可用性；只提炼"时间物化"的概念。

**落地建议**：作为**概念层 moodboard**，喂给年度总结页、时间轴视图、导出分享页的氛围设计。

### 对照组：现代多彩俏皮（Amie / Cron / Vimcal）——前卫的"反面基线"

**视觉语言**：明亮渐变、圆润、情绪化色彩、微动效、愉悦感。

**可引用案例**：
- [Amie 设计语言拆解（design-bites）](https://raw.githubusercontent.com/educlopez/design-bites/main/design-mds/amie.so/DESIGN.md) · [Amie（The Verge 报道）](https://www.theverge.com/2024/1/24/24048981/amie-calendar-app-ios-mac-web)
- [2026 日历/日程 App 深度拆解（Notion Calendar / Amie / Fantastical / Vimcal）](https://www.youngju.dev/blog/culture/2026-05-16-calendar-scheduling-apps-2026-notion-calendar-amie-fantastical-vimcal-cal-com-deep-dive.en)

**为什么收进来**：它是"前卫"的**对照系**。Amie 证明了日历可以做得"让人想打开"，但也说明这条路的尽头是**同质化**（人人都是圆角渐变）。本项目要避开它的通用审美，但**吸收它的"愉悦感"目标**——前卫不等于冷硬，最终产品仍要"让人想天天翻"。

## 3. 三个候选视觉方向（合成方案，供拍板）

> 每个方向是「骨架 + 数据语言 + 色彩系统 + 事件系统」的组合，而非单挑一个流派。方向名是临时代号，拍板后再正式命名。

### 方向一：游戏档案馆（Game Archive）★ 推荐

- **骨架**：瑞士/编辑式排版（§2.1）——巨大日期数字、严格网格、留白。
- **数据语言**：终端/档案风（§2.2）——等宽字体展示时间戳、时长、价格、精度标注。
- **色彩系统**：深黑/炭灰底 + 单一强调色（可选"档案章红"或"终端绿"），游戏封面作为唯一的彩色来源。
- **事件系统**：色点/细色条编码事件类型（沿用调研 §2.5），克制不喧宾。
- **气质**：一本"我的游戏人生"的精装档案册。
- **优点**：最贴合"编年史 + 时间是第一公民"的定位；排版不依赖封面图；对稀疏友好；前卫但不廉价。
- **风险**：偏冷，需要在"年度总结/回顾"处补温度（借 §2.7 的仪式感）。

### 方向二：街机粗野主义（Arcade Brutalism）

- **骨架**：新粗野主义（§2.3）——粗边框、硬投影、高饱和原色、直角。
- **数据语言**：普通无衬线 + 高对比，数字用粗黑大字号。
- **色彩系统**：深底 + 五个状态高饱和色（想买=蓝/已有=绿/在玩=黄/玩完=紫/弃坑=红），事件类型用硬色块。
- **事件系统**：高饱和色块 chip，选中态用硬投影凸显。
- **气质**：一台游戏街机 / 独立游戏菜单。
- **优点**：三个方向里最"游戏"、最直给、实现成本相对低（有现成组件库）。
- **风险**：长期看可能疲劳；与怀旧情绪冲突；潮流性强、可能过时。

### 方向三：点阵档案（Dot Archive）

- **骨架**：点阵/单色极简（§2.5）——黑白灰 + 工业感排版。
- **数据语言**：点阵数字 + 等宽时间戳，正文用中性无衬线（规避中文点阵缺失）。
- **色彩系统**：纯黑白灰底，**彩色只属于"有事件的日子"和游戏封面**。
- **事件系统**：彩色点 + 底边色条（完全延续调研 §2.5），黑白底让彩色点成为绝对焦点。
- **气质**：一块克制、精密的时间仪表。
- **优点**：与既有"色点密度"设计决策共振最强；最大胆、最前卫、最"档案"。
- **风险**：排版功力门槛最高；中文点阵需替代方案；对比度/无障碍需专门处理。

## 5. 可直接落地的设计原则（无论选哪个方向都成立）

从这次调研提炼出的、与方向无关的原则，可直接写进后续设计规范：

1. **日期数字是第一视觉主角**。月历的标题区、时间轴的刻度，"2026 / 08 / 25"要用排版层级而非普通文本呈现。
2. **数字/时间戳用等宽字体**。会话起止、时长、价格、精度这些"数据字段"统一等宽，与正文无衬线形成层次——这是"档案感"的最低成本实现。
3. **封面是唯一的彩色来源（主视图）**。骨架保持黑白灰或深色中性，让游戏封面、事件色点成为仅有的高饱和焦点，解决"稀疏"的注意力分配。
4. **事件类型色与游戏封面色分区**。事件类型用系统级固定色（蓝/绿/黄/紫），游戏封面用自身色彩；两者分属不同层（L0 格子 vs L2/L3 面板），不混用（呼应调研 §2.5.7 的"和事件类型色打架"结论）。
5. **精度标注要"诚实且可见"**。`inferred / daily / manual` 用不同的排版标记（如虚线边框、角标、括号）区分，不能都显示成假精确的时间戳（PRD §3 关键决策 2）。
6. **过去与未来可有两套情绪**。终端/档案感服务"过去"（回顾），更轻快的直给感服务"未来"（购买规划）——不一定要强行统一成一种情绪。
