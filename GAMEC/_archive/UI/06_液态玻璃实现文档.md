## 1. 根因（为什么透明悬浮窗不像玻璃）

- **`backdrop-filter` 在透明窗里是空转**：透明窗采样不到 Windows 桌面，`blur()` 没有可糊的内容，等于没写。
- `--panel-ref` 这个「所有前景色按它验算」的基准是有前提的——填充透明度没抬到位时，它在纯黑壁纸上只有 1.21:1，基准本身不成立。
- 结论：**要么保留「面板外真透明」放弃真模糊，要么把背景取进页面换取真模糊**——两条路线都走过，最终落在「取系统颜色」这条（§2）。

## 2. 最终路线（§17，已拍板 2026-08-27）

**弃壁纸文件，直接投射系统颜色。** 层级塌缩：

| | 旧（壁纸取样） | **新（系统颜色）** |
|---|---|---|
| L0 背景 | 壁纸位图按窗口坐标裁切 | **系统强调色派生的渐变**，与窗口位置无关 |
| L2 `backdrop-filter` | `blur(24px) saturate(160%)` | **删除** |
| L3 `backdrop-filter` | `blur(44px) saturate(180%)` | **保留**（糊页面内日历，一直有效） |
| 全窗口滤镜数 | 2 | **1** |
| 壁纸 / 颜色变更 | 30s 轮询 + 解码传图 | **`accent-color-changed` 事件，零轮询** |

颜色源：`systemPreferences.getAccentColor()`（原生 API）。注册表的 DWM `ColorizationColor` / `Colors\Background` **不用**（多进程调用 + 字节序 + 编码坑，换不来新信息）。

**派生渐变（不平涂）**——平涂会让面板读作塑料板：

```js
const lit   = mix(C, '#FFFFFF', .14);  // 迎光侧，sRGB 通道线性插值（勿用 HSL，低饱和色相不稳定）
const shade = mix(C, '#000000', .10);  // 背光侧
```
```css
.glass-l0 {
  background: radial-gradient(135% 105% at 20% -8%,
    var(--sys-lit) 0%, var(--sys-base) 52%, var(--sys-shade) 100%);
}
```

这层渐变不随窗口移动，是面板自己的光照，**不可能「漂」**。

## 3. 玻璃取值（定稿，跨路线原样有效）

| 项 | 值 | 备注 |
|---|---|---|
| 自适应填充 `--glass-alpha` | **`.45 ~ .65`** | 上限 .65 是对比度红线实测硬下界；下限对应亮色底 |
| `--glass-bezel` 光学带 | **26px** | 边缘玻璃感**唯一来源**（折射删后全靠它） |
| 边缘 | 外描边 + 1px 高光 | 高光切换条件随路线走 |
| 投影 | 三层投影 | — |
| 颗粒层 | **无**（§16 移除，不要磨砂） | 颗粒的两个职责都已不成立 |
| SVG 折射 | **已删** | 观感收益实测为零，链路对但不可辨；加回前提是放弃「面板外真透明」 |
| 对比度解耦 `--guard-*` | 保留 | 今日胶囊外环 / 色点双层压边 / 色条白上沿 |
| `--text-3` 自适应 | `[.50, .60]` | — |
| 降级 | 取色链全失败 → 固定回退色 | 面板照常可读 |

## 4. 验收口径（§17.6）

| # | 条目 | 判据 |
|---|---|---|
| 1 | 颜色投射 | 面板等效底色 = 系统色按 `--glass-alpha` 与白混合的预期值，误差 ≤ 2 灰阶（**透光率指标作废**——没有背景可透） |
| 2 | 文字对比度 | `--text-1/2/3` 在三个极端系统色（`#000000` / `#FFFFFF` / `#0078D4`）下全部 **≥ 3:1** |
| 3 | 观感 | 42 格、零报错、面板边界在三个极端色下都一眼可见 |
| 4 | 降级 | 取色失败回固定回退色，面板照常可读 |
| 5 | 帧率 | 切月稳态掉帧 0 |
| 6 | 换色跟随 | 改系统强调色后面板无需重启跟着变 |

## 5. 代价（§17.7，必须认下来）

1. **没有模糊，也没有「背后」**——面板是颜色均匀的有色玻璃，不透视桌面图案。这是与壁纸取样路线的根本区别，不可后续补。
2. **观感更接近「有色亚克力板」而非「透明玻璃」**——玻璃感全部由边缘承担。
3. 系统强调色 ≠ 壁纸主色（除非用户开了「从背景自动选取主题色」）。
4. 深色主题 + 深强调色时 `--glass-alpha` 顶到 .65，面板偏灰白——与红线约束一致，非 bug。

## 6. 施工顺序（§17.10，将来照此做）

四步，前两步一次提交：

1. 新建 `systemColor.js`：取色链 + `accent-color-changed` 转发；`preload.js` 换 `getSystemColor` / `onSystemColorChanged`。
2. `glass.js` 删壁纸映射 / canvas 采样 → `deriveGradient(base)` 写三个 CSS 变量；`styles.css` 删 L2 `backdrop-filter`；`.glass-l0` 改渲染派生渐变。
3. 删 `wallpaper.js`、几何推送 / 轮询、`make-stress-wallpapers.js`、压力壁纸资源。
4. `glass-acceptance.js` 按 §4 重写：壁纸档 → 三极端系统色档。

> 第 3 步不要提前——先让新路线在页面跑通（步骤 2 出口条件）再删旧代码，否则连对照基线都没有。
