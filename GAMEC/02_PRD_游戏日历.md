## 1. 产品定位

**一句话**：把我的游戏消费与游玩，放回一条时间线上。

**定位陈述**
> 对于**有稳定游戏消费习惯、Steam 库存超过一定规模的玩家**，
> 当他们**想决定接下来买什么、以及想回看自己这些年玩过什么**时，
> Game_C 是一个**面向多用户的游戏编年史工具**（后端存储、多端查看），
> 它**把"未来的发售计划"和"过去的游玩记录"呈现在同一条时间轴上**，
> 不同于 Backloggd 的社交列表和 Steam 愿望单的降价提醒，
> 它的核心是**时间**，而不是分类或价格。

### 1.1 要解决的三个真实问题

1. **"我到底想买什么，什么时候买"** —— 愿望单躺着 200 个游戏，没有节奏感，不知道下个月有什么值得留预算。
2. **"我这几年到底玩了什么"** —— 库里 500 个游戏，记不清哪年沉迷过什么，没有属于自己的游戏记忆。
3. **"我买的游戏值不值"** —— 花了钱没玩，或者玩了很久却记不住，缺乏对自己消费行为的反馈。

### 1.2 设计原则

- **多用户 · 服务端存储**：数据通过登录从 Steam 拉取后存在**后端**，用户以 SteamID 区分；客户端是"视图"，后端是"数据与采集"。
- **时间是第一公民**：所有数据模型都围绕"什么时候发生"组织。
- **极简**：界面只有**一条时间轴**；把复杂度压进数据层，不在界面上堆功能。
- **先 HTML 后封装**（v1.0 新增）：时间轴先用**传统 HTML**（原生 HTML/CSS/JS，浏览器直接打开）跑通，暂不做桌面客户端封装，后续再考虑封装成 Electron / Tauri。
- **颜色只有一处个性化**：成就与首次游玩事件用游戏主题色，发售用系统固定色，避免整屏花掉。
- **优雅降级**：Steam 登录态失效或接口异常时，产品仍可用（用已缓存的本地数据）；取色 API 不可用时回落本地取色，本地也失败时回落系统色。

## 3. 核心概念模型

```
Game（游戏）
  ├─ 身份：steam_appid
  ├─ 元数据：名称(中/英)、封面、开发商、发行商、发售日
  ├─ 主题色：theme_color(hex)、theme_color_source(api|local|fallback)、theme_color_at
  ├─ 封面缓存：cover_url、cover_cache_path
  ├─ 状态：wishlist | owned | played | released_wishlist(已发售归档)
  └─ 生命状态（v1.2 新增，后端每日同步后派生，P-13 / P-14）：
       launched_ever(bool)、last_active_at(最后一次运行日 / 成就 / 截图，三者取最大)
       play_days_count(运行天数，核心指标)、ach_unlocked / ach_total
       playtime_forever(分钟，GetOwnedGames；**仅供判定，不上界面**)、rtime_last_played(最后启动时间)
       lifecycle: never_launched | active | dormant | shelved
       shelved_at(封盘时点 = last_active_at；非 shelved 为 null)

PurchaseRecord（购买记录，v1.1）—— 商店购买历史页拉取，日粒度
  ├─ game_id, time_created(购买/交易日期，仅日粒度), payment_method(付款方式)
  └─ 首次购买日期 = 每游戏最早 time_created

PlayDay（运行日）—— 每日近期活跃轮询，核心指标
  ├─ game_id, date（这一天玩过该游戏）
  └─ 运行天数 = count(distinct date)

AchievementUnlock（成就解锁，历史回填）—— 需 API Key，回填过去
  ├─ game_id, achievement_id, unlocktime(精确时间戳)

Screenshot（游戏截图，v0.7 新增）—— 社区截图接口拉取，运行日补强 + 视觉素材
  ├─ game_id, shot_id, taken_at(截取时间 rtime_created / 文件名时间戳)
  ├─ url(原图)、thumbnail_url(缩略图)、privacy(公开/仅好友/私密)、caption
  └─ 按日聚簇派生 PlayDay；缩略图进日详情浮层

TimelineEvent（日历事件）—— 统一事件模型，日历据此渲染
  ├─ type: release(发售) | purchase(购买) | first_play(首次游玩) | achievement(成就簇)
  ├─ game_id, date(datetime), 备注
  └─ 渲染色：achievement 与 first_play 取 Game.theme_color；purchase / release 取系统固定色
```

> `PurchaseIntent`（购买意愿）模型随 F-3 一并移入 [[04_未来规划_游戏日历|未来规划]]，V0.1 的数据层与界面均不实现。购买时间 = **商店购买历史页**（web cookie，日粒度）；「许可证入库时间（`CMsgClientLicenseList` 的 `time_created`，TCP）」已**放弃**。

**封盘判定（P-13，后端算，V0.1 阈值写死）**：

**判据是「最后一次启动时间」`last_active_at`** —— 取 `rtime_last_played`（Steam 直接给的最后启动时间）与本地三路来源（运行日 / 成就解锁 / 截图截取）的**最大值**。

```
never_launched : 无任何 PlayDay / AchievementUnlock / Screenshot 且 playtime_forever = 0
active         : now - last_active_at <  T_quiet
dormant        : now - last_active_at >= T_quiet，但投入未达标            → 轴上不画标记
shelved        : now - last_active_at >= T_quiet 且（playtime_forever >= T_time
                 或 ach_total > 0 且 ach_unlocked / ach_total >= T_ach）
```

| 阈值 | 默认 | 依据 |
|---|---|---|
| `T_quiet`（沉寂） | **45 天** | 一个半月没启动，这一轮就算过去了；封盘不是永久判决，再启动就回 `active`（见下） |
| `T_time`（时长） | **600 分钟 = 10h** | 十小时是「玩进去了」的常见门槛 |
| `T_ach`（成就比例） | **10%** | 只看比例，不设绝对数目门槛——成就总数从 12 个到 200 个不等，绝对数会把小体量游戏一律挡在门外。无成就游戏（`ach_total = 0`）只看时长 |

- **投入两条是「或」不是「且」**：小体量独立游戏时长短但成就能刷满，沙盒 / 模拟类时长长却没成就，任一条达标即算「玩够了」。
- **状态是每次同步现算出来的，不是打上去的标签**：`lifecycle` 只由「当下的 `last_active_at` + 阈值」决定。**再次启动 → 下次同步即回 `active`，`shelved_at` 清空，轴上那道封盘帽随之消失**。所以不需要回滚滞后、不需要状态机，也不存在「反复跳变」——封盘帽表达的是「到今天为止这条线停在这里」，不是「这游戏被判死刑」。
- **代价说清楚**：45 天较短，轴上封盘帽会明显变多，很多只是「这一轮玩完了」。这是有意的——它标的是**一轮游玩的收尾**，不是永别。
- **dormant（浅尝即止）不在轴上表现**——只在数据层存在。轴上给「没玩多久就放下」的游戏打标记是价值判断，不是记录。
- 阈值 V0.1 **写死不暴露**（总则 2：没有对应功能的入口不出现），配置入口延后见 [[04_未来规划_游戏日历|未来规划]] §0c。

**数据获取方式（v0.5 起，v0.6 补充主题色，v0.7 补充截图，v1.2 补充总时长）**：

| 数据 | 来源 | 方式 |
|---|---|---|
| 愿望单 / 发售日 / 元数据 | Steam（`GetWishlist`、Store API） | 登录后拉取 |
| **每日运行记录（哪天玩过）** | `GetRecentlyPlayedGames` 每日轮询 `rtime_last_played` | **API Key，每日轮询，落 PlayDay** |
| **成就解锁时间（历史回填）** | `GetPlayerAchievements` 的 `unlocktime` | **API Key，一次性回填过去，与每日轮询互补** |
| **购买时间（v1.1 新增）** | 商店购买历史页 `/account/history/`（web cookie，日粒度） | **后端用存储的 session cookie 拉取**；appid 映射见 [[03_Steam信息获取文档\|03]] §4.1 |
| **游戏主题色** | ① 色值 API（如 SteamGridDB 等提供的主色字段）→ ② 本地缓存封面取色 → ③ 系统回退色 | 同步时计算一次并入库；离线可用，取色规范化与可读性护栏见 [[05_UI设计规范_游戏日历|UI 规范]] §3.4 |
| **游戏总时长（v1.2 新增）** | `IPlayerService/GetOwnedGames` 的 `playtime_forever` | **API Key**；**仅用于封盘判定**，不作为界面指标（「玩得久不久」仍以 P-9 运行天数为准） |
| **游戏截图（v0.7 新增）** | Steam 社区「截图」接口（`profiles/{steamid}/screenshots/`，`appid` + 截取时间 `rtime_created` / 文件名时间戳） | **公开截图可读，私密需登录**；按日聚簇派生运行日，缩略图进日详情浮层 |

> **过去 vs 未来**：成就解锁时间（`unlocktime`）回填**过去**的运行状态，每日轮询 `GetRecentlyPlayedGames` 记录**未来**的运行增量；**游戏截图截取时间（v0.7）两者兼得**——既回填过去（通常比成就更密），也记未来增量。三者互补而非二选一。
> 已移除会话级采集（`PlaySession`、`PlaytimeCursor`、`PlayPeriod`、`PriceSnapshot` 等模型）——进程监听 / `localconfig.vdf` 轮询均暂不实现。

## 4. 页面结构（极简：一条横向时间轴）

```
┌─ 主视图（唯一视图）—— 传统 HTML 单页（原生 HTML/CSS/JS，浏览器直接打开；暂不封装桌面客户端）
│
│   顶部：时间范围指示（如「2025-06 · 月」）+ 缩放层级（日 / 周 / 月）
│
│   时间轴主体：
│     ══════════════════════ 屏幕横向中心一条轴（时间线，水平居中） ══════════════════════
│     ▲ 轴上方：时点事件标记（发售 · 购买 · 首次启动 · 成就簇）
│     │        成就 / 首玩用游戏主题色，购买 / 发售用系统固定色；密集处 "+N" 折叠
│     │        已封盘的游戏在其最后活动时点的标记上方加一道「封盘帽」（P-13）
│     ▼ 轴下方：该时点的游戏截图缩略图（竖向排列，每列最多 5 张，超过 5 张增开一列）
│     ─ 交互：鼠标移到页面左 / 右边缘，微延时后时间轴向该方向滑动；坐标多尺度——稀疏段跨周、密集段精确到日
│
├─ 时点悬浮 panel：悬浮某个时点标记就地渲染（微延时 120ms）
│     游戏形态：竖版 2:3 封面 + 游戏名 / 日期 + 该时点事件行（图标 + ×N + 时间戳）
│                多款游戏时封面下出圆点分页可切换；已封盘的补「封盘」标与判定依据
│     成就形态：所属游戏（头部只出现一次）+ 成就名 + 全球解锁率
│     （底部升起的日详情浮层已降级为范式 A / C 用，V0.1 不渲染）
│
├─ 设置：账号 / 同步 / 数据（数据组含「隐藏从未启动的游戏」开关，默认开，P-14）
│
└─ 首启：未登录引导 + 登录后的同步进度态
```

- **数据层仍归档已发售的愿望单游戏**（F-2），但 V0.1 **不提供「已发售清单」界面**。
- **主视图 = 横向时间轴（范式 B）**，当前为唯一实施视图；范式 A 月历 / C 周列看板 / D 左历右详 的定义见 [[07_视图范式_游戏日历|视图范式]]，随 V0.2 评估。
- **时间轴实现形态**：先**传统 HTML**（浏览器打开、无桌面壳），跑通后再封装成桌面客户端（Electron / Tauri）；液态玻璃悬浮窗、无边框、系统托盘等桌面形态随封装一并评估（见 [[04_未来规划_游戏日历|未来规划]]）。
- **时间轴交互**：鼠标移到页面左 / 右边缘，**微延时后**触发横向滑动；**轴上方**展示时点事件（购买 / 首次启动 / 成就 / 发售等），**轴下方**展示截图（**竖向排列，每列最多 5 张，超过 5 张增开一列**，点击 / 悬浮扩展）；**坐标多尺度变化**——稀疏段跨周、密集段精确到日，尺度随数据密度自适应。
- 界面取值（颜色、事件色、组件、字体）以 [[05_UI设计规范_游戏日历|UI 设计规范]] 的通用章节为准；玻璃层 / 悬浮窗取值当前**停用**。

## 5. 当前范围

### 做（V0.1）

- Steam 账号登录（SteamKit / node-steam-user），本地安全保存登录态
- 首次同步：拉取愿望单 + 拥有的游戏 + 元数据（中文名 / 封面 / 发售日）
- 采集运行记录：**每日轮询 `GetRecentlyPlayedGames`** + **游戏截图截取时间（v0.7）**，记录"哪天玩了哪款游戏"（核心指标 = 运行天数）；成就解锁时间作回填增强
- **购买时间（v1.1）**：同步时用存储的 web session cookie 拉取购买历史页，日粒度落 `purchases`（appid 映射见 [[03_Steam信息获取文档|03]] §4.1）
- **游戏主题色**：同步时按「API 优先、本地封面取色兜底」计算并缓存，用于运行 / 游玩标记（与成就）
- **游戏截图（v0.7）**：同步时拉取截图元数据（截取时间 + 缩略图），截取时间按日聚簇进运行日
- **横向时间轴（范式 B，主视图）**：传统 HTML 实现——屏幕横向中心一条轴；**轴上方**时点事件（购买 / 首次启动 / 成就 / 发售），**轴下方**截图；鼠标移到页面左 / 右边缘触发横向滑动；无数据时段坐标精简
- **时点悬浮 panel**：悬浮时点标记 → 就地渲染（游戏形态：封面 + 事件行 + 多游戏圆点分页；成就形态：成就名 + 全球解锁率），取值见 [[07_视图范式_游戏日历|07]] §4.8；**底部升起的日详情浮层降级为范式 A / C 用**
- **封盘标记（P-13）**：玩够且长期沉寂的游戏，在其最后活动时点画封盘帽（[[07_视图范式_游戏日历|07]] §4.9）
- **隐藏从未启动的游戏（P-14）**：设置里的开关，默认开；隐藏时其购买 / 发售点一并不进轴，数据层与导出不受影响
- 已发售的愿望单游戏在数据层归档，不进时间轴主体
- 本地存储 + 一键导出 JSON 备份

### 不做（明确非目标 / 延后）

- ⏸ **桌面客户端封装（Electron / Tauri）与系统托盘**：先传统 HTML，跑通后再封装（见 [[04_未来规划_游戏日历|未来规划]]）
- ⏸ **液态玻璃悬浮窗 / 无边框透明 / 以桌面为背景的浅色玻璃**：随客户端封装一并延后
- ⏸ **范式 A 月历**：V0.1 不做，定义仍在 [[07_视图范式_游戏日历|视图范式]] §3
- ⏸ **范式 C 周列看板 / 范式 D 左历右详 / 范式切换手势**：V0.1 不做，随 V0.2 评估
- ❌ **Windows 窗口控制按钮（最小化 / 最大化 / 关闭）与独立标题栏**
- ❌ **深色主题与主题切换**
- ❌ **「已发售清单」界面及其筛选项（全部 / 必买 / 打折买）**
- ❌ **购买意愿等级（必买 / 打折买 / 观望）**及其标签与解释性文案
- ❌ 会话级采集、进程监听、`localconfig.vdf` 轮询
- ❌ 价格 / 市场数据（ITAD 历史低价、降价提醒、目标价、月度预算）
