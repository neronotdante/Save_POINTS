## 0. 设计规范（总则）

1. **基准优先**：一切取值先在 **1440 × 900 桌面浏览器视口**下成立（§1.1），再考虑拉伸。
2. **去除冗余项**：界面上的每个元素必须能回答「它服务哪个 PRD 用户故事」。答不上来的一律删除——包括装饰性图标、重复标签、**说明性文案**、「更多」入口、空状态插画、非必要的分隔线与容器。同一信息不得在一屏内出现两次。
3. **不画壳**：V0.1 是一张浏览器页面，不是桌面悬浮窗——不做透明底、不做标题栏、不做窗口按钮、不做托盘。玻璃 / 悬浮 / 托盘随 V0.2 封装再评估（取值见 `_archive/UI/`）。
4. **一条轴就是全部**：主视图只有一条时间轴，不并置第二个视图区；明细就地出 panel，不开第二屏。
5. **数字即内容**：日期、时间戳、数量、ID 一律等宽字体，不参与文案排版。
6. **颜色只有一处个性化**：只有**成就与首次游玩**用游戏主题色；发售 / 购买用系统固定色。任何新增元素不得再引入第二个可变色源（唯一例外：封面占位可用主题色双色渐变）。
7. **一屏一件事**：一屏只有「时间轴」这一件事，其余均为就地 panel 或全屏替换（设置 / 首启）。
8. **分层**：本文件 = 范式无关层（色彩 / 字体 / 组件 / 事件标记 / 动效 / 界面清单）；[[07_视图范式_游戏日历|07]] = 时间轴自身（结构 / 坐标 / 滚动 / 悬浮 panel / 封盘）。取值冲突时，通用取值以本文件为准，时间轴专有取值以 07 为准。

### 1.2 栅格：时间轴没有列栅格

- 横向位置**唯一由坐标层给出**（`lib/scale.js`，见 [[07_视图范式_游戏日历|07]] §4.3），不存在 7 列或任何固定列栅格。
- 纵向只有三条线：头部下沿 96、轴线（主体区中心）、底栏上沿。
- **截图组宽度参与时点间距**：一个时点的截图组宽 = `列数 × 96 + (列数 − 1) × 6`；**相邻时点的截图组不得重叠**，也不得越出画布左右 8px。这是坐标层的输入约束（画板 `build_timeline.py::check()` 已实现为硬校验），不是渲染层的事后补救。

### 1.3 拉伸（v1.4 重写：横向不重排，纵向重排）

**横向**：只有一条规则——**轴长跟随视口宽**，panel 宽、截图尺寸、字号一律不变。小于最小视口时整页横向滚动。

**纵向（v1.4 新增）**：主体区高度变化时页面重新排布，链条是单向的，顺序不能反：

```
主体区高 → 轴线 y（§1.1 居中 + 钳制） → 轴下剩余高 → 每列截图张数 → 列数 → 组宽 → 段最小宽 → 坐标层
```

| 项 | 规则 |
|---|---|
| **每列截图张数** | `floor((轴下剩余高 − 32 + 6) / (54 + 6))`，上限 **5**（07 §4.2 的设计值）、下限 1。变矮 = **行数减少、列数增加**——「超过就增开一列」本来就是弹性规则，把纵向溢出转成横向增列正是它的本意 |
| **首玩封面尺寸** | 锚在整数行截图上：`高 = min(114, 行数 × 54 + (行数−1) × 6)`，宽按 2:3 取整。设计值 76 × 114 恰好等于两行截图，所以两者上沿与行距永远对得齐；每列只放得下 1 行时封面同步缩到 36 × 54，**不会自己捅出下边框** |
| **列容量必须先于间距算出** | 列数决定组宽，组宽是坐标层的间距输入（§1.2）。先渲染后调整会让间距与实际宽度对不上，截图组重新重叠 |
| **不重建 DOM 的那一半** | 轴上下所有元素距轴线的偏移都是常量，故 top 一律写成 `calc(var(--axis-y) ± N)`：高度变化时只改主体区上这**一个** CSS 变量即可完成重排。只有列容量真的变了才重建 DOM（600+ 绝对定位节点，一次约 2.6s，拖窗口时每帧一发会把页面焊死） |

#### 整页背景（v1.4 新增）

任意一张截图或封面都能在灯箱里一键钉成**整页底色**，偏好存 localStorage（不跨设备），首启 / 时间轴 / 设置三个视图共享。这不是新概念——上表 `--bg-fallback` 的「兜底」、`--panel-ref` 的「浅**壁纸**上的等效底色」、§3.3 的「换成深色壁纸对比度会掉」，整套对比度体系一直是按「底下有一张壁纸」算的，v1.4 只是把它落地。

| 项 | 值 | 说明 |
|---|---|---|
| **铺法**（v1.3 新增） | 按素材比例现算：`max(素材比 / 视口比, 视口比 / 素材比) > 1.5` → `contain`，否则 `cover`。两者都 `center` | 一张 600×900 的竖版封面 `cover` 进 1440×900 的横屏要放大 **2.64 倍**，看得见的只剩原图正中那 **42%** 的高度，游戏名和主视觉全裁在框外。`background-position` 实测确实是 `50% 50%`——**几何上它居中，看上去完全不像**，因为露出来的那一条根本不是这张图的中心内容。1.5 这个档 = 「裁掉三分之一以内还算居中」：截图 16:9 进 16:10 只有 1.11，照旧 `cover` 铺满；竖封面 2.4，换 `contain`。视口比例会变，拉窗口要重算 |
| **真图走 `image` 字段**（v1.3 补） | 素材的 `background` 只是**底色**，真图在 `image` 里，两者都要带进偏好 | 截图素材的 `background` 从来就是一层主题色渐变（真图交给灯箱预载，才分得清「挂了」和「还在路上」）。只把 `background` 钉上去的那版，等于**把一张截图设成背景后铺出来是一块纯色**，一个像素的截图都没有，而且不报错 |
| **底层填充**（v1.3 新增） | `contain` 时四周不是主题色，是**同一张图 `cover` 铺满后 `blur(30px)`**，主题色只做兜底 | 播放器填黑边的老办法。主题色那版实测太抢——一张高饱和的竖封面会把整页染成粉红，而这一层的职责是「不打扰」 |
| 底图 | `blur(14px) saturate(.95)`，容器 `inset: -5%` | **重模糊是有意的**：目标是「这张图的底色铺满整页」，不是把照片贴到内容后面——后者会跟轴上每个 14px 的小图标抢注意力，也过不了 §0 规则 2。糊到只剩色场，它才是一层可读的氛围色。`inset` 负值把模糊的透明羽化推到视口外，否则四边露白 |
| 洗白层 | **`rgba(242,244,248,.88)`** | **算出来的，不是调出来的**：最坏情况（纯黑底图）等效底色 = .12 × 0 + .88 × 242 ≈ 213，`--accent` 在它上面实算 **3.07:1**，压着 §3.4 的「≥ 3:1」过线；`--text-1` 仍有 8.9:1。**再调低就直接作废 §3.4 的全部验算**，改前回来把新值的最坏情况重算一遍 |
| 固定色事件点 | 不额外补偿 | §3.3 已经承认深色壁纸下 `--ev-purchase` 之流会掉对比度，轮廓**靠那道压边**——那句话就是为这一天写的 |
| 层级 | `#page-backdrop` z-index 0，`.view` z-index 1 | 它是页面的**底**，不是浮在内容上的遮罩 |

### 3.4 游戏主题色（v0.2 新增，PRD P-11）

**用途边界**：只用于**成就**与**首次游玩**事件的色点、成就簇 `×N` 的数字色、以及日详情浮层内成就 / 首玩行的色点。**不得**用于背景填充、文字正文、按钮底、发售色条。

**取色链路（三级，逐级兜底）**

| 级 | 来源 | 说明 |
|---|---|---|
| ① API | 第三方 / 官方色值接口返回的封面主色字段 | 首选；同步时按 appid 批量取，命中即用 |
| ② 本地 | 缓存封面图本地取色 | 缩放到 64 × 64 → 丢弃 `L < 12%` 与 `L > 92%` 的像素 → 中位切分 / k-means（k = 3）→ 取覆盖率最高的簇 |
| ③ 回退 | `--ev-achieve-fallback` `#6D4AE0` | 前两级失败，或封面近乎灰度（`S < 12%`）时使用 |

**规范化（入库前必做，浅底可读性护栏）**

1. 转 HSL（或 OKLCH，等价即可），**色相 H 保持不变**——主题色的辨识度靠色相。
2. 钳制饱和度 `S → clamp(S, 35%, 85%)`：低于 35% 会退化成灰点，高于 85% 在浅底上刺眼。
3. 钳制亮度 `L → clamp(L, 32%, 50%)`。
4. 验算与 `--panel-ref` 的对比度：不足 3:1 则以 4% 为步长降低 `L`，下限 `L = 24%`；仍不足则改用回退色。
5. 结果写回 `theme_color`，并记 `theme_color_source = api | local | fallback`。

**去重（同一天多款游戏）**：当日成就簇按「成就数量」降序取前 3 个游戏各画一点，超出折叠为 `+N`（§6）。若两款游戏规范化后色相差 `< 20°`，第二个自动叠加 `L −8%` 以拉开距离；仍冲突则第二个改用回退色。

**缓存**：`theme_color` / `theme_color_source` / `theme_color_at` 与封面一起入库，**同步时算一次**，之后离线渲染直接读库，不在渲染期做取色。封面更新时才重算。

> v0.1 的 §3.4「意愿等级（必买 / 打折买 / 观望）」配色整节删除——F-3 已移入 [[04_未来规划_游戏日历|未来规划]]，界面上不再有意愿标签、解释性文案与筛选项。

> 单主题：V0.1 **只做浅色**，不做深色切换（PRD §5 明确非目标）。

## 6. 事件标记规则（v1.0 改写为时间轴口径）

> 原「88 × 88 月历格里的色点排布 / 今日格 / 非本月降 45%」条款随范式 A 归档（`_archive/范式/`）。本节现在只讲**时间轴上的时点标记**。

1. **组与 unit**：一个时点是一个**组**；组内每款游戏的每类事件是一个 **unit**。unit = 图标（14px 描边）+ 可选 `×N` + **色点 6 × 6**，图标与色点间 gap 5；组内 unit 横向间距 **12**。
2. **一个组最多画 3 个 unit**，超出折叠为 `+N`（`mono` 9px、`--text-3`、贴组右下）。展开明细走悬浮 panel（07 §4.8），panel 的封面分页上限 5 是**另一套上限**，两者不换算。
3. **引线（stem）**：组底部一条 1px 竖线连到轴线，色 `--stem`。**高度分配算法（v1.1 定案，D-3 关闭）**：默认恒为 **64**；仅当相邻组的**命中区**（组宽 + 16，07 §4.8）在水平上重叠时，右侧那组逐级抬高一档，步进 **40**（= 标记块高 32 + 呼吸 8），层级上限 4 档——取值集合固定为 **{64, 104, 144, 184}**；同一重叠簇超过 4 组时不再加高，交给第 2 条的 `+N` 折叠。原稿 64–212 的手工差值是装饰不是规则，已废弃；三档画板实测无一组冲突，故全部落在 64。现行实现是 `timeline/lib/layout.js::assignStems`（`canvas/范式B/build_timeline.py::assign_stems` 是它的来源，属上一版基线，改算法以前者为准）。
4. **同类型多事件用 `×N`**（如成就簇 `×12`），不重复画点；成就的 `×N` 数字用该游戏主题色，其余用 `--text-3`。
5. **事件色**：成就 / 首玩取游戏主题色（§3.4）；**购买用 `--ev-purchase` `#0E9E68`**；发售用 `--ev-release` `#2F6BFF`。主题色缺失时用回退色 `--ev-achieve-fallback`，**不留空点**。
6. **图标词汇**（全局一致）：首玩 = play 三角 · 成就 = 钥匙 key · 发售 = 日历 cal · **购买 = 购物车 cart**（v1.0 新增，与画板一致）。
7. **今日**（v1.0 新增，取代原「今日格」）：今日刻度线用 `--accent`、高 **7**（普通刻度高 5、色 `rgba(15,23,42,.14)`），其标签同用 `--accent`。
8. **色点压边强制**：`box-shadow: inset 0 0 0 .5px rgba(15,23,42,.14)`，浅色底**不使用外发光**。谁觉得多余想删，先回 §3.3 读那一段。
9. **悬停**：命中区底色 `--hover`，**无位移**。
10. **封盘帽**（PRD P-13）：已封盘游戏在其最后活动时点的**对应 unit 正上方 4px** 处，加宽 12 / 高 1.5 / 圆角 1 的横线，色 `--text-3`。**不是第五类事件色**——封盘是状态不是事件，不占事件色、不用主题色。画法见 [[07_视图范式_游戏日历|07]] §4.9。
11. **从未启动的游戏**（PRD P-14）：被设置里的开关隐藏时，其**购买 / 发售标记一并不渲染**，不做灰化 / 半透明。
12. **已发售的愿望单游戏不进轴**（PRD F-2）；V0.1 也没有清单界面，它们只存在于数据层。
13. **月档的 ICON 级命中区**（v1.2）：月档一个像素跨好几天，组级悬浮只能告诉你「这一簇」的日期，读不出单个事件到底哪天。所以月档在组级命中区**之内**再给每个 unit 一个 40 × 40 的圆形命中区，点击浮出只读一行日期的读数条（§5「日期读数条」、07 §4.8a）。两级命中区是**嵌套关系不是并列**——ICON 命中区是组命中区的子元素，否则指针停在 ICON 上会被判成离开组，组级悬浮会被自己打断。日 / 周档不下沉，只有组级悬浮。

## 7. 动效（v1.0 改写）

| 场景 | 规格 |
|---|---|
| **缩放换档**（日 / 周 / 月） | 150–200ms 连续插值 `pxPerDay`，新旧刻度交叉淡入淡出；以指针为锚，锚点时间不动 |
| **悬浮 panel 出现** | 指针进入命中区 **120ms 微延时**后渲染；**120ms 淡入 + `translateY(4px→0)`** |
| **悬浮 panel 消失** | 离开命中区 120ms 后消失；指针移入 panel 本身不消失 |
| **边缘滚动启动** | 指针进入边缘带后 **120–200ms 微延时**再启动 rAF 循环；离开即停 |
| **隐藏从未启动开关切换** | 120ms 淡入，前端本地重算，不重新请求 |
| 按钮按下 | 120ms · `scale(.97)` + 高光 inset 减半 |
| 悬停 | 120ms · 底色 `transparent → --hover`，**无位移** |
| 同步进度 | 宽度过渡 400ms · ease-out |
| **封面切换**（v1.2） | 轨道位移 380ms `cubic-bezier(.22,.76,.24,1)`；滚轮攒够 28px 或距上次 260ms 才走一格——触控板的惯性流不该一路狂翻 |
| **灯箱开 / 关**（v1.2） | 遮罩即时，卡片 `opacity 220ms` + `scale(.94)→1` `260ms cubic-bezier(.2,.8,.25,1)`；关闭后焦点回到触发它的封面 |
| **日期读数条**（v1.2） | `opacity 160ms` + `translateY(6px→0) 220ms cubic-bezier(.2,.8,.25,1)`；点同一个 ICON 收起，点别处 / ESC 也收起 |
| **首启换态**（v1.2） | 登录态先淡出 220ms，再把同步态淡入 250ms——直接换 DOM 会「啪」地跳一下 |
| **齿轮悬停**（v1.2） | 图标旋转 35°，500ms `cubic-bezier(.2,.8,.2,1)`；气泡 160ms 淡入 + `translateY(4px→0)` |
| **同步活跃指示**（v1.3） | 进度条斜纹 1.1s linear 向右流动 + 推进头 1.6s 呼吸；配一个每秒走一格的 `ELAPSED mm:ss` 读数 |

> 已删除（随桌面壳 / 月历归档）：切换月份的纵向位移、切换范式的横向位移、L3 浮层升起 320ms、遮罩淡入、托盘显隐。

动效只服务三件事：**缩放的连续感**、**panel 的层级感**、**显隐的存在感**。不做装饰性微动效，不做无限循环动画（唯一例外见 §7.1）。`prefers-reduced-motion` 下全部降为 120ms 淡入。

### 7.1 同步活跃指示：唯一允许的无限循环动画（v1.3）

上一句的「不做无限循环动画」有且只有这一个例外，因为它不是装饰，是**读数**。

**要解决的问题**：首次同步要跑几十分钟，而后端 `/sync` 只有 `owned_games` 阶段每 10 款推一次进度；`achievements` / `screenshots` 全程静默、只在结束时推一次 `done`。那几分钟里进度条一动不动、计数一个不变——**和卡死没有任何观感区别**。用户此刻真正想知道的不是「还剩多少」，而是「这东西还活着吗」。

**给的答案是三个与具体进度无关、但只要链路活着就一定在动的东西**：

| 信号 | 说明 |
|---|---|
| 斜纹流动 | 进度条 `fill` 内的高光条纹持续向右走 |
| 推进头呼吸 | 条尾那一小竖在明暗之间循环——`fill` 很窄时斜纹看不见，它保证「在动」始终可见 |
| `ELAPSED mm:ss` | 每秒走一格的墙钟，放在阶段 chip 那一行的右端，不新增行 |

**关键在于它们会停**：同步报错 / SSE 断开时立刻加 `.stalled`，两个循环动画停住、颜色转 `--text-3`，状态文案改「同步中断」。**一个永远在动的装饰动画什么也没说；会停的动画才是信号**——正因为它会停，它转着的时候才等于「还在拉」。

**`prefers-reduced-motion` 下**两个循环动画都关掉，此时 `ELAPSED` 的逐秒变化就是唯一的活跃证据——文字变化不是动画，不受该偏好影响，所以降级后信息不丢。

> **这不是「假进度条」**。斜纹与推进头从不谎报进度：宽度仍然严格等于真实完成度，动的只是纹理。区别于那种「没有真实进度就来回扫」的 indeterminate 条——那种做法在**有**真实进度时使用即为撒谎。

## 9. 实现约定（v1.0 改写为 timeline 单页口径）

- 全部取值落成 **CSS 自定义属性**，命名同 §3 token 名。
- **无框架、无构建、无 TS**：原生 HTML/CSS/JS + JSDoc 类型注释；ES Modules 需本地静态服务（`file://` 会被 CORS 拦），走 `http://localhost`。
- **三层分离**：`mock-data.js`（数据） → `lib/scale.js`（**唯一坐标真源**，分段线性 scale，UTC 基准） → `timeline.js`（渲染：视窗虚拟化 + 节点池）。骨架（头部 / 底栏 / panel 挂载点）与轴的渲染层分开，换数据源不动渲染层。
- **位置一律 `transform`**，不改 `left/top`；自管滚动（不用超长元素 + 原生滚动条），两套位置真源不得并存。
- **DOM + canvas 混合**：密集时点 / 刻度走 canvas（命中测试靠坐标反查），卡片 / 截图 / panel 留 DOM；启用阈值由 spike 定。
- **字体本地打包 woff2** + `font-display: swap`，**Noto Sans SC 必须子集化**（全量 > 8MB）。⚠️ 画板走的是 Google Fonts CDN，那只是设计稿，实现不得联网取字体。
- **图标**：一律内联 SVG 描边，24 视口、`stroke-width 1.8~2`、`round` 端点。禁止 emoji、禁止图标字体。
- **主题色**：同步期计算并入库（`theme_color` / `theme_color_source` / `theme_color_at`），渲染期只读；规范化与对比度验算写成纯函数并加单测（极暗 / 极亮 / 近灰度 / 荧光四类封面）。
- **禁用**：CSS scroll-driven animations（非 Baseline）、CSS anchor positioning 作主路径。可用：`popover`、`content-visibility` + `contain-intrinsic-size`、`:has()`、container queries、`overscroll-behavior: contain`。
- 需要先做的验证 spike 清单见 Project `claude/INBOX.md`（原 §9 的玻璃 / 透明窗两条随桌面壳归档）。
