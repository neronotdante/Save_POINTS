# 前端开发规范（游戏日历 Game_C · 横向时间轴 timeline/）

> 用途：指导 `timeline/` 的前端开发。取值与交互的**唯一来源**是 `../../GAMEC/05_UI设计规范_游戏日历.md`（范式无关层）与 `../../GAMEC/07_视图范式_游戏日历.md`（时间轴自身），本文只讲「怎么写代码」，不重复取值。
> 技术选型的调研过程见 `../../GAMEC/开发文档/01_客户端开发文档.md` §2A，本文是该调研落地后的编码约定。
> 与 `../../game-calendar/docs/前端开发规范.md`（旧 Electron 桌面壳规范）**不是同一套架构**：`game-calendar/` 已归档，两份规范互不适用，不要混用其中的模块写法。

---

## 1. 技术栈与边界

- **原生 HTML / CSS / JS，无框架、无构建步骤、无 TypeScript**（用 JSDoc 类型注释代替）。
- **ES Modules（`import`/`export`）+ 本地静态服务器**，不是 IIFE + `window` 挂载。
  - 原因：`<script type="module">` 在 `file://` 下会被 CORS 拦死，「双击 index.html 直开」与 ES Modules 二选一；本项目后端本就是 HTTP 服务，前端统一走 `http://localhost` 更一致（01§2A.9 方案 A）。旧 `game-calendar` 规范选 IIFE 是因为它要支持双击直开，本项目不需要这个约束。
  - 启动：`cd timeline && python serve.py`，浏览器打开 `http://localhost:5173/`。
  - ⚠️ **端口不得用 8080**：Steam 客户端的 CEF 远程调试固定占用它（`steamwebhelper.exe --remote-debugging-port=8080`），而本项目用户必然开着 Steam——撞上时打开 8080 得到的是 Steam 调试页，症状像「前端挂了 / 登录按钮没反应」。`serve.py` 已在启动前预检端口并给出这条提示。换端口要同步放行后端 `GC_CORS_ORIGINS`。
- **不采纳**（01§2A.5，出现即视为违反本规范）：React / Vue / Svelte 及任何构建链；现成时间轴库（vis-timeline / TimelineJS3 / react-calendar-timeline 等）作渲染层；CSS scroll-driven animations（`animation-timeline`）；全量 canvas / WebGL 渲染；CSS anchor positioning 作主定位路径。
- **三套数据环境并行**（MOCK / LIVE / IMPORT）：视图层只认 `api.js` 一个取数入口，环境分流发生在门面内部（见 §4a）。

## 2a. 组件化的边界（哪些该抽成 lib）

`cover.js` / `carousel.js` / `lightbox.js` 是这轮抽出来的三个，标准是同一条：**同一段行为在两处以上出现，且行为本身与业务无关**。

- 封面轮播在悬浮 panel 的两种形态里都要用，且月档读数条也复用了成就卡——抽。
- 灯箱做成**全局单例**而不是每个轮播各建一份：同一时刻只可能有一个封面被放大；每个轮播各建一个会在 DOM 里留一堆空壳，还得各自维护 `ESC` 监听。
- 反过来，「事件行」「成就行」只在 `panel.js` 内部出现，就留在 `panel.js` 里当私有函数，不进 `lib/`。

模块加载顺序在 `index.html` 里用原生 `import` 表达依赖，不需要像旧规范那样手工排 `<script>` 顺序——这是 ES Modules 相对 IIFE 的直接好处，新增模块按 `import` 图自然解析。

## 3. 模块规范（ES Module）

```js
// lib/scale.js
export function createScale(segments) { /* ... */ }
```

- 每个文件按其职责 `export` 具名函数；不使用 `export default`（具名导出便于 tree-shaking 与调用方按需引入，也方便未来切换构建工具）。
- **纯函数模块**（`lib/` 下全部文件）：不碰 DOM、不产生副作用，接收数据返回数据，可脱离浏览器在 Node 里单测。
- **渲染模块**（`timeline.js` / `panel.js` / `settings.js` / `first-run.js`）：碰 DOM 的副作用一律收敛到 `mount()` / `render(state)` 两个入口——
  - `mount()`：只执行一次，查询 DOM、绑定事件；用内部 `bound` 标志防重复调用。
  - `render(state)`：可重复调用，按状态重绘 DOM，不重复绑事件。
  - 这条生命周期约定与技术栈无关，从旧规范继承。
- 全局命名空间不需要了（ES Module 天然隔离作用域），但**跨模块共享的常量/图标/token 名必须只定义一处**（`lib/icons.js`、`styles.css` 的 `:root`），禁止在多个渲染模块里各自复制一份。

## 4. 坐标层（`lib/scale.js`）—— 全页唯一坐标真源

依据 07§4.3「变化坐标」与 01§2A「A.3 坐标层」：

- **分段线性 scale**：按数据密度把时间轴切段，每段一个 `pxPerDay`（密段展开、疏段压缩），`scale(t)` 分段累加、`scale.invert(x)` 二分反查。
- **UTC 基准**：Steam 时间戳是 unix 秒，本地时区只在格式化（如 `mono/label` 刻度文案）时套用，避免 DST 下「一天 ≠ 24h」造成坐标漂移。
- **接口形状对齐 d3**（不引入 d3 依赖，只是接口形状一致，便于将来无痛换成真 `d3-scale`）：
  ```js
  const scale = createScale(segments, pxPerDayByLevel);
  scale(timestamp)       // → x（像素）
  scale.invert(x)        // → timestamp
  scale.ticks(level)     // → 按 day/week/month 出刻度数组
  ```
- **内容宽度约束必须回灌坐标层，不得在渲染层事后推挤**（05§1.2：「截图组宽度参与时点间距…**这是坐标层的输入约束，不是渲染层的事后补救**」）。做法：由 `layout.js::minWidthsBetween()` 按相邻时点的占位宽算出每段最小像素宽，作为 `segment.minPx` 注入，`createScale` 取 `max(自然宽, minPx)`。
  > 踩过的坑：曾在渲染层加过一个「算完 x 再贪心推开」的 `resolveOverlaps`。小数据量下看着没事，157 个时点后累积推挤 12000px，`scale()` 与实际渲染位置彻底脱钩——`invert()`、缩放锚点、头部月份、初始定位全错，而且不报错。**位置真源只能有一个**。
- **职责边界**：`scale.js` 不知道 DOM、不知道渲染、不知道事件数据的业务含义，只做「数字 → 数字」的映射；密度分段判定（多密展开到「日」、多疏压缩到「跨周」的分界，渐变 vs 跳变）也在这一层完成，暴露成可调参数（分段阈值是 PRD §8 未决项，交 spike 6b 定，见 01§9），并写单测覆盖极端情况（全空区间、单点、密集簇）。

## 4a. 取数门面（`api.js`）—— 视图层唯一取数入口

三套环境并行——MOCK（本地假数据）/ LIVE（真实后端）/ IMPORT（导入的 JSON 备份，**会话内只读**，见 07§4.7），交互规格见 `../../GAMEC/开发文档/02_前端功能文档.md` §5。代码侧的三条硬约束：

1. **视图层不得直接 import `mock-data.js`，也不得直接 `fetch` 后端**——一律走 `api.js`。违反这条，两套环境立刻分叉成两份代码。
2. **`mock-data.js` 的出参形状必须逐字段对齐后端**（`backend/app/schemas/` 下的 `TimelineEvent` / `ScreenshotOut` / `GameOut` / `AchievementDetail`）。形状漂移 = MOCK 下调通的东西到 LIVE 会碎，而且碎在最难查的地方。
   - 特别注意 `TimelineEvent.date` **只到「日」不含时刻**。panel 事件行的时刻走 `getDayDetail(day)` 的 `rows[].time`（当日分钟数）补齐，两套环境同一路径——不要在 mock 里私自给事件加时刻字段。
3. **门面方法名对齐后端端点**，新增取数一律先在门面开口子：

| 门面方法 | 后端端点 |
|---|---|
| `getTimeline()` | `GET /calendar/timeline`（带 ETag，304 复用缓存） |
| `getDayDetail(day)` | `GET /calendar/day/{day}` |
| `getAchievementDetail(appid, day)` | `GET /achievements/{appid}/{day}` |
| `getSyncStatus()` | `GET /sync/status` |
| `syncNow(onProgress)` | `POST /sync`（SSE 进度流） |
| `hasApikey()` / `submitApikey(k)` / `deleteApikey()` | `GET` / `POST` / `DELETE /auth/apikey`（POST 时后端先拿 Key 查一次本人资料，无效直接 400） |
| `logout()` | `POST /auth/logout` |
| `health()` | `GET /health` |
| `loginUrl()` | `GET /auth/steam/openid/login?front=<location.origin>`（后端只认 CORS 白名单里的源，验签后按它 302 回来） |
| `mediaRequest(url)` | `GET /media/image?url=…`（导出长图专用的素材代理，见 §4d） |

不对应后端端点、纯前端的两个（导入 / 导出这一对必须同源，否则导出的东西自己都读不回来）：

| 门面方法 | 作用 |
|---|---|
| `exportDataset()` | 把当前环境的数据打成可再导入的备份（`format` / `exported_at` / `games` / `events` / `screenshots`）。**不含成就明细**——逐款去拉会打上百个请求，代价远大于收益；代价是导入方的成就面板显示「当日无成就明细」 |
| `setImportedDataset(raw)` / `exitImport()` | 载入 / 退出导入模式。形状不对直接抛 `ApiError`，把原因摆给用户看 |

**导入模式为什么不写 `localStorage`**：一份几十 MB 的库塞进 storage 不稳（配额、序列化开销都在边缘上）。它只压在持久模式之上（模块级 `importedMode` 变量），刷新即失效——宁可让它消失，也不要出现「模式还在、数据没了」的死状态。

其他约定：

- **SSE 用 `fetch` 手动解析，不用 `EventSource`**——后端要 `Authorization: Bearer`，而 `EventSource` 不能带自定义头。
- **`SYNC_STEPS` 必须与后端 `sync_service.py` 的 `yield {"step": ...}` 逐个对齐**，MOCK adapter 的假序列也要跟着对齐。
  > 踩过的坑：`SYNC_STEPS` 曾少列 `wishlist` / `purchase_history` / `lifecycle` 三个阶段。后果不是「少三个格子」——收到未列入的 step 时 chip 不推进，而 `stepLabel()` 的兜底会把裸英文 step 名直接怼到状态行上。用户在真实首次同步里看到的是「进度条不动 + 一行看不懂的英文」，正是最像卡死的画面。**这类"多列一个不痛不痒、少列一个很难看"的枚举，宁可写全**。
- **跨站跳转一律整页 `location.href`，不用 `window.open`**：弹窗会被拦截器拦；在嵌入式 / CEF 浏览器里 `window.open` 还会降级成当前页导航，两种情况都会把用户丢在外站回不来。登录回跳的 token 由 `consumeLoginCallback()` 从 URL fragment 取出并立即清 hash。
- **跳转前先探活**：跳去后端之前先 `health()`，后端没起就地报错——否则用户被跳到一个打不开的页面，看不到任何解释。
- 环境 / token / 后端地址存 `localStorage`（`gamec.timeline.mode` / `.token` / `.apiBase`），刷新后保持。
- **后端地址的默认值看页面自己从哪来**（`DEFAULT_BASE`）：由后端托管（`http://127.0.0.1:8000/`，`run.cmd` 的路径）时前后端同源，直接用 `location.origin`；用 serve.py 起在 5173 / 5174 的开发态才指回 `http://127.0.0.1:8000`。两种起法都不需要改配置。
- **API Key 有两个入口，缺一不可**：首启页在登录之后、同步之前拦一道（`renderApikeyEntry`），设置页 ACCOUNT 组一行（`apikeyRow`）负责事后更换 / 解绑。同步失败且后端回 400 时，首启页直接给「绑定 API Key」按钮——400 在 `/sync` 上只有「没 Key」一个含义，不要让用户对着「跳过」猜。
- **错误要分得清**：网络层失败（后端没起 / CORS 未放行）与 401（登录态失效）必须给不同文案——两者的处置完全不同。统一抛 `ApiError`，带 `status`。
- **`now()` 也走门面**：MOCK 用数据基准日、LIVE 用真实当前时间，否则「今日刻度」会飘到轴外。

## 4b. 哪些「取值」是常量，哪些是**规则的结果**

05/07 里的数字有两类，混淆它们会写出在基准分辨率下正常、换个视口就崩的代码：

| 文档写法 | 性质 | 正确做法 |
|---|---|---|
| 头部 96 / 底栏 34 / 截图 96×54 / 字号 | **常量**，05§1.3 明确「不随视口变化」 | 直接写死 |
| 「轴线 = **主体区垂直居中**」（05§1.1） | **规则**。384 只是 1440×900 下的结果 | 按 `body.clientHeight / 2` 现算 |
| 「每列最多 5 张，超过增开一列」（07§4.2） | **规则 + 基准上限**。5 是 900 高下刚好放得下的数 | 按轴下剩余高度现算，上限取 5 |
| 「首玩封面 76 × 114」（07§4.2） | **派生值**。114 之所以是 114，是因为它等于两行截图（54+6+54） | 由每列张数推：`高 = min(114, 行数 × 54 + (行数−1) × 6)`，宽按 2:3。写死 114 会在每列只剩 1 行时自己捅出下边框 |

> 踩过的坑：把轴线 384 和每列 5 张都当常量写死。1440×900 下一切正常（5 张 = 294px，384+32+294=710 < 770，**刚好**放得下），视口一矮就把整列截图捅出底栏——实测 305px 高时溢出 535px，且轴线本身已经在主体区外面了。
>
> 连锁关系要按顺序算：**视口高 → 轴线 y → 轴下可用高 → 每列张数 → 列数 → 组宽 → 段最小宽（`minPx`）→ scale**。列容量必须在算间距**之前**定下来，并且渲染与 `minWidthsBetween()` 用**同一个值**——否则按 5 张算间距、按 8 张渲染，截图组又会重叠回去。

### 4b-1. 几何量按「沿轴 main / 垂轴 cross」写，不按「宽 / 高」写

时间轴可以横排也可以竖排（07§4.10），而两种排法**规则完全相同**——差别只在哪个屏幕方向承载时间。所以布局层（`lib/layout.js`）里不出现「宽 / 高」这两个词：

| 术语 | 横排 | 竖排 | 归它管的东西 |
|---|---|---|---|
| **main**（沿轴） | x | y | 时点间距、组占位、截图增列、轨道长度、平移与缩放 |
| **cross**（垂轴） | y | x | 轴线位置、引线长度、每列截图张数、封面厚度 |

方向是 `lib/layout.js` 的**模块级设置**（`setOrient()`），不是每个函数的入参——整页永远只有一条轴，当参数传会让每个调用点都多带一个永远相同的值。

渲染层只做两件事：写 `--axis-c`，以及给元素写沿轴坐标。**「谁该朝哪边长」全部由 CSS 的 `#timeline-body[data-orient]` 表达**，不写第二套渲染分支。写位置时注意一个 CSS 陷阱：`calc(var(--axis-c) + -8px)` 不合法，符号得自己拼。

### 4b-2. 垂轴位置一律写成 `calc(var(--axis-c) ± N)`

上面那条连锁只在**列容量变化时**才需要重跑。轴线本身移动（视口变高变矮）时，轴上下每个元素**距轴线的偏移都是常量**——`stem + 7 + 25`、`+32`、`+32+封面高`……所以位置不要在 JS 里算成绝对像素塞进 `style.top`，而是：

```js
// 主体区上挂一个变量，一处写
els.body.style.setProperty('--axis-y', `${axisYFor(h)}px`);
// 元素只声明「我在轴上方 N」
el.style.top = `calc(var(--axis-y) - ${markOffset(stem)}px)`;
```

改一个变量 = 整页重排，零 DOM 遍历、零重建。600+ 个绝对定位节点重建一次约 2.6s，拖窗口时每帧来一发会把页面焊死；有了这条，**只有列容量真的变了**（`shotsPerColumn()` 返回值变化）才走那条贵路，其余尺寸变化全部零成本。

两个配套细节，都是踩出来的：

- **便宜路不要套 `requestAnimationFrame`**。页签被切到后台时 rAF 会被节流甚至完全不派发，回到前台就会看到布局还停在旧尺寸。写一个 CSS 变量本来就够便宜，同步做。
- **监听用 `ResizeObserver(body)`，不要只用 `window.resize`**。主体区尺寸不只被窗口大小决定（devtools 停靠、浏览器缩放、以后可能加的侧栏都会改它）。`window.resize` 仍留着兜底：容器尺寸没变但视口变了，也要重新夹 `offset`。

### 4b-3. 「静默失败」的坑

这一层里所有难查的 bug 都是同一种形状：**出错了但什么都不说**。留档已经踩过的：

1. **CSS 背景图加载失败是静默的**。`background-image: url(…)` 指向一张加载不出来的图时，浏览器既不报错也不留痕，画面上就是一片空白——和「图还在路上」完全分不清。需要能看出成败的地方（灯箱大图）必须 `new Image()` 预载，成功才铺、失败要明说。
   > **同一个坑的第二次**：`cover_portrait` 是后端按 appid 拼出来的模板地址，从没验证过——真实库 334 个里 32 个（9.6%）是 404，前端只露出底下的主题色渐变，看着就像「这些游戏没有封面」，而它们的横版图全都好好的。**别把没验证过的构造地址当数据存下去**；渲染侧也要有退路（挂了就换下一个变体），否则一次 CDN 抖动就悄悄退化成一块纯色。退路只换贴图不换尺寸——形态是坐标层算间距时的输入，这时候改它会把整条轴的间距弄错。
2. **字段名不等于字段内容**。`ScreenshotOut.url` 曾装着 `…/filedetails/?id=…` 这个网页地址；配上第 1 条，结果就是「点开截图一片空白，没有任何报错」。外部数据按**长相**判断，别按字段名信任（`lib/media.js`）。
3. **除以一个可能为 0 的尺寸**。把 pointer 事件打在一个 `hidden` 的元素上时 `getBoundingClientRect()` 全是 0，`at / size` 就是 NaN；那个 NaN 一路流进 `state.offset`，之后 `transform` 变成非法值被浏览器**忽略**（画面停在原地）、头部读数变 `NaN.NaN`、视窗框消失——控制台一声不吭。两头都要防：算比例前 `if (!(size > 0)) return`，以及在**所有位移的唯一出口**（`clampAndApplyOffset`）上兜一次 `Number.isFinite`。
4. **CSS 值里插进一个 `undefined`，整条声明会被丢掉**。`linear-gradient(135deg, rgb(…), undefined)` 是非法值，浏览器**连同同一条 `background-image` 里的真图那一层一起**忽略掉，不报错——表现是「这一批图全是空白格」，而隔壁同样的代码好好的。触发它的通常不是渲染层，而是**数据装饰漏了一条路径**：这次是截图的 `__color` 只在「按日期分桶」那条路上补过，走「按游戏归堆」的那批没补。**装饰要放在分流之前，让所有下游拿到同一份对象**；渲染层再兜一个 `|| 默认值` 作保险。
5. **函数返回的是对象，你当字符串用了**。`normalizeThemeColor()` 返回 `{color, source, usedFallback}`，把它整个塞进 CSS 变量就是 `[object Object]` —— 又一个非法值被静默丢弃、边框悄悄回落到默认灰。写进 CSS 之前**校验形状**（`/^#[0-9a-fA-F]{6}$/`），别指望调用处永远记得取 `.color`。
6. **`Math.max(1.5, NaN)` 是 NaN**。来自 localStorage 的偏好可能没存过、可能被手改坏，夹取函数不拦 NaN 的话它会一路流进 scale、轨道长度、刻度，最后整条轴什么都不画——而且没有任何一行报错。**夹取函数就是拦这个的地方**，用 `Number.isFinite` 兜底回默认值。
7. **让位距离按「中心」算，而邻居是按「边缘」占地的**：轴上每一组都以自己的时点为**中心**摊开 `groupFootprint`，所以「离时点 12px」和「离那一组 12px」差着半个身位。两端的 `START` / `TODAY` 标原来按前者算，于是第一组的封面盖住起点标、最后一组的截图面板盖住 TODAY 标——**没有报错、没有溢出、没有裁切**，就只是叠在一起，而且只在竖排下明显。
   > 为什么只在竖排下明显：这两枚标**横跨轴线**（垂轴方向居中于轴线）。轴的一侧是封面、另一侧是截图面板，横跨的东西**两边都躲不开**，没有「挪到对侧去」这条退路——而轴上别的元素都有。凡是横跨轴线的元素，让位只能沿轴算，且必须按邻居的**内容边缘**（`p ± footprint / 2`）算。
8. **`style.background =` 会把样式表里的 `background-size` / `background-position` 一起清掉**，而且是**写在行内**，之后再改 `backgroundImage` 也盖不回来。成就图标就踩了：`.ach-tile` 在样式表里写着 `background-size: cover`，占位色块却用简写写进行内 → 计算值变成 `auto` / `0% 0%`，64×64 的成就图按原尺寸铺在 32×32 的格子里、左上角对齐——页面上看到的是每张图的**左上四分之一**。一行报错都没有，图也确实「显示」了，只是显示的是一角。
   > 凡是「尺寸 / 定位写在样式表、图片由 JS 换」的元素，JS 一律只能写 `backgroundImage`。反过来，把 `center / cover` 直接写进值串里（`url(…) center / cover no-repeat, …`，封面和灯箱就是这么做的）也安全——那时简写里本来就带着它们。

9. **两类元素落在同一条线上，却各做各的防撞**：轴上的主刻度标签和稀疏段的「起 — 止」都钉在轴的同一侧、同一条基线上，抢的是同一段空间。给其中一类加了防撞、另一类没有，或者两类各排各的，重叠就是必然——实测横排 6 处。其中 5 处更隐蔽：稀疏段被压成**固定 96px**，而它的标签实测 **110px**，居中放置每边溢出 7px，**标签比它描述的那段还宽**，两个相邻稀疏段必撞。判据是「谁和谁会落在同一条线上」，不是「谁和谁是同一种元素」。

10. **写字用的粒度算在写字之后**：`currentSpec`（刻度粒度）原来算在稀疏段标签渲染**之后**，而那行字的文案正是按它拼的。它有初值 `{month, 1}`，所以第一帧不报错，只是一律按月粒度写（该写 `SEP 12 — OCT 03` 的地方写成 `SEP — OCT`），之后每一帧都用上一帧的粒度。**有初值反而让它更难被发现**——没有初值至少第一帧会炸。凡是「A 的输出被 B 用来渲染」，A 就必须排在 B 前面，哪怕 A 看起来只是个不起眼的赋值。

11. **给一个维度加上限，却忘了夹住被它装的东西**：截图面板的列数封到 4 之后，摊平算法照样把 12 张图塞进这 4 列——每列 3 张，而每列能叠几张是**垂轴空间**定死的（`perColumn`）。窗口矮到 `perColumn = 2` 时，第 3 张就顶出面板：不报错、不裁切、没有滚动条，只是看着挤。上限和容量是一对，夹了一个就必须同时夹另一个（`shown = min(count, 12, 4 × perColumn)`），并且把算出来的 `shown` **交给渲染侧用同一个数**——模型按 8 张算格子、渲染按 12 张摆图，是同一个错的另一半。

### 4b-3b. 同一个算法不要在前后端各写一遍

一度在前端用 canvas 复制了后端的封面取色（中位切分那一套），想补上后端取不到色的那 12%。结论是**不该做**：

- 同一套算法、同一张图，**前端算不出更好的结果**——它只是把后端的失败原样重演一遍；
- 却引入了后端没有的失败模式：Steam CDN 有约 3% 的封面 URL 是 404（`cover_portrait` 是按模板拼的、没验证过资源存在），带 `crossOrigin` 请求 404 会被浏览器报成 CORS 错误，控制台刷一屏——**而干净的控制台是发现真问题的手段**；
- 真正的修法在后端：把近灰度门槛从 12% 放宽到 5%（`normalize_color` 本就把饱和度钳到 35~85%，那道门槛只该判「有没有色相」），27 张里救回 19 张，还能落库、让图标和占位一起受益。

**判断准则**：前端补位只在它**拿得到后端拿不到的信息**时才成立（比如视口尺寸、用户偏好）。同样的输入跑同样的算法，就该放在能持久化的那一端。

### 4b-4. 类名在 CSS 里没有作用域

导航条的图例色块一度也叫 `.shot`，跟轴下方那个 96×54 的缩略图撞名，把它的圆角、压边、`cursor: zoom-in` 一并继承了过来。同名类不会报错，只会悄悄变形。新加装饰性小元素时，类名带上它所属组件的前缀（`.ov-*`）。

## 4c. 命中层必须盖在标记层之上

`.hit-region` 与 `.event-group` 是兄弟节点，且**两者都因 `transform` 各自形成 stacking context**。不给 `.hit-region` 一个 z-index，DOM 里靠后的 `.event-group`（图标层）就会整个压住命中层：鼠标停在图标本身上时 `mouseenter` 根本不触发，只有落在图标之间的空隙才有反应。**unit 越多、图标覆盖越宽、能触发的空隙越少**——症状是「三个 ICON 的时点 hover 不响应」，而单 ICON 的时点一切正常，很容易被当成偶发。

同理，月档下沉到单 ICON 的 `.df-hit` 按钮，宽度不能写死 40px：ICON 中心间距只有 26~42px（unit 宽 14/30 + gap 12），固定 40px 会让相邻按钮互相压住约 6px，瞄准左边那个的右缘实际命中右边那个。**按相邻中心间距取 `min`**，让它们恰好不重叠。

## 4d. 导出长图（`lib/raster.js` + `export.js`）

把**整条轴**拍成一张 PNG。入口在头部工具条的下载图标，面板里只有两个选项（方向、倍率），
其余一切沿用主页面——这是这个功能的第一条规矩。

**口径不另立一套**：轴上有什么由 `buildGroups()` 决定，而它读的是「隐藏从未启动 / 隐藏成就 /
精简模式」三个主页面开关；轴有多长由 `state.pxPerDay` 决定。导出**不复制这些判断**，
它只是把主体区那块视口撑到轨道全长再照一张相（`timeline.js::captureLongImage`）。
面板上那行「沿用主页面的过滤规则：…」是把这件事写在脸上，不是装饰：用户可能刚关掉成就，
不说清楚就会以为导出漏了内容。方向是唯一在导出时才定的东西，选完**同步应用到主页面**——
所见即所得，不留「屏幕上是横的、导出来是竖的」这种对不上的状态。

**为什么不自己用 canvas 画**：那等于把 styles.css 的每条规则在 JS 里再实现一遍，两份实现
从第二天起就分叉。这里走 `<svg><foreignObject>` 把已经排好版的 DOM 交给浏览器自己光栅。
（这不违反 §1「不采纳全量 canvas / WebGL 渲染」——那条约束的是**主渲染路径**。）

四个坑写在 `lib/raster.js` 的文件头，改这块之前先读那一段，这里只列结论：

1. **SVG image 里没有网络**：`url(https://…)` 一律不加载、也不报错，所以每张真图都要先
   fetch 回来转成 data: URI（并按它在成图上的实际占位缩小，否则内存要翻几番）。
2. **装 DOM 的那张 SVG 只能用 data: URI**：Chrome 把 `blob:` 来的 SVG image 判成非同源，
   画进画布就污染，`toBlob` 抛 SecurityError——而且是在整条流程跑完之后才炸。
   位图走 `blob:` 没问题，只有 SVG 这一处不行。
3. **画布尺寸上限是静默的**：超限时 Chrome 把 `canvas.width` 悄悄改成 0，表现为「导出成功
   但图是全白的」。所以 `allocCanvas` 画一个像素再读回来验证，`fitScale` 据此自动降倍率；
   长边也按 `SLICE_PX` 切片，一片一片画到同一张画布上。
4. **成就图标那个图床不给 CORS 头**：`steamcdn-a.akamaihd.net` 的
   `/steamcommunity/public/images/apps/…` 没有 `Access-Control-Allow-Origin`，前端取不回来
   （封面与截图那两个域给了，能直接取）。成就是轴上数量最大的一类事件，少了它们整张图
   就是几千个纯色方块，所以后端开了一条只读、只走白名单、只回图片的
   `GET /media/image`（`backend/app/api/media.py`），前端通过 `api.js::mediaRequest` 走它。
   MOCK / IMPORT 环境没有后端会话，`mediaRequest` 返回 null，取不回来的贴图退回主题色占位，
   面板会把「几张没取回来」如实说出来。

**懒加载要先补齐**：轴上的成就图标平时只拉视窗附近那几组（§07 4.5）。导出要的是整条轴，
所以 `captureLongImage` 会先把全部 `g.__fill()` 跑完再开拍——这是导出比截屏慢的唯一原因，
也是为什么面板上必须有进度。真实库（1139 个时点 / 3834 张贴图 / 8.5 万像素长）实测约 3 分钟。

**按年份导出（清晰度的正解）**：整条轴的根本矛盾是画布上限——十年的库 8～9 万像素长，
只能整体压到 0.7× 出图，全糊。面板的「范围」一栏可以改成「按年份」：选一个起始年，
连着导 1 年或 2 年（上限 `timeline.js::EXPORT_MAX_YEARS`，按真实库密度估的：最密的年份
一年约 1.5 万 px，两年 × 2 倍率刚好压着 65 535 的上限；再多一年 2× 就又要降档）。
实现上**不重排、不重建**：仍然克隆整条轨道，只是（1）`yearRange()` 把年份折成沿轴像素区间，
两侧各留 `YEAR_CROP_PAD` 免得把居中钉在刻度上的年份标签切成两半；（2）把区间外的轨道子节点
从克隆体里摘掉——不摘也画得对，但序列化 / 光栅 / 贴图内联都按克隆体体量付费，摘掉之后
范围外那几千张成就图标也就不用取了；（3）交给 `nodeToPng` 的 `crop` 只画这一段。
成就明细的懒加载补齐也只补范围内的组。文件名带年份（`…-h-2024-2025.png`），逐年导不会互相覆盖。

## 5. 渲染层（`timeline.js` / `panel.js`）职责边界

- **虚拟化：尚未启用，且不要提前做**。当前 mock 是个位数到百量级的时点，全量建 DOM 毫无压力。启用阈值定为「单屏可见时点 > 300 或全量事件 > 3k」，到点了再做「只渲染 `[视窗 − 1屏, 视窗 + 1屏]` + 节点池按事件 id 复用」。写在这里是为了到时候有据可依，不是现在就该有的东西。
- **位置一律 `transform: translate3d(x, 0, 0)`**，不改 `left/top`；**自管滚动**，不用原生 `overflow-x: auto`（变化坐标下滚动距离 ≠ 时间距离，原生滚动条要反算位置，缩放时还要重算 `scrollLeft`）——两套位置真源不得并存，选一套到底。
- **DOM + canvas 混合：同上，尚未启用**。到阈值后轴上密集时点 / 刻度改用 `<canvas>` 绘制（命中测试靠坐标反查，不建 DOM）；卡片 / 截图 / panel 始终是 DOM（01§2A.4 第4条、A.6 spike 6a）。
- **边缘滚动**：指针进入左/右边缘带（64px，05§1.1）后 `setTimeout` 120–200ms 再启动 rAF 循环；速度为距边缘距离的函数；离开边缘带/`pointerleave` 立停；`visibilitychange` 隐藏时暂停循环。
- **同步活跃指示的循环动画走 CSS，计时器走 `setInterval` 不走 rAF**（05§7.1）。rAF 在页面不绘制时会被节流甚至暂停——用户切到别的标签页等同步跑完，回来看到 `ELAPSED` 停在几分钟前，反倒坐实了「卡住了」。`setInterval` 在后台仍会推进（节流到 1s 级正好够用）。
  > 同理，`.stalled` 只在**同步真的报错**时加，不做「N 秒没收到事件就判定卡住」的启发式——`achievements` 阶段本来就会静默好几分钟，那样会稳定误报。
- **缩放换档（日/周/月）**：只改 `pxPerDay` 与刻度粒度，不重建 DOM；以指针为锚——先 `scale.invert(x_pointer)` 取锚点时间，改档后用新 `scale(t_anchor)` 反解 offset，保证锚点时间不漂移；档位间 150–200ms 连续插值，新旧刻度交叉淡入淡出。
- **命中测试**：时点组的命中区（07§4.8：高44、宽=组宽+16、圆角14）用于触发悬浮 panel；封面/截图等 DOM 元素走原生事件。canvas 路径启用后，密集时点走坐标反查（记录每个时点组的包围盒，指针位置二分/遍历查找落在哪个组内）。
- **月档的 ICON 级命中区必须是组命中区的子元素**（07§4.8a）。做成兄弟节点看起来一样，但指针从组命中区移到 ICON 上时会触发组的 `mouseleave`——组级悬浮 panel 会被自己叠上去的按钮打断，表现为「悬浮到图标上 panel 就闪没了」。父子关系下 `mouseleave` 不会因为进入后代而触发。
- **浮层的锚点坐标必须换算到它所在的坐标系**。`#panel-root` 挂在 `#timeline-body` 上（**不随轨道平移**），而时点的 `x` 是**轨道坐标**；直接拿 `x` 定位 panel，在 `offsetX = 0` 时看着对，一滚就整块飘到屏幕外。规则：给 body 层的浮层传 `x - state.offsetX`，给轨道内的浮层（月档读数条）传原始 `x`。
  > 同理，panel 还要做左右夹取（`[8, 视宽 − 320 − 8]`）——轴滚到两端时时点本身就贴边，不夹一下 panel 会被切掉一半。
- **锚在时点上的浮层，轴一动就收掉**（`Panel.hideImmediately()` + 关读数条）：滚轮、边缘滚动、前后按钮三个入口都要收。它们指向的是某个具体时点，轴移走之后留在原地只会指错。

## 6. 样式与取值

- 所有取值落成 **CSS 自定义属性**，命名与 05§3 完全一致，不改名、不加前缀：`--accent`、`--text-1/2/3`、`--ev-release/purchase/achieve-fallback`、`--axis`、`--stem` 等。
- 间距阶 **4 · 6 · 8 · 12 · 16 · 20 · 24**（05§1.1：6 在时间轴内是合法值，用于截图行距/列距、unit 内 gap）。
- 圆角阶：截图 8、成就图标 6、封面 10（panel 内成就头像 46×69）、panel 18、胶囊 999。
- 隐藏一律用 `hidden` 属性，配合全局 `[hidden] { display: none !important; }`。
- 数字 / 时间戳 / 数量一律等宽（`.mono`，JetBrains Mono）。
- **字体本地打包 woff2 子集化** + `font-display: swap`——画板用的 Google Fonts CDN（`fonts.googleapis.com`）只是设计稿产物，**实现禁止联网取字**；Noto Sans SC 必须子集化（全量 > 8MB）。
  > ⚠️ **当前状态：尚未接入**。`fonts/` 是空目录，`styles.css` 里没有 `@font-face`，Space Grotesk / JetBrains Mono / Noto Sans SC 三个字族全部落在系统回退上。字号、字重、`letter-spacing`、`tabular-nums` 都按规范写了，但实际字形不是设计稿那套——**视觉验收时不要拿字形对画板**，等子集化落地再对。这是待办，不是已放弃的项。

## 7. 图标与文案

- 图标一律**内联 SVG**，24 视口、`stroke-width 1.8~2`、`round` 端点、`fill:none`；禁止 emoji、禁止图标字体、禁止引入图片资源。
- 图标词汇表集中在 `lib/icons.js`：首玩 = play 三角、成就 = key、发售 = cal、购买 = cart、前/后 = chevL/chevR、设置 = gear、关闭 = close、导出 = download。所有渲染模块共享同一份，不各自重复定义 SVG path。
  > `gear` 用的是**连续齿廓**路径而不是「圆 + 8 根短齿」：设置入口放大到 44px 浮动圆钮后，短齿画法在 19px 图标里会糊成一团。
- **删除冗余**：每个元素必须能回答「服务哪条 PRD 用户故事」；同一信息一屏不出现两次；禁止空状态插画、解释性文案、「更多」入口（05 总则2）。
- 悬浮 panel 不放截图——轴下方已常驻该时点的截图列（07§4.8「不放什么」）。

## 8. 状态管理与数据流

- 时间焦点：`{ range, scale }`，`scale ∈ { day, week, month }`。
- 同步态：`idle | syncing | error` + 上次同步时间戳。
- 用一个轻量发布订阅 store（无框架依赖的纯对象即可，不引入状态管理库）：
  ```js
  // store.js（如需要可拆出）
  export function createStore(initial) {
    let state = initial;
    const subs = new Set();
    return {
      get: () => state,
      set: (partial) => { state = { ...state, ...partial }; subs.forEach(fn => fn(state)); },
      subscribe: (fn) => (subs.add(fn), () => subs.delete(fn)),
    };
  }
  ```
- 「隐藏从未启动的游戏」开关（02§4.1）：切换后前端本地重算，120ms 淡入，**不重新请求**；持久化到 `localStorage`。
- 主题色不做前端取色，直接消费 `mock-data.js` / 后端返回的 `theme_color` 字段（渲染期只读，05§3.4）。
