# 前端开发规范（游戏日历 Game_C 客户端）

> 用途：指导本仓库后续前端开发。取值与交互的**唯一来源**仍是 `../../GAMEC/05_UI设计规范_游戏日历.md`（v0.3）与 `02_PRD_游戏日历.md`，本文只讲「怎么写代码」，不重复需求与像素。
> 玻璃层的原理与验收基线见 `../../GAMEC/_archive/UI/06_液态玻璃实现文档.md`（已归档），后端接口契约见 `../../GAMEC/开发文档/05_后端接口文档.md`。

---

## 1. 技术栈与边界

- Electron（透明无边框悬浮窗 + 托盘），渲染层为**原生 HTML / CSS / JS**，**无打包器、无框架、无 TypeScript**。
- 日历网格手写 CSS Grid（`repeat(7, minmax(0,1fr))`），不用第三方日历库。
- 渲染层通过 `preload.js` 的 `contextBridge` 访问主进程能力；**不开启** `nodeIntegration`，渲染层无 Node 能力。
- 数据在「无后端」阶段由 `mock-data.js` 提供，经 `api.js` 门面统一暴露——**视图层只允许 import `API`，不得直接 import `MockData`**（接入后端时只改 `api.js`）。

## 2. 目录结构

```
main.js             主进程：窗口 / 托盘 / IPC / 壁纸·几何推送 / 导出落盘
preload.js          contextBridge 最小接口
wallpaper.js        主进程读桌面壁纸（玻璃 L0 数据源）
renderer/
  index.html        全部视图骨架 + 脚本加载顺序
  styles.css        token + 玻璃 L0/L2/L3 + 日历 + 浮层 + 设置/首启 + 动效
  glass.js          玻璃运行期驱动（壁纸映射 / 自适应填充）
  mock-data.js      确定性演示数据（对齐后端 get_day_detail 结构）
  calendar.js       日历网格纯函数
  theme.js          主题色纯函数（规范化 / 对比度 / shade）
  api.js            数据访问门面（预留 REST 接口）
  state.js          状态仓库 + 登录态持久化
  sync.js           同步编排
  router.js         视图路由
  app.js            主日历 + 日详情浮层（CalendarView）
  settings.js       设置页
  first-run.js      首启页
scripts/            make-icon / smoke / stress-wallpapers / glass-acceptance
docs/               本规范
```

脚本加载顺序在 `index.html` 底部，**必须按依赖顺序**：`mock-data → calendar → theme → api → state → sync → router → settings → first-run → glass → app`。新增模块时插到它依赖的模块之后。

## 3. 模块规范（IIFE + window 挂载）

每个 JS 文件是一个自执行函数，暴露到 `window`，不写 `export`/`import`（无打包器，`file://` 下 ES Module 有 CORS 风险）：

```js
(function (global) {
  'use strict';
  // 私有实现……
  global.SomeModule = { publicFn, otherFn };
})(window);
```

约定：

- **全局命名**：`MockData`、`Calendar`、`Theme`、`API`、`Store`、`Sync`、`Router`、`Settings`、`FirstRun`、`CalendarView`。
- 模块内私有函数不暴露；只挂需要的公开面。
- 不在模块顶层做 DOM 查询 / 副作用——副作用收敛到 `mount()` / `init()`（见 §4）。

## 4. 视图与生命周期

视图（`app.js` 的 `CalendarView`、`settings.js`、`first-run.js`）遵循同一接口：

- `mount()`：**只执行一次**——查询 DOM、绑定事件、注册 `Store.subscribe`。用 `bound` 标志防重复。
- `render(state)`：**可重复调用**——按 `Store.get()` 重绘 DOM，不重复绑事件。
- `app.js` 的 `init()` 负责：`mount()` 各视图 → `Store.restoreAuth()` → `Router.show('calendar' | 'first-run')`。

路由：

- 三个互斥主视图 `calendar / settings / first-run`，由 `Router.show(name)` 切换（切到 settings/first-run 前自动收起日详情浮层）。
- 日详情浮层是 `calendar` 的内联层，不进主视图路由，由 `CalendarView.openSheet/closeSheet` 控制。

状态：

- 唯一可变状态在 `Store`。动作 → `Store.set(partial)`；跨视图响应（如底栏同步态、设置页同步按钮）→ `Store.subscribe(fn)`。
- 登录态持久化用 `localStorage`（`Store.persistAuth/restoreAuth/clearAuth`）——**真实实现换 OS keychain / DPAPI，接口不变**。

## 5. 数据访问与「预留接口」

`api.js` 是**唯一取数入口**，方法名对齐 `05_后端接口文档.md`：

| 前端方法 | 后端端点 |
|---|---|
| `authSteam` | `POST /auth/steam` |
| `submitApikey` / `hasApikey` | `POST|GET /auth/apikey` |
| `getMonthEvents(year, month)` | `GET /calendar/{year}/{month}` |
| `getDayDetail(date)` | `GET /calendar/day/{date}` |
| `getSyncStatus` / `syncNow(onProgress)` | `GET /sync/status` · `POST /sync` |
| `getGames` / `submitWishlist` / `submitReview` | `GET /games` · `POST /wishlist` · `POST /games/{appid}/review` |
| `exportJson` | 本地（走主进程 `export-json` IPC） |

接入真实后端的步骤（视图零改动）：

1. `API.baseUrl = 'http://127.0.0.1:8000'`；
2. 登录成功后 `API.token = res.token`（`request()` 自动带 `Authorization: Bearer`）。

约定：

- `getMonthEvents` 返回 `{ year, month, days: { 'YYYY-MM-DD': groups[] } }`（42 格网格窗口）；`getDayDetail` 返回 `{ counts, rows }`，`row = { type, game:{zh,en}, themeColor, count, time }`（`time` 为当日分钟数）。
- 日期统一 `isoDate(d) === 'YYYY-MM-DD'`（本地时区）；`month` 在 `api.js`/后端为 **1 基**，在 `focus`/`Calendar.buildCells` 为 **0 基**——注意边界转换（`app.js` 调 `getMonthEvents(focus.year, focus.month + 1)`）。
- 事件数据在数据层聚合后出，渲染期**不做**全量拉取与取色；主题色渲染期只读（`theme.js` 在同步期执行）。

## 6. 样式与取值

- 所有取值落成 CSS 自定义属性（token），命名同 UI 规范 §3：`--accent`、`--text-1/2/3`、`--ev-release/purchase/achieve-fallback`、`--glass-*`、`--lift-*`、`--guard-*`。
- 玻璃只分 `.glass-l2` / `.glass-l3` 两个类，**不就地拼装、不存在 `.glass-l1`**（L1 是 Windows 桌面，L0 是它在页面内的替身）。
- 层内元素（按钮/胶囊/列表行/今日格）用 `--lift-*` 相对提亮，不用再套 `backdrop-filter`。
- 隐藏一律用 `hidden` 属性，配合全局 `[hidden] { display: none !important; }`（否则会被 `.view` 等的 `display:flex` 顶掉）。
- 元素间距只用 4 的倍数（4·8·12·16·20·24）；容器内边距专用值 14·18·20；圆角阶 12/10/18~20/26/30/999。
- 数字 / 时间戳 / 数量一律等宽（`--font-mono`）；`.mono` 工具类已提供。

## 7. 图标与文案

- 图标一律**内联 SVG**，24 视口、`stroke-width 1.8~2`、`round` 端点、`fill:none`；禁止 emoji、禁止图标字体、禁止引入图片资源。
- 类型图标集中在 `app.js` 的 `ICONS` 表（首玩 play / 购买购物车 / 成就钥匙 / 发售日历）。
- **删除冗余**（总则 2）：每个元素必须能回答「服务哪条 PRD 用户故事」；同一信息一屏不出现两次；禁止空状态插画、解释性文案、「更多」入口。
- 日详情浮层不放关闭按钮——遮罩 / Esc / 再点同一天已能收起；手动补录（P-4）等 V0.5 入口本版不渲染。

## 8. 交互与可访问性

- 桌面悬浮：无边框透明窗、不可缩放、顶部 18px + 月份头为拖拽区（`-webkit-app-region: drag`），按钮/格子/列表行显式 `no-drag`。
- 面板外透明区做**鼠标穿透**（`app.js bindPassthrough` + 主进程 `glass:pointer-inside`）——改窗口尺寸或圆角必须同步 `RADIUS`。
- 键盘：`←/→` 切月、`Esc` 收浮层；浮层为模态（开着时方向键不切月）。
- 日详情浮层带 `role="dialog" aria-modal` 等语义；无事件日期不给 `.has-ev`（不响应点击）。
- 动效只服务切月方向感 / 浮层层级感 / 显隐存在感，`prefers-reduced-motion` 下降为 120ms 淡入。

## 9. 测试与验收

- `npm run smoke`：Node 内以 `window` 垫片加载纯逻辑（`calendar / theme / mock-data`），校验 42 格、周一列首、事件形状、主题色规范化——**纯函数必须在这里加断言**。
- `npm run glass-acceptance`：玻璃量化（透光率 / 对比度 / 降级 / 帧率），改玻璃参数前后各跑一次对照。
- 冒烟截图：`SHOT=<path> npm start` 走查「登录 → 日历 → 设置 → 日详情浮层」，输出 `dom` / `walk` 摘要；渲染层报错转发到主进程 stdout（`[renderer]` 前缀）。
- 提交前：`npm run smoke` 通过 + `SHOT` 走查无 `[renderer]` 报错。
